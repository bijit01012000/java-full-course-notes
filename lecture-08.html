    Part 1 · Java Basics · Lecture 08

    Java Loops & Jump Statements Explained — for, while, do-while, break, continue

    16 sections · interview-oriented · both themes

    Scope evidence: lecture title "Java Loops & Jump Statements | for, while, do-while, break, continue Explained" (playlist map, verified). This lecture's repo folder contains two code files: Demo.java and Demo2.java. The cached lecture PDF is image-only and is ignored per project rules.

    A loop is Java's way of saying "do this again until told to stop", and the language provides exactly three iteration forms plus two jump statements to control them. This lecture covers the anatomy and fixed execution order of for, the condition-first while, the body-first do-while, the jump statements break and continue with their labelled forms, the enhanced for (for-each), and the pitfall catalogue: off-by-one errors, infinite loops, loop-variable scope, and the int overflow condition that never terminates. Conditionals inside loop bodies follow Lecture 7, and the increment and compound-assignment operators driving every update clause come from Lecture 6.

    1. What Is a Loop and Why Java Has Exactly Three Forms

    A loop executes a block of statements repeatedly while a controlling condition holds. Every loop answers three questions: where does the state start, when do we stop, and what changes each round? The three forms differ only in where those answers live:

    1. for — all three answers sit in one header line; best when the iteration count is known.
    2. while — only the condition sits in the header; best when the count is unknown up front.
    3. do-while — the body runs first and the condition is checked last; best when the body must execute at least once.

    All three are interchangeable in power — any loop can be rewritten as any other — but readability, and therefore correctness, belongs to the right form for the job. Interviewers use that choice as a design signal.

    Memory aid — three forms, three homes: for keeps the plan, while keeps the question, do-while keeps the promise (the promise being "the body runs at least once").

    2. The for Loop: Anatomy, Execution Order and Header Variants

    The for header has three semicolon-separated sections, each of which is optional:

    // Demo.java — for anatomy: init; condition; update
public class Demo {
    public static void main(String[] args) {
        int sum = 0;
        for (int i = 1; i <= 5; i++) {   // init; condition; update
            sum += i;                    // 1+2+3+4+5
        }
        System.out.println(sum);         // 15
    }
}

    The execution order is fixed and worth memorizing as a cycle:

    init (once) -> check condition -> body -> update -> check -> body -> update -> ...
                              ^ condition false: loop ends, control passes on
    1. init runs exactly once, before anything else.
    2. condition (must be boolean) is checked before every potential pass.
    3. body runs only if the condition was true.
    4. update runs after each completed pass, then control jumps back to the condition.

    So the order is init — condition — body — update, and the update clause never runs on the first arrival at the loop. Candidates who answer "init then body" forfeit the point.

    The header also has legal variants:

    // Demo2.java — multi-expression header and the empty header
public class Demo2 {
    public static void main(String[] args) {
        int a = 1, b = 5;
        for (a = 0, b = 10; a < b; a++, b--) {   // multiple init and update
            System.out.println(a + " " + b);
        }
        int j = 0;
        for (;;) {               // all sections empty: infinite loop
            if (++j == 3) break; // escape hatch — break is Section 8
        }
        System.out.println("stopped at " + j);
    }
}
    1. Multiple init expressions are comma-separated and must share one type: for (int i = 0, j = 10; ...) compiles; for (int i = 0, long j = 0; ...) does not.
    2. Multiple update expressions are comma-separated with no type restriction: a++, b--.
    3. All three sections may be empty — for (;;) is the idiomatic infinite loop, equivalent to while (true).
    4. The two semicolons are mandatory even when their sections are empty.

    Important One condition expression only — the comma does not join conditions. for (a = 0, b = 10; a < b, b > 0; ...) is a compile error. Combine conditions with && or || (Lecture 6).

    3. Classic Loop Patterns

    Four patterns appear in almost every written interview round:

    // Sum 1..n
int sum = 0;
for (int i = 1; i <= 100; i++) sum += i;          // 5050

// Reverse a number
int n = 1234, rev = 0;
while (n != 0) {
    rev = rev * 10 + n % 10;   // last digit becomes most significant
    n /= 10;                   // drop the last digit
}                              // rev = 4321

// Digit extraction (count digits)
int count = 0, m = 45673;
while (m != 0) { count++; m /= 10; }              // 5

// Multiplication table
int t = 7;
for (int i = 1; i <= 10; i++) {
    System.out.println(t + " x " + i + " = " + (t * i));
}

    The reverse and digit patterns are the same loop wearing two hats: % 10 isolates the last digit and / 10 discards it. Both use while because the iteration count is unknown in advance, and the update lives in the body rather than in a header — the natural while shape.

    Interviewer's perspective "Reverse 1234 without strings." The rev = rev * 10 + n % 10 idiom is the expected answer. A candidate who converts to String and reverses characters solves it, but the numeric idiom shows fluency with / and % (Lecture 5's arithmetic context, Lecture 6's operators).

    4. The while Loop: Condition First, Zero Runs Possible

    int i = 0;               // init outside
while (i < 3) {          // condition checked first
    System.out.println(i);
    i++;                 // update inside the body — forget it and the loop never ends
}

int x = 10;
while (x < 5) {          // false on the very first check
    System.out.println("never printed");
    x++;
}

    while is a pre-test (entry-controlled) loop: the condition is evaluated before each iteration, so a false initial condition means the body runs zero times. Its anatomy is the for cycle minus the header — init before the loop, condition at the top, update inside the body.

    The comment above marks the single most common while bug: a missing update clause produces an infinite loop silently. Note also that i here is declared before the loop, so its scope outlives the loop — unlike the for variable of Section 7.

    5. The do-while Loop: Body First, Runs At Least Once

    int i = 10;
do {
    System.out.println("printed once even though condition is false");
    i++;
} while (i < 5);   // trailing semicolon is mandatory

    do-while is a post-test (exit-controlled) loop: the body executes, then the condition is checked, so the body is guaranteed at least one pass. Two facts exams probe:

    1. The final while (...); ends with a semicolon — forgetting it is a compile error.
    2. Variables declared inside the braces die at the closing brace; the condition can see only variables declared before the do.

    The textbook use case is the menu-driven program: show the menu, read the choice, act on it, and repeat only if the user did not choose exit.

    int choice;
do {
    System.out.println("1. Add  2. Exit");
    choice = readInput();     // body must run before a choice exists
} while (choice != 2);

    The body-first shape is not a style preference — it is the only one of the three forms where the logic genuinely requires one guaranteed pass.

    6. for vs while vs do-while: The Comparison Table

    Aspect for while do-while
    Condition check position Top of loop, inside header Top of loop, before body Bottom of loop, after body
    Body guaranteed to run No — may run 0 times No — may run 0 times Yes — runs at least once
    Test type Pre-test (entry-controlled) Pre-test (entry-controlled) Post-test (exit-controlled)
    Where init/update live Header line Before loop / inside body Before loop / inside body
    Loop variable scope Confined to the loop Outlives the loop Outlives the loop
    Typical use Known/fixed iteration count Unknown count, condition-driven Menus, input validation, retries
    Empty header allowed Yes — for(;;) No — condition required No
    Equivalent to while with tighter scope for(;; condition) while with one forced pass

    The equivalence row matters: any for can be mechanically converted to a while by moving init above and update below the body — but then the loop variable leaks into the enclosing scope. That leak is the practical reason for exists for counted loops.

    7. Loop-Variable Scope

    Variables declared in the for(...) header live only inside the loop — they are conceptually re-created each iteration and are invisible after the closing brace:

    for (int i = 0; i < 3; i++) { /* i visible here */ }
// System.out.println(i);     // compile error: cannot find symbol
int last;                     // declare outside to smuggle a value out
for (int i = 0; i < 3; i++) last = i;    // last == 2 after the loop
    1. Re-declaring int i in a second for loop is legal, because the first i died with its loop.
    2. Declaring the same name twice in one header (int i = 0, i = 1) is a compile error.
    3. A while variable declared before the loop remains usable after — sometimes a feature, often an accident.

    Important Because the header variable is re-created per iteration, capturing it in a lambda or inner class is a compile error ("local variables referenced must be final or effectively final"). Copy it to a fresh final variable inside the body when needed.

    8. Jump Statements: break and continue

    break terminates the loop (or switch) it sits in and hands control to the first statement after that construct:

    for (int i = 1; i <= 10; i++) {
    if (i == 4) break;          // leaves the for loop entirely
    System.out.print(i + " ");  // prints 1 2 3
}

    Three rules govern break:

    1. Inside a switch, break exits only the switch, not any enclosing loop (Lecture 7).
    2. Inside nested loops, break exits only the innermost enclosing loop — the outer loop keeps running.
    3. A break outside any loop or switch is a compile error.

    Breaking out of nested loops needs a label — the classic nested-search example:

    int[] a = {2, 5, 9}, b = {7, 9, 11};
outer:
for (int x : a) {               // labelled loop
    for (int y : b) {
        if (x == y) {
            System.out.println("common: " + x);
            break outer;        // exits BOTH loops
        }
    }
}

    continue abandons the current pass only and jumps to the next one:

    for (int i = 1; i <= 6; i++) {
    if (i % 2 == 0) continue;   // skip even numbers — update still runs
    System.out.print(i + " ");  // prints 1 3 5
}
    1. In a for, control jumps to the update expression first, then re-checks the condition.
    2. In a while/do-while, control jumps straight to the condition — if the update sits below the continue, the loop is now infinite.
    3. A plain continue targets the innermost loop; continue outer; targets the labelled one, just like break outer;.

    9. break vs continue: Side-by-Side

    Aspect break continue
    Effect Terminates the loop entirely Ends only the current iteration
    Control goes to First statement after the loop Next pass: update (for) or condition (while)
    Loop may keep running No Yes — remaining iterations survive
    Works in switch Yes — exits the switch No — compile error in a switch
    Labelled form break label; — exit the labelled loop continue label; — next pass of the labelled loop
    Typical use Early exit once the answer is found Filter — skip values that fail a test

    Important In a for, continue never skips the update clause — the update is part of the jump path. In a while, the update lives in the body, so a continue placed above it is the classic recipe for an accidental infinite loop.

    10. The Enhanced for (for-each) Loop

    int[] nums = {10, 20, 30};
for (int n : nums) {      // "for each int n in nums"
    n = n * 2;            // modifies the copy, NOT the array
    System.out.println(n);
}                         // nums is still {10, 20, 30}

    The enhanced for iterates over arrays and collections without an index:

    1. Syntax: for (Type element : arrayOrCollection) — the colon reads as "in".
    2. No index access — you receive the element, not its position, so you cannot look ahead or write arr[i].
    3. The element variable is a copy: assigning to it rebinds only the copy, so for primitives nothing is written back into the array. (For objects the reference is copied — mutating the object shows, reassigning it does not.)
    4. There is no structural-modification safety net — removing elements from a collection while iterating it throws ConcurrentModificationException. The deep dive, removal idioms and iterator mechanics are Lecture 30.

    Traditional for stays superior whenever the index matters: position, reverse traversal, updating arr[i] in place, stepping by 2. Arrays themselves are Lecture 9's topic.

    11. The Pitfall Catalogue

    Pitfall Example What happens Fix
    Off-by-one (< vs <=) for (i = 0; i <= arr.length; i++) Reads arr[arr.length] — ArrayIndexOutOfBoundsException i < arr.length
    Missing update while (i < 5) { print(i); } Infinite loop Put i++ in the body
    Wrong condition for (int i = 10; i < 5; i++) Body runs 0 times — logic silently skipped Verify the first check
    Changing the loop variable for (i = 0; i < 5; i++) { i = 10; } Update edits it again — skipped iterations or endless loop Never reassign the loop variable
    Overflowing condition for (int i = s; i <= Integer.MAX_VALUE; i++) i++ wraps to MIN_VALUE, condition stays true forever i < MAX_VALUE, or use long
    continue above the while-update while (i < 5) { if (x) continue; i++; } Infinite loop Put the update first
    Loop variable leaking Using header int i after the loop Compile error Declare outside or rename
    break in a switch inside a loop switch (c) { case 1: break; } in a for Breaks only the switch — loop keeps iterating Use a flag or a labelled break

    Interviewer's perspective "Does i <= Integer.MAX_VALUE ever exit?" No — i++ at MAX_VALUE wraps to Integer.MIN_VALUE (two's-complement overflow, Lecture 5's wraparound made cyclic), the condition stays true, and the loop runs forever. The fix i < Integer.MAX_VALUE exits after the last legal pass. It is the favourite infinite-loop question precisely because the condition looks so ordinary.

    12. Myth vs Reality

    Myth Reality
    "do-while runs its body at least twice" Post-test means one guaranteed pass; re-running depends solely on the condition checked after pass one.
    "break exits all nested loops" Plain break exits only the innermost loop or switch; the labelled form is needed for more.
    "continue skips the for-loop's update clause" The update runs on the continue path; only while/do-while jump straight to the condition.
    "for-each can update array elements" The element variable is a copy; assigning to it never writes back through the array (primitives).
    "for(;;) is invalid syntax" All three header sections are optional — the semicolons are not. for(;;) is a legal infinite loop.

    13. Common Trap Questions

    Trap 1 — The do-while semicolon: "Does do { ... } while (i < 5) need a semicolon?" Yes, after the closing parenthesis of the condition. Dropping it is a compile error — and the condition being checked only after the first pass is the second half of the answer.

    Trap 2 — The switch-in-loop break: "A loop contains a switch, and case 3 says break. What happens to the loop?" Nothing — the break exits only the switch; the loop continues with its next iteration. Exiting the loop needs a flag or a labelled break targeting the loop.

    Trap 3 — The unreachable statement: "Does code after break in the same block compile?" No. Statements after an unconditional break (or return) in the same block are unreachable, and unreachable code is a compile-time error in Java. if (cond) break; more; compiles, because the break is conditional.

    Trap 4 — The for-each write-back: "I doubled n inside for (int n : arr) — why did the array not change?" The loop variable is a copy of each element. Doubling it rebinds a local; the array slot is untouched. Write-back needs the index form: for (int i = 0; i < arr.length; i++) arr[i] *= 2;

    Trap 5 — The overflow condition: "for (int i = 0; i <= Integer.MAX_VALUE; i++) — how long does it run?" Forever. i++ at MAX_VALUE wraps to MIN_VALUE, so the condition never becomes false. Correct form: i < Integer.MAX_VALUE.

    Trap 6 — The labelled jump: "Which loop does continue outer; affect — the current one or outer?" The one named. outer: marks a specific loop; a labelled continue jumps to that loop's next pass (for: via update) even from nested code, and a labelled break exits that loop entirely.

    14. Points to Remember

    1. Every loop is init — condition — body — update; for writes the cycle in one header, the others spread it out.
    2. while and for are pre-test loops (0 runs possible); do-while is post-test (minimum 1 run).
    3. for header: multiple same-type inits and comma updates are legal; all sections optional; semicolons mandatory — for(;;) is the idiomatic infinite loop.
    4. The condition must be boolean — while (1) is C, not Java.
    5. do { ... } while (cond); needs the trailing semicolon and evaluates the condition after the first pass.
    6. break exits the innermost loop or switch; continue skips to the next pass — update-then-check in a for, condition only in a while.
    7. Labels (outer:) plus break label; / continue label; act on the named loop — the standard nested-search tool.
    8. Code after an unconditional break/return in the same block is unreachable and will not compile.
    9. A for-header variable lives only inside the loop and is re-created each iteration; hoist the declaration outside to keep a value.
    10. i <= Integer.MAX_VALUE never terminates — i++ wraps to MIN_VALUE. Use <, or long.
    11. for-each has no index and binds a copy of each element; mutating a collection during it throws ConcurrentModificationException (Lecture 30).
    12. Off-by-one (<= on length) and silently missing updates cause most loop bugs — verify the first check and the last update before anything else.

    15. Likely Interview Questions

    Question Crisp Answer
    What are the three loop types in Java? for (counted, pre-test), while (condition-driven, pre-test), do-while (post-test, body runs first).
    for vs while vs do-while — one line each? for holds init/condition/update in one header; while checks first and may run 0 times; do-while runs the body first, at least once.
    Which loop runs at least once, always? do-while — the condition is evaluated after the body.
    Can a for loop have multiple initializations? Yes, comma-separated and same type: for (int i = 0, j = n - 1; i < j; i++, j--).
    Is while(1) valid in Java? No — the condition must be boolean; while (true) is the infinite-loop idiom.
    Difference between break and continue? break leaves the loop entirely; continue skips to the next iteration (for: via update; while: via condition).
    What does break do inside a switch nested in a loop? It exits only the switch; the loop keeps iterating.
    How do you break out of nested loops? Label the outer loop and break outer; — or refactor into a method and return.
    When is a for header variable usable after the loop? Never — its scope ends with the loop; declare it before the loop to survive.
    Why does i <= Integer.MAX_VALUE loop forever? i++ wraps from MAX_VALUE to MIN_VALUE, so the condition stays true; write i < MAX_VALUE instead.
    What is the enhanced for loop and its limits? for (Type e : arr) iterates elements without an index; it cannot update primitives in place and does not protect against structural collection modification (Lecture 30).
    Can for and while replace each other? Always, mechanically — move the init above and the update below the body; only scope and readability decide the choice.

    16. Final Summary

    init --> check condition --> body --> update -->+
        ^                                       |
        +------------- loop back ---------------+
condition false -> exit      break -> exit now      continue -> next pass
    • for → all three loop controls in one header; counted loops; header variable scope ends with the loop.
    • while → pre-test, condition-driven, may skip its body entirely; never forget the update.
    • do-while → post-test with trailing semicolon; one guaranteed pass; menus and input validation.
    • break → innermost exit; labelled for outer loops; switch-only inside a switch.
    • continue → next pass (for: update first, while: condition only); infinite loop if the update sits below it.
    • for-each → clean read-only iteration; copy variable, no index, ConcurrentModificationException on structural modification (Lecture 30).
    • Counted iterations → for; unknown iterations → while; at least one pass → do-while; recursion (Lecture 11) replaces loops when the state itself must nest.

    Golden rule Choose the loop by where the question is asked: before the body (for/while) or after it (do-while) — and never let the update clause drift below a continue.

    One-line takeaway: all three loops are the same cycle — init, check, body, update — and mastery is knowing that for puts the cycle in one line, do-while delays the check by one pass, and break/continue are the two sanctioned ways to leave the cycle early or skip to its next turn.
