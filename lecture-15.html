    Part 2 · Arrays & OOP Core · Lecture 15

    Static & Final in Java — Static Methods, Blocks & String[] args

    15 sections · interview-oriented · both themes

    Scope evidence: lecture title "Static & Final in Java | Static Methods, Blocks & String[] args" (playlist map, verified). Repo evidence: three code files, Demo.java, Demo2.java and Demo3.java (Code/ folder).

    Two modifiers separate code that belongs to a class from code that belongs to an object: static and final. static says "one copy per class, reachable without an object", which is exactly why the JVM can call main before any object exists; final says "assigned once, changed never", which is how Java writes constants. This lecture covers static variables, methods and blocks, the precise initialization order of a class, why main is static, the String[] args command-line array, and every face of final — including the interview-favourite distinction between a final reference and an immutable object. The static members live in the method area, whose memory internals are detailed in Lecture 45; the String[] machinery is built on arrays from Lecture 9 and text handling from Lecture 3.

    1. The One Question Behind static

    Every member in Java answers one question: does it belong to the class or to each object? A static member belongs to the class; an instance member belongs to each object. There is exactly one copy of each static member per class loaded, stored with the class data in the method area (Lecture 45), while instance members are created anew for every object on the heap.

    The keyword is not about immutability and not about access control — it is purely about ownership and sharing. A class is loaded lazily: the first time the program actively uses it (constructing an object, touching a static member, or launching it), the class is loaded and its static state is created once.

    Aspect Static (class) member Instance member
    Belongs to The class itself Each individual object
    Copies in memory Exactly one per class loader One per object
    Created when Class is first loaded (lazy) Object is constructed with new
    Accessed via ClassName.member (preferred) reference.member
    May use this / super No Yes
    Can read instance members directly No Yes
    Typical use Shared counters, constants, utility methods Per-object state and behaviour

    Memory aid — static is shared, instance is personal: a static field is one whiteboard read by the whole class; an instance field is a private notebook each object carries.

    2. Static Variables (Class Variables)

    A static variable is declared with static at class level and is shared by every instance. Reaching it through an object reference compiles, but ClassName.member is the honest, preferred form because it states where the data lives.

    // Demo.java — one shared count, one id per object
class Counter {
    static int count = 0;          // one copy shared by every counter
    int id;                        // one copy per object

    Counter() {
        count++;                   // every creation bumps the shared value
        id = count;
    }

    static void showCount() {      // static method: no object required
        System.out.println("created: " + count);
    }
}

public class Demo {
    public static void main(String[] args) {
        new Counter();
        new Counter();
        Counter.showCount();       // created: 2  (printed without any saved reference)
    }
}

    Two facts fall out of this code. First, count survives across objects because it is not stored in any of them. Second, changing shared state from a constructor is powerful but dangerous: every object silently edits the same variable (Section 10).

    3. Static Methods and the Static Context Rules

    A static method is invoked on the class, not on an object: Math.max(2, 3), Counter.showCount(). Because there is no object, a static method cannot use this or super, and it cannot directly touch instance fields or instance methods — those need an object to exist. This is the "static context" rule, and it is the single most common compile error of the topic.

    class Helper {
    int value = 10;
    static int doubled(int n) { return n * 2; }   // pure input -> output
    void print() { System.out.println(value); }

    static void broken() {
        // System.out.println(value);   // compile error: non-static variable value
        // print();                      // compile error: non-static method print()
    }
}

    The rule cuts both ways helpfully: static members can be called from instance methods (the reverse of the error above), because an object can always see its class. A static method is the right home for a calculation that depends only on its parameters.

    Important this and super are references to an object. No object, no reference — so the compiler rejects them inside any static context (static method, static initializer, static nested class body). Passing an instance parameter into a static method is the legal way to reach object state.

    4. Why main Is static

    main is static so the JVM can invoke it before any object exists. When you run java Demo, the launcher loads the Demo class and calls Demo.main(args) directly on the class — there is no new Demo() anywhere in the launch sequence. If main were an instance method, the JVM would need an object to call it on, and no object exists yet.

    This is the same entry-point signature introduced in Lecture 2: public static void main(String[] args). The four parts are load-bearing — public so the launcher may call it, static so it needs no object, void because the JVM ignores any return value, and the exact String[] parameter for command-line arguments (Section 9).

    5. Static Blocks and Initialization Order

    A static block (static { ... }) is a block of code that runs once, when the class is first loaded. It exists for setup too complex for a single initializer expression — filling a map, reading config, registering handlers. Static field initializers and static blocks run in textual order, together, before main runs in the launched class.

    // Demo2.java — static state builds in textual order, once
public class Demo2 {
    static int a = init("field a");           // 1. static field initializer
    static { a = 10; System.out.println("static block 1"); }   // 2. textual order
    static { System.out.println("static block 2"); }

    static int init(String s) { System.out.println(s); return 1; }

    int b;                                    // instance field
    { b = 5; System.out.println("instance block"); }   // per object
    Demo2() { System.out.println("constructor"); }

    public static void main(String[] args) {
        System.out.println("main begins");
        new Demo2();                          // only now do instance steps run
    }
}

    The output is fixed: field a, static block 1, static block 2, main begins, instance block, constructor. Nothing instance-level runs until an object is created, and the static steps never repeat — not for a second new Demo2(), and not for a second main entry.

    Order What runs How often Belongs to
    1 Static field initializers and static blocks, in textual order Once, at class load, before main Class
    2 Instance field initializers and instance blocks, in textual order Once per new object Object
    3 Constructor body Once per new object Object

    Interviewer's perspective "At what point does a static block run relative to the constructor?" A static block runs when the class is loaded — potentially long before any constructor, and exactly once. A constructor runs for every object. Mixing the two up is the fastest way to lose the initialization-order question.

    6. Static Nested Classes (Preview) and Static Imports

    A static nested class is a class declared inside another class with the static modifier. Unlike an inner class, it has no hidden reference to an enclosing instance, so it can be instantiated on its own: Outer.Nested n = new Outer.Nested();. The full taxonomy — static nested, inner, local and anonymous — is Lecture 19.

    A static import lets you use a class's static members without the class qualifier. Writing import static java.lang.Math.*; lets code say max(2, 3) and PI instead of Math.max(...) and Math.PI. It is a readability tool only; it changes no ownership or behaviour, and overusing it makes the origin of a name unclear.

    7. The final Keyword

    final is the "assign once, then frozen" modifier. It applies to four things, and the meaning shifts slightly each time:

    1. Final variable — a local, field or parameter that may be assigned exactly once. A local or parameter is written once and read thereafter; a final field is set in the declaration, in an initializer block, or as a blank final in every constructor.
    2. Blank final field — declared without a value (final int id;) and assigned by the time each constructor finishes. The compiler's definite-assignment analysis enforces that no path to the end of a constructor leaves it unset.
    3. Final reference — the reference itself cannot be reassigned, but the object it points to may still mutate. This distinction is the heart of the topic.
    4. Final method — cannot be overridden by a subclass (Lecture 17). Final class — cannot be extended; String is the canonical example (Lecture 17 and Lecture 25).
    // Demo3.java — final references and compile-time constants
public class Demo3 {
    static final double PI = 3.14159;      // static final constant, UPPER_SNAKE_CASE
    static final int[] DIGITS = {1, 2, 3}; // final reference, mutable array contents

    public static void main(String[] args) {
        final int[] data = {1, 2, 3};
        data[0] = 99;                      // legal: the object contents change
        // data = new int[5];              // compile error: cannot assign a final variable

        DIGITS[0] = 42;                    // legal too — final fixed only the reference
        System.out.println(data[0] + " " + DIGITS[0] + " " + PI);
    }
}

    The lesson in three lines: final freezes the binding, not the contents. To make the contents safe you need an immutable type (Lecture 21), not merely final.

    8. static vs final, and the Constant Idiom

    The two keywords are orthogonal: static answers "whose is it?", final answers "can it change?". A field can be static, final, both, or neither.

    Aspect final variable (instance / local / parameter) static final constant
    Keyword combination final only static final
    Copies One per object (instance final) or per call (local final) One per class
    Assignment Exactly once, before use; blank final set in the constructor Exactly once, at declaration or in a static block
    Value can differ per object Yes (e.g., a final id set per object) No — one shared value for the whole class
    Naming convention camelCase, or constructor-set fields UPPER_SNAKE_CASE, e.g. MAX_SIZE
    Compile-time inlining No Yes, when it is a primitive or String compile-time constant
    Example final int id; static final double PI = 3.14159;
    Aspect static final
    Meaning Belongs to the class; one copy Assigned once; cannot be overridden or extended
    Applies to Variables, methods, blocks, nested classes Variables, methods, classes, parameters
    Effect on state Shares state across all objects Freezes one binding
    Memory notion Yes — class-level storage in the method area (Lecture 45) No — it is a modifier, not a location
    Together static final = one shared, fixed value: a true constant —
    Cross-reference This lecture and Lecture 45 final method/class in Lecture 17; immutable classes in Lecture 21

    Important A static final primitive or String whose value is known at compile time is a compile-time constant: the compiler copies the value into every use site (inline). That is why changing such a constant in a library can require recompiling its callers.

    9. String[] args — Command-Line Arguments

    The String[] args parameter of main carries the command-line arguments: every word typed after the class name becomes one element, in order.

    // Demo3.java — reading arguments safely
public static void main(String[] args) {
    System.out.println("args.length = " + args.length);   // 0 when none given
    if (args.length > 0) {
        int n = Integer.parseInt(args[0]);                // java Demo3 42 -> 42
        System.out.println(n * 2);
    }
}

    Three facts to hold:

    1. java Demo one two gives args[0] = "one" and args[1] = "two". There is no program-name element as in C — args[0] is the first real argument.
    2. When no arguments are supplied, args is an empty array (length == 0), not null. Reading args[0] anyway throws ArrayIndexOutOfBoundsException.
    3. Arguments arrive as text; convert numbers with Integer.parseInt (or Double.parseDouble), which can throw NumberFormatException on bad input. Array mechanics are Lecture 9; text handling is Lecture 3.

    10. The Pitfall Catalogue

    Pitfall Example What happens Fix
    Instance member from static context static void m() { print(); } where print is instance Compile error: non-static method cannot be referenced from a static context Make it static, or call it on an object
    Assuming static state is per object A static counter bumped in every constructor All objects share one value — surprising totals Use an instance field for per-object state
    Modifying a final reference's contents final List l = ...; l.add(x); Legal — the reference is fixed, not the object Use an immutable type for genuine constants
    Forgetting a static block runs once A static block expected to "reset" per object It ran once at class load, long before the objects Put per-object logic in the constructor
    Assuming public static final is deeply immutable static final int[] A = {1}; A[0] = 9; Contents change; only the reference is frozen Return copies, or use an unmodifiable type
    Shadowing a static variable A local int count inside a method Hides the class variable; class state untouched Rename the local or qualify ClassName.count
    Assuming args is non-empty args[0] with no arguments ArrayIndexOutOfBoundsException — empty, not null Guard with if (args.length > 0)

    Interviewer's perspective "Can static methods be overloaded?" Yes — overloading is resolved at compile time by parameter list, and static methods participate fully. What static methods cannot do is be overridden; a subclass may declare an identical static method, but that is method hiding, not polymorphism (Lecture 17).

    11. Myth vs Reality

    Myth Reality
    "static means the value can never change" static means one copy per class and can still change; final, not static, freezes a value.
    "A static method can use this" No — this and super need an object, so the compiler rejects them in a static context.
    "final makes an object immutable" final fixes the reference only; the referenced object can still mutate.
    "Static blocks run once per object" They run once per class load, before any object exists.
    "args is null when no arguments are passed" args is an empty array (length == 0), never null.

    12. Common Trap Questions

    Trap 1 — "Can a static method access an instance variable?" Not directly. With no object there is no instance to read; either make the member static or pass an object into the method. Inside main, an instance field is unreachable without a constructed object.

    Trap 2 — "Does a final reference freeze the object?" No. final int[] a = {1, 2}; a[0] = 9; compiles and runs — a still points at the same array, whose contents changed. Only a = ... is forbidden. Immutability needs an immutable type (Lecture 21).

    Trap 3 — "Are static field initializers and static blocks order-independent?" No. They execute top to bottom in textual order, once, at class load. Moving a static block above an initializer it depends on changes the result.

    Trap 4 — "Is args null when you run java Demo with no arguments?" No. args is an empty array; args.length is 0. args == null happens only if someone explicitly passes null, which the launcher never does.

    Trap 5 — "What exactly is the difference between static and static final?" static gives one copy per class that can change; static final adds "assign once", producing a constant. A compile-time constant primitive or String is also inlined at every use site.

    Trap 6 — "Can a blank final field be assigned after the constructor finishes?" No. A blank final must be definitely assigned by the end of every constructor (or in an initializer/static block). Assigning it later, or on only some paths, is a compile error.

    13. Points to Remember

    1. static members belong to the class, not to any instance — exactly one copy per class loaded, held in the method area (Lecture 45).
    2. Access static members as ClassName.member; reaching them through an object reference compiles but is discouraged.
    3. A class loads lazily on first active use; its static initializers run once at that moment, before main in the launched class.
    4. Static methods have no this/super and cannot directly use instance members; pass an object or make the member static.
    5. main is static because the JVM calls ClassName.main before any object exists (Lecture 2).
    6. Static field initializers and static blocks run once, in textual order; instance initializers and the constructor then run per object.
    7. final means assign-once (variable), no-override (method) or no-extend (class) — a modifier, not a memory concept.
    8. A final reference is fixed, but the referenced object may still mutate; final is not the same as immutable.
    9. static final with a primitive or String compile-time constant is inlined at every use site; name constants in UPPER_SNAKE_CASE.
    10. String[] args is the command-line argument array — empty (never null) when none are given; parse numbers with Integer.parseInt (Lecture 3 and Lecture 9).

    14. Likely Interview Questions

    Question Crisp Answer
    What does static mean in Java? The member belongs to the class, not to instances: one copy per class, reachable without an object.
    Where do static variables live? With the class data in the method area, one copy per loaded class (memory internals in Lecture 45).
    Why is main static? The JVM calls ClassName.main before any object is created, so the method cannot require an instance (Lecture 2).
    Can a static method use instance variables directly? No. No object means no instance state; make the member static or pass an object into the method.
    What is a static block and when does it run? A static { ... } initializer that runs once at class load, in textual order with static field initializers.
    What is the initialization order of a class? Static initializers and static blocks (once, at class load) → instance initializers and blocks → constructor (per object).
    Difference between static and final? static: one copy belonging to the class. final: assign-once / no-override / no-extend. They are independent.
    What does static final signify? A class-level constant: one shared value, assigned once. Compile-time primitive/String constants are inlined.
    Does final make an object immutable? No — it fixes the reference; the object it points to can still mutate. Immutability is a property of the type.
    When must a blank final field be assigned? By the end of every constructor, or in an initializer/static block — definite assignment is enforced by the compiler.
    What do final methods and classes forbid? final methods cannot be overridden; final classes cannot be extended, e.g. String (Lecture 17 and Lecture 25).
    What is String[] args? The array of command-line arguments; empty (length 0), never null, when none are supplied.
    What is a static import? import static java.lang.Math.*; lets you use static members without the class qualifier; readability only.

    15. Final Summary

    class load (lazy, once) --> static field initializers + static blocks (textual order)
        --> JVM calls main(String[] args) --> new object
        --> instance initializers/blocks --> constructor
static member: one per class     final: assign once / no override / no extend
static final: one per class and never reassigned = constant
    • static → belongs to the class, one copy per class, no this, shares state; stored in the method area (Lecture 45).
    • Static methods → called as ClassName.method(), pure of instance state unless an object is passed in.
    • main → static so the JVM can launch it before any object exists (Lecture 2).
    • Static blocks → run once at class load, in textual order with static field initializers.
    • Initialization order → static (once) → instance initializers/blocks → constructor (per object).
    • final → assign-once variable, blank final set in the constructor, non-overridable method, non-extendable class.
    • Final reference ≠ immutable object → the binding is frozen, the contents may still change.
    • static final → the constant idiom; UPPER_SNAKE_CASE; compile-time constants are inlined.
    • String[] args → command-line arguments, empty not null, parsed with Integer.parseInt (Lecture 3, Lecture 9).

    Golden rule Ask ownership first (static: the class, one copy) and mutability second (final: assigned once) — the two are independent, and static final is simply "one copy, fixed forever".

    One-line takeaway: static gives one shared copy per class and lets the JVM reach main and args before any object exists, while final locks a single binding — and only static final together yields a true constant, because final freezes the reference, never the object behind it.
