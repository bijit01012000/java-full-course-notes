    Part 4 · Strings, Generics & Collections · Lecture 26

    Java Strings Part 2 | All String Methods + StringBuilder vs StringBuffer

    18 sections · interview-oriented · both themes

    Scope evidence: "Java Strings Part 2 | All String Methods + StringBuilder vs StringBuffer" (playlist map, verified). Repo evidence: 3 Demo files.

    Lecture 25 established the two facts that govern everything here: a String is immutable, and string literals live in the string pool. This lecture turns those facts into working knowledge. It catalogues the methods every Java developer is expected to know, shows why each method that looks like it "modifies" a string actually returns a brand-new one, exposes the regex traps hidden inside split and replaceAll, and then introduces the two mutable companions, StringBuilder and StringBuffer. The lecture closes with the capacity-growth rule, the cost of + inside a loop, and where the compiler secretly sends concatenation.

    1. Immutability Recap: Every "Modifier" Returns a New String

    A String object can never change after construction. A method such as toUpperCase(), trim(), substring() or replace() does not edit the receiver; it computes a new String and returns it. If the return value is discarded, the original is untouched.

    // Demo.java — the receiver is never modified
String s = "  java  ";
s.trim();                       // result thrown away — s is still "  java  "
s = s.trim();                   // correct: capture the returned String
System.out.println(s);          // java

    This single rule explains most beginner surprises: methods are pure with respect to the receiver, and chaining works because each call hands back a fresh immutable value. Lecture 25's StringBuilder aside — for mutation you need a different class, introduced in Section 9.

    3. Length, charAt and the Index Contract

    length() counts UTF-16 code units, not Unicode code points and not bytes. A character outside the Basic Multilingual Plane (for example a surrogate-pair character) occupies two char values, so its length() is 2, not 1. charAt(i) is valid only for 0 <= i < length(); any other index throws StringIndexOutOfBoundsException.

    // Demo.java — index arithmetic is half-open for substring
String s = "Java Full Course";
System.out.println(s.length());            // 16
System.out.println(s.charAt(0));           // J
System.out.println(s.substring(0, 4));     // Java  (0..3, end exclusive)
System.out.println(s.substring(5));        // Full Course (from 5 to end)

    The half-open interval [begin, end) is the single most important indexing convention in Java: substring(0, 4) returns four characters, and end may equal length() but never exceed it.

    4. Searching and Comparing

    Search methods answer "where", comparison methods answer "same or order". Note that compareTo returns an int sign, not a boolean — this is the Comparable contract of Lecture 36.

    // Demo.java — search returns positions; compareTo returns a sign
String s = "Java Full Course";
System.out.println(s.indexOf("Full"));                  // 5
System.out.println(s.contains("Course"));               // true
System.out.println(s.startsWith("Java"));               // true
System.out.println(s.endsWith("Course"));               // true
System.out.println(s.compareTo("Java Full Course"));    // 0  (equal)
System.out.println("apple".compareTo("banana"));        // negative
System.out.println(s.equalsIgnoreCase("JAVA FULL COURSE")); // true

    The contract of compareTo: negative if the receiver sorts before the argument, zero if they are equal, positive if it sorts after. Comparing against the case-insensitive variant preserves that same three-way sign.

    5. Slicing, Splitting and Joining

    split takes a regular expression, not a plain string, and an optional limit that caps the number of pieces. String.join is the reverse operation, and it is the idiomatic way to rebuild a string from parts.

    // Demo.java — split with a limit, then join back
String csv = "red,green,blue";
String[] parts = csv.split(",", 2);        // ["red", "green,blue"]
System.out.println(parts.length);          // 2
System.out.println(String.join(" | ", parts));
System.out.println(String.join("-", "a", "b", "c")); // a-b-c

    Two details matter. First, a positive limit stops splitting after that many pieces; a negative limit keeps trailing empty strings; the default (zero) drops trailing empties. Second, the split argument is a regex, which is exactly why split(".") behaves nothing like split("\\.") — the next sections explain.

    6. Case Folding and Whitespace: trim vs strip

    Java 11 introduced strip, stripLeading, stripTrailing, isBlank, repeat and lines. The most common confusion is trim versus strip.

    Aspect trim() strip()
    Introduced Java 1.0 Java 11
    Definition of whitespace Any code unit at or below U+0020 (ASCII control + space) Character.isWhitespace, Unicode-aware
    Removes U+00A0, U+2003, U+3000 No Yes
    Typical use Legacy compatibility New code, international text

    toLowerCase() and toUpperCase() are also locale-sensitive. The famous case is the Turkish dotless i: in a Turkish locale "I".toLowerCase() yields a dotless i, not a plain "i". Any code that folds case for comparison, identifiers or protocols should pass an explicit locale, normally Locale.ROOT.

    // Demo2.java — locale matters
System.out.println("TITLE".toLowerCase());                 // locale-dependent
System.out.println("TITLE".toLowerCase(java.util.Locale.ROOT)); // dependable

    7. replace vs replaceAll vs replaceFirst

    This is the highest-yield trap in the whole topic. replace treats its target as a literal; replaceAll and replaceFirst treat it as a regular expression.

    Method First argument is Replaces Example Result
    replace Literal char/CharSequence Every occurrence "1.2.3".replace(".", "-") 1-2-3
    replaceAll Regex Every match "a.b.c".replaceAll(".", "-") ------
    replaceAll Regex (escaped) Every match "a.b.c".replaceAll("\\.", "-") a-b-c
    replaceFirst Regex First match only "a.b.c".replaceFirst("\\.", "-") a-b.c

    In regex, . matches any character, so replaceAll(".", "-") replaces every character with a dash and wipes the string; split(".") likewise sees every position as a separator and returns an empty array. To use these characters literally, escape them in the pattern: \\. for a dot, \\s for whitespace, \\| for a vertical bar.

    // Demo2.java — the same dot means two different things
System.out.println("1.2.3".replace(".", "-"));       // 1-2-3  (literal)
System.out.println("a.b.c".replaceAll(".", "-"));    // ------  (regex wildcard)
System.out.println("a.b.c".replaceAll("\\.", "-"));  // a-b-c  (escaped)
System.out.println("a.b.c".split("\\.").length);     // 3

    Important Use replace when you mean a literal substring: it is faster and it cannot be broken by regex metacharacters. Reserve replaceAll/replaceFirst for patterns you actually intend.

    8. equals vs == and the Sign of compareTo

    Lecture 25 warned about this and it is worth restating. == compares references; equals compares content. Two literals may share one pooled object, so == often appears to work until an object built at runtime disagrees.

    // Demo2.java — reference vs content equality
String a = "java";
String b = "java";
String c = new String("java");
System.out.println(a == b);        // true  (same pooled literal)
System.out.println(a == c);        // false (different objects)
System.out.println(a.equals(c));   // true  (same content)
System.out.println(a.compareTo(c));// 0     (equal ordering)

    Golden rule For strings: == asks "same object?", equals asks "same text?", and compareTo asks "which comes first?". Never use == for text equality.

    9. String vs StringBuilder vs StringBuffer

    StringBuilder and StringBuffer are the mutable counterparts of String. They expose the same API, and the only meaningful difference between them is synchronization.

    Aspect String StringBuilder StringBuffer
    Mutable No Yes Yes
    Thread-safe Yes (immutable) No Yes (synchronized)
    Performance Slow to build character by character Fastest Slower than StringBuilder
    Introduced 1.0 5.0 1.0
    Use when Value is fixed; keys, literals, constants Building in one thread Sharing a builder across threads
    Content comparison equals None — call toString().equals None — call toString().equals

    Neither builder overrides equals, so two builders with identical text are not equals; convert with toString() first. In practice StringBuilder is the default choice, and StringBuffer appears mainly in older code.

    10. StringBuilder and StringBuffer Internals

    Both classes wrap a resizable char[] (a byte[] of a fixed coder since Java 9, with a compact-string layout). They start at a default capacity of 16 and grow on demand. The growth formula for StringBuilder is:

    newCapacity = oldCapacity * 2 + 2

    Because every growth step copies the existing characters into a new array, pre-sizing with new StringBuilder(expectedLength) avoids repeated copies for large builds.

    Operation Effect Returns
    append(x) Adds at the end this — chainable
    insert(i, x) Inserts at index i this — chainable
    delete(s, e) Removes [s, e) this — chainable
    deleteCharAt(i) Removes one char this — chainable
    reverse() Reverses in place this — chainable
    setLength(n) Truncates or pads with NUL void
    setCharAt(i, c) Overwrites one char void
    toString() Snapshot as an immutable String String 
    // Demo3.java — build "a".."z", chain, reverse, reuse
StringBuilder sb = new StringBuilder();
for (char c = 'a'; c <= 'z'; c++) {
    sb.append(c);
}
System.out.println(sb);                    // abcdefghijklmnopqrstuvwxyz
sb.reverse();
System.out.println(sb);                    // zyxwvutsrqponmlkjihgfedcba
sb.setLength(0);                           // clear, keep the buffer for reuse
for (int i = 1; i <= 5; i++) {
    sb.append(i).append(' ');              // chainable append
}
System.out.println(sb.toString().strip()); // 1 2 3 4 5

    Memory aid StringBuilder = Single-thread, Swift. StringBuffer = Buffered, Blocking (synchronized). Same API, different guarantee.

    11. Why + in a Loop Is Quadratic

    Inside a single expression, + is convenient. Inside a loop, it is a performance trap. Every s = s + i allocates a fresh builder, appends, produces a new String, and discards the old one — so the characters are copied again and again. Total work becomes O(n^2) instead of O(n).

    // Demo3.java — linear build vs quadratic build
int n = 20_000;

StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) {
    sb.append(i);                 // reuses one buffer: O(n)
}
System.out.println(sb.length());

String s = "";
for (int i = 0; i < n; i++) {
    s = s + i;                    // new String every iteration: O(n^2)
}
System.out.println(s.length());   // same result, dramatically slower

    The rule of thumb: use StringBuilder whenever concatenation happens across loop iterations; use + freely for a handful of terms in one statement.

    12. Where + in Source Actually Goes

    The compiler does not leave + as a runtime instruction. Its translation changed across versions:

    Java version Translation of a + b + c
    Java 8 and earlier new StringBuilder().append(a).append(b).append(c).toString()
    Java 9 and later invokedynamic with a bootstrap for StringConcatFactory.makeConcatWithConstants

    The Java 9 change gives the JVM a single concatenation recipe it can optimise at link time. Crucially, the optimisation applies to one expression, not to a loop: s = s + i still creates a new string each pass because the source contains separate concatenations. That is why the explicit StringBuilder of Section 11 remains the idiomatic fix.

    Interviewer's perspective A strong answer distinguishes the two levels: the compiler rewrites a single + expression (StringBuilder pre-9, invokedynamic from 9), but it cannot hoist a StringBuilder out of a loop body written with +=. Recognising that difference is the point of the question.

    13. Pitfalls and Common Errors

    Pitfall What goes wrong Correct approach
    replaceAll(".", "-") Regex wildcard wipes every character Escape: replaceAll("\\.", "-"), or use replace(".", "-")
    split(".") Regex wildcard returns an empty array split("\\.")
    trim() on Unicode spaces U+00A0/U+2003 survive Use strip() (Java 11)
    Locale-free case folding Turkish locale turns "I" into a dotless i toLowerCase(Locale.ROOT)
    + inside a loop O(n^2) copying Use a reused StringBuilder
    Sharing a StringBuilder across threads Silent data races (no synchronization) Use StringBuffer or confine to one thread
    Index arithmetic on substring Off-by-one or out-of-range Remember [begin, end) and 0 <= i < length()
    String.format in hot loops Format-string parsing on every call Cache or use plain concatenation
    == for string equality Reference comparison equals / equalsIgnoreCase
    Comparing two builders with equals Always false (identity) sb1.toString().equals(sb2.toString())

    14. Myth vs Reality

    Myth Reality
    "String methods change the original string." Strings are immutable; each method returns a new String, leaving the receiver intact.
    "replaceAll replaces a literal substring." replaceAll takes a regex; replace is the literal version.
    "trim removes all whitespace." trim removes only code units at or below U+0020; strip is Unicode-aware.
    "+ in a loop is optimised into one builder." The compiler optimises a single expression, not per-iteration +=; loops still allocate each pass.
    "StringBuilder and StringBuffer differ in features." The API is identical; the difference is synchronization — StringBuffer is thread-safe and slower.

    15. Common Trap Questions

    Trap 1 — The wildcard: "What does "a.b.c".replaceAll(".", "-") print?" "------". In a regex, . matches any character, so every character is replaced. Use replace(".", "-") or replaceAll("\\.", "-") for literal dots.

    Trap 2 — Splitting on a dot: "What does "a.b.c".split(".").length return?" 0. The pattern "." matches every character, so the result is not the three expected pieces and trailing empties are dropped. The correct pattern is split("\\.").

    Trap 3 — Reference equality: "Do "java" == "java" and new String("java") == "java" both give true?" No. The first compares two references to the same pooled literal (true); the second compares a new heap object with a pool reference (false). Use equals for content.

    Trap 4 — The sign of compareTo: "Can I assign the result of compareTo to a boolean?" No. compareTo returns an int whose sign encodes order; zero means equal, negative means before, positive means after.

    Trap 5 — Builders and threads: "Is StringBuilder safe to share between two threads?" No. StringBuilder is not synchronized; concurrent appends can corrupt state. Use StringBuffer for shared mutable text, or keep the builder thread-confined.

    Trap 6 — Unicode whitespace: "Does " \\u2003x ".trim() remove the em-space?" No. trim strips only code units at or below U+0020, and U+2003 is above that. strip() removes it because it is Unicode-aware.

    16. Points to Remember

    1. Strings are immutable; every "modifying" method returns a new String and never edits the receiver.
    2. Learn methods by family: Basics, Search, Compare, Transform, Extract, Compose.
    3. substring(begin, end) uses the half-open interval [begin, end); length() counts UTF-16 code units.
    4. compareTo returns an int sign (negative, zero, positive), never a boolean.
    5. replace takes a literal; replaceAll/replaceFirst take a regex — and . in a regex matches any character.
    6. Escape regex metacharacters: split("\\."), replaceAll("\\."), split("\\\\|") for a bar.
    7. trim handles only ASCII space and control codes; strip (Java 11) is Unicode-aware.
    8. Case folding is locale-sensitive; pass Locale.ROOT for deterministic behaviour.
    9. StringBuilder is mutable and fast but not thread-safe; StringBuffer is the synchronized, slower sibling with the same API.
    10. StringBuilder grows by newCapacity = oldCapacity * 2 + 2; + across loop iterations is O(n^2), so reuse one builder.

    17. Likely Interview Questions

    Question Crisp Answer
    Why do String methods return new strings? Because String is immutable; a method computes a new value and returns it, leaving the receiver unchanged.
    Difference between == and equals for strings? == compares references; equals compares content. Use equals/equalsIgnoreCase for text.
    What does compareTo return? An int sign: negative, zero or positive, encoding lexicographic order.
    replace vs replaceAll? replace replaces a literal target; replaceAll treats the target as a regex and replaces every match.
    Why does split(".") fail? "." is a regex wildcard matching every character; escape it as split("\\.").
    trim vs strip? trim removes code units at or below U+0020; strip (Java 11) removes Unicode whitespace.
    Why is toLowerCase() locale-sensitive? Some locales map letters differently (Turkish dotless i); pass Locale.ROOT for predictability.
    StringBuilder vs StringBuffer? Same API; StringBuilder is unsynchronized and fast, StringBuffer is synchronized and thread-safe.
    How does StringBuilder grow? It doubles plus two: newCapacity = oldCapacity * 2 + 2, starting from a default capacity of 16.
    Why is + in a loop slow? Each iteration allocates a new string and copies the accumulated text, giving O(n^2) total work.
    Where does + go in compiled code? Java 8: StringBuilder; Java 9+: invokedynamic via makeConcatWithConstants.
    When should you prefer StringBuilder? When concatenating across many iterations or building large text in a single thread.

    18. Final Summary

    String (immutable)  --method-->  new String   (receiver untouched)
   families: Basics · Search · Compare · Transform · Extract · Compose

replace(literal)          != replaceAll(regex)   ("." matches any char)
trim(<= U+0020)           != strip(Unicode)      (Java 11)
"a.b.c".split("\\.")       ->  3 pieces
"a.b.c".split(".")         ->  0 pieces

StringBuilder : mutable, fast, single-thread   (+ loop = O(n^2) without it)
StringBuffer  : same API, synchronized, slower
grow: newCapacity = oldCapacity * 2 + 2

'+' expression --javac--> StringBuilder (Java 8) | invokedynamic (Java 9+)
    • Immutability → every method returns a new String; capture the result or it is lost.
    • Catalogue → Basics, Search, Compare, Transform, Extract, Compose; indexing is [begin, end).
    • Regex traps → replace and split on a dot; escape metacharacters; trim is ASCII-only while strip is Unicode.
    • Builders → StringBuilder (fast, not thread-safe) and StringBuffer (synchronized, slower); neither overrides equals.
    • Loop cost → + across iterations is O(n^2); reuse one StringBuilder; the compiler's + optimisation covers a single expression only.

    Golden rule Strings are immutable values, so use String for fixed text and a single reused StringBuilder for anything built in a loop — and never confuse a literal with a regex.

    One-line takeaway: a String never changes, so learn its method families and their regex and Unicode traps, and reach for a reused StringBuilder (or the synchronized StringBuffer) whenever text is built piece by piece.
