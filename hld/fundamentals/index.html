Introduction

2 topics
01 What is System Design?System design is the process of deciding which components a system needs, what each one owns, how they communicate, and how data flows between them — so the system meets its functional and non-functional requirements at a level above writing code. → 02 Top 30 System Design ConceptsThirty building blocks, grouped from the network upward: how machines connect, how applications exchange data, where data lives, how systems scale, what breaks across multiple machines, and how to organize the whole thing. →

Core Concepts

5 topics
03 ScalabilityScalability is the ability to handle more users, traffic, and data without collapsing — but only after you identify the resource that is actually the bottleneck. → 04 AvailabilityAvailability is how often users can actually reach and use the system — engineered by removing single points of failure, adding redundancy that survives correlated failures, and containing the blast radius when a dependency breaks. → 05 CAP TheoremWhen a network partition splits replicas, CAP says you cannot keep both a single up-to-date view and a successful response for every affected request — and the choice belongs to each operation, not to the whole database. → 06 Consistent HashingConsistent hashing maps keys and servers onto the same ring so that adding or removing one server moves only a small slice of the keys instead of reshuffling the whole cluster. → 07 Latency vs ThroughputLatency is how long one request takes, throughput is how much work finishes per second, and bandwidth is the ceiling a connection could reach — improving one does not automatically improve the others. →

Networking

6 topics
08 Load BalancersA load balancer gives many backend servers one stable endpoint, spreading traffic across healthy instances and removing failed ones from rotation without the client noticing. → 09 Proxy vs Reverse ProxyA forward proxy speaks for the client, a reverse proxy speaks for the servers — the difference is whose side of the connection it represents. → 10 Domain Name System (DNS)DNS is the internet's hierarchical, heavily cached naming system: it turns a domain name into the records a client needs, and its TTLs decide how quickly a change can reach everyone. → 11 HTTP/HTTPSHTTP is a stateless request-response protocol carried over TCP or QUIC; HTTPS is the same protocol wrapped in TLS, which adds encryption, integrity, and proof of the server's identity. → 12 TCP vs UDPTCP and UDP both carry data between ports on top of IP, but TCP buys reliable, ordered delivery with handshakes and retransmissions, while UDP stays fast and simple and leaves those guarantees to the application. → 13 ChecksumsA checksum is a small value computed from data so a later reader can detect that the bytes changed; it detects corruption, but recovery still comes from a retry, a replica, or a backup. →

API Fundamentals

4 topics
14 What is an API?An API is the contract that lets one piece of software call another: it fixes the operations, the data to send, and the response to expect, while hiding everything behind the boundary. → 15 API Architectural StylesAn API style is the pattern a communication follows — resource-based, query-based, action-based, streaming, or event-driven — and real systems pick a different one for each communication path. → 16 WebSocketsA WebSocket is one persistent, full-duplex TCP connection upgraded from HTTP, so either side can send a message the moment it has one instead of the client repeatedly asking. → 17 WebhooksA webhook is an HTTP callback: the provider POSTs an event to a URL you registered, so you stop polling and start reacting — but reliable delivery is entirely your problem. →

Databases & Storage

3 topics
18 Database TypesNo single database is best at transactions, single-key lookups, text ranking, and time-window aggregates — pick the engine whose storage layout and index structure match how the data is actually queried. → 19 Object StorageObject storage is a flat, HTTP-addressable store for whole blobs — images, video, backups, model datasets — built to scale capacity and durability far beyond a single filesystem, at the cost of POSIX semantics and cheap queries. → 20 Query OptimizationQuery optimization is the work of making a query read only the rows it needs — usually a far better return than a bigger server, a read replica, or a cache layered over a query that scans 50 million rows to return 20. →

Database Scaling Techniques

3 topics
21 IndexingAn index is a small, sorted structure that turns a full table scan into a few page reads — but each one adds write cost, storage, and memory pressure, so the goal is the smallest set of indexes that supports the real query patterns. → 22 ShardingSharding splits one large dataset across multiple independent database instances, so each shard stores and serves only a slice — trading cross-shard simplicity for horizontal write and storage scale. → 23 DenormalizationDenormalization intentionally stores duplicate or precomputed data so reads avoid expensive joins — trading write complexity and consistency risk for faster, simpler read paths. →

Caching

4 topics
24 What is Caching?A cache keeps a copy of frequently used data in a faster layer so repeat requests avoid the database — cutting latency, reducing load, and raising throughput at the cost of staleness and invalidation work. → 25 Caching StrategiesCaching strategies answer one question: who moves data between cache and database, and when — with cache-aside as the default read pattern and write-through, write-behind, or write-around chosen to fit the write path. → 26 Cache Eviction PoliciesAn eviction policy decides which valid entry leaves when the cache is full — LRU by default, LFU for stable hot keys, FIFO or random for low overhead, with TTL handling freshness and admission control protecting against pollution. → 27 Content Delivery Network (CDN)A CDN is a globally distributed cache that serves content from an edge location near the user, so latency and origin load drop — as long as the content is shareable, cacheable, and safely invalidated. →

Asynchronous Communications

2 topics
28 Pub/SubPub/sub lets a publisher announce that something happened once, while any number of independent subscribers receive their own copy — decoupling the producer from everyone who cares. → 29 Message QueuesA message queue is a durable buffer between producers and consumers that turns slow, bursty, failure-prone work into independent background tasks — at the price of duplicates, retries, and eventual completion. →

Microservices

5 topics
30 Service DiscoveryService discovery lets a caller find a service by name and receive its currently healthy instances, so addresses can change with autoscaling, crashes, and deploys without anyone editing configuration. → 31 Sidecar PatternThe Sidecar pattern runs a helper process next to every application instance so cross-cutting work like logging, secrets, TLS, and traffic management lives in infrastructure instead of being rebuilt in every service and language. → 32 Circuit Breaker PatternA circuit breaker watches calls to one dependency and, once failures or slow calls cross a threshold, stops calling it so a local slowdown does not consume every thread and become a system-wide outage. → 33 SAGA PatternA saga replaces one distributed transaction with a sequence of local transactions across services, plus compensating actions that undo completed steps when a later step fails. → 34 Service MeshA service mesh moves timeouts, retries, encryption, routing, and telemetry out of application code and into a fleet of proxies that the platform configures centrally. →

Big Data Processing

5 topics
35 Batch vs Stream ProcessingBatch processing runs finite jobs over bounded data for throughput and exact reprocessing; stream processing runs forever over unbounded events for low latency, at the cost of windows, watermarks, state, and delivery guarantees. → 36 ETL PipelinesAn ETL pipeline moves data from many source systems into one trusted analytical store by extracting changes, transforming them into agreed shapes, and loading them in a repeatable, monitored, and replayable way. → 37 MapReduceMapReduce is a batch framework that splits a huge dataset into independent map tasks, groups intermediate results by key through shuffle and sort, and aggregates them in reduce tasks — while the framework handles distribution and failure. → 38 Data LakesA data lake stores raw data from many sources in cheap object storage and applies schema when it is read, which makes it flexible and inexpensive but puts the burden of cataloging, governance, and quality on the organization. → 39 Data WarehousingA data warehouse is a separate analytical database that enforces a schema before loading, stores data column-wise across many machines, and models it into facts and dimensions so business questions can scan history without slowing production. →

Architectural Patterns

5 topics
40 Client-Server ArchitectureClient-server architecture splits responsibilities between clients that handle interaction and servers that own shared data, business rules, and permissions — communicating over a network through a request-response contract. → 41 Microservices ArchitectureMicroservices split a system into small, independently deployable services, each owning its data and exposing a contract — trading in-process simplicity for network boundaries, distributed data, and serious operational machinery. → 42 Serverless ArchitectureServerless hands server provisioning, patching, and capacity planning to a cloud provider: you deploy code and managed services, and the platform runs, scales, and bills them per use — while retries, cold starts, limits, and lock-in stay your problem. → 43 Event-Driven ArchitectureEvent-driven architecture replaces direct calls with facts: a producer announces that something happened, a broker stores and delivers it, and any number of consumers react on their own — trading immediate consistency and simple debugging for decoupling and resilience. → 44 Peer-to-Peer (P2P) ArchitecturePeer-to-peer architecture spreads bandwidth, storage, and compute across the participants themselves, so capacity grows with demand — at the price of churn, unreliable connectivity, and having to trust nobody in particular. →

Observability

2 topics
45 LoggingGood logging is not more logging: it is structured events with consistent fields, honest levels, a correlation ID, and enough context to explain an incident — while keeping secrets out and volume affordable. → 46 Alert & MonitoringMonitoring records what the system is doing; alerting decides which of those facts is worth waking a human for. A good alerting system fires quickly when something important breaks and stays quiet the rest of the time. →

Security

3 topics
47 JWTA JWT is a signed, self-contained token that lets any service holding the issuer's public key verify who the user is without a session lookup — at the cost of revocation and exposure. → 48 SSL/TLSTLS turns an untrusted network into a channel that is private, tamper-evident, and bound to a verified server identity — confidentiality, integrity, and authentication for data in transit. → 49 RBACRBAC replaces per-user permission assignments with roles: permissions are grouped into named bundles, roles are assigned to users, and every request is checked against the result — which stays manageable only if roles are designed and reviewed deliberately. →
