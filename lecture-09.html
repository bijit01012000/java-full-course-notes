    Part 2 · Arrays & OOP Core · Lecture 09

    Java Arrays Explained — Declaration, Initialization, Traversal & a First Look at String

    17 sections · interview-oriented · both themes

    Scope evidence: lecture title "Introduction to Arrays | Declaration, Initialization, Traversal | String Intro" (playlist map, verified). Repo evidence: code/Demo.java, Demo2.java, Demo3.java.

    An array is the first data structure Java gives you: a fixed-size, homogeneous, reference-type container that stores many values of one type under a single name. This lecture covers how an array is declared, created and initialized, the default value each element receives, how to traverse it with the classic for, the enhanced for and while, the two array exceptions, arrays of objects and arrays of arrays, the first look at String, and the pitfall catalogue — == versus contents, the unreadable [I@hash print, the length family, and off-by-one. Defaults tie back to Lecture 3, for-each detail to Lecture 8, the entry-point signature to Lecture 2, and String depth to Lecture 25.

    1. What Is an Array?

    An array is a container object that holds a fixed number of values of a single type, each reachable by a zero-based index. The four facts that define it:

    1. Fixed size — the length is chosen at creation and can never grow or shrink. A full array cannot be resized; a new array must be created.
    2. Homogeneous — every element has the same type, which is fixed when the array is declared.
    3. Reference type — the array is an object on the heap; the variable holds a reference to it, not the values themselves.
    4. Zero-based indexing — the first element is at index 0, the last at length - 1.

    Because the array is an object, its elements live contiguously in the heap and are reached through the reference in O(1). The deeper memory picture — heap layout, contiguity, random access — belongs to Lecture 10.

    Memory aid — an array is a numbered row of identical lockers: one label holds the whole row, you open a locker by its number, and the row count is fixed when the row is built.

    2. Declaring an Array — Two Legal Forms

    A declaration only names the variable and fixes the element type; it allocates nothing. The four forms to know are int[] a; (preferred — the type is "int array"), int b[]; (legal C-style, still an int array), int[] x, y; (both are arrays), and the trap form int m[], n; (m is an array, n is a plain int).

    1. int[] a and int a[] compile to the same type; the first is idiomatic and is what every style guide recommends.
    2. The brackets position in a multi-declarator statement matters: int m[], n; declares one array and one primitive.
    3. After declaration, the reference is null until an array is created — using it before creation throws NullPointerException.
    4. The element type may be primitive or reference; String[] names; is equally valid.

    Golden rule The brackets belong to the type, not the variable — write int[] a. Java permits int a[] only for C familiarity, and it silently changes meaning in multi-variable declarations.

    3. Creating and Initializing an Array

    There are three creation styles, and the third is easy to miss:

    // Demo.java — declaration and initialization forms
public class Demo {
    public static void main(String[] args) {
        int[] a = {10, 20, 30};        // literal initializer (declaration only)
        int[] b = new int[3];          // default-filled: 0, 0, 0
        int[] c = new int[]{1, 2, 3};  // anonymous array initializer
        int d[] = new int[2];          // C-style declaration, legal but discouraged
        System.out.println(a.length + " " + b[0] + " " + c[2] + " " + d.length);
    }
}
    1. Literal form int[] a = {10, 20, 30}; — the size is inferred from the values. It is legal only where the declaration and the initializer appear together.
    2. new form int[] b = new int[3]; — allocates three slots and fills each with the type default. The length is fixed at this instant.
    3. Anonymous form int[] c = new int[]{1, 2, 3}; — the new type with a literal body, legal anywhere an expression is allowed, including method arguments.
    4. Mixed form int[] e = new int[5]; e[0] = 7; — create empty, then assign by index.

    The subtle rule: a = {1, 2, 3}; after int[] a; is a compile error. The literal braces are tied to the declaration, so a later reassignment must use new int[]{1, 2, 3}. A negative length compiles but throws NegativeArraySizeException at runtime — a length is a runtime value the compiler cannot police.

    4. Default Values of Array Elements

    new always fills an array with defaults, exactly as object fields are filled (Lecture 3):

    Element type Default value Notes
    byte, short, int, long 0 0L for long
    float, double 0.0 0.0f for float
    boolean false never 0
    char '\u0000' the null character, not a space
    reference types (String, arrays, objects) null no object is created

    The last row is the one that bites: new String[3] creates an array of three null references, not three empty strings. Touching any element before assignment throws NullPointerException. This is the same JVM defaulting rule as fields, and the same reason a local variable has no default at all.

    Interviewer's perspective "What does new int[5] contain?" — five zeros, guaranteed by the JVM, not by any constructor you wrote. The candidate who answers "garbage" is thinking of C; the candidate who answers "null" has confused int with a reference type.

    5. Accessing Elements and the length Field

    An element is read or written as array[index]. Both index and bounds are checked at runtime:

    1. The first element is a[0]; the last is a[a.length - 1].
    2. length is a final field of the array object — it has no parentheses and cannot be assigned.
    3. length is set once at creation and never changes.
    4. new int[0] is legal: an empty array with length == 0, which is not null. An empty array is a valid, iterable object; a null array is a trap waiting for an NPE.

    The difference between "empty" and "null" is a favourite beginner question and a common production bug: a.length on a null array throws, while a.length on an empty array safely returns 0.

    Important length is a field, length() is a method String happens to own, and size() is a method collections own. Three similar names, three different owners — the table in Section 12 holds them side by side.

    6. Traversing an Array

    Three loops cover every traversal; each has a distinct strength:

    // Demo2.java — three traversal styles
public class Demo2 {
    public static void main(String[] args) {
        int[] nums = {4, 8, 15, 16, 23, 42};
        for (int i = 0; i < nums.length; i++)      // index traversal
            System.out.print(nums[i] + " ");
        int sum = 0;
        for (int n : nums) sum += n;               // for-each: read-only copy
        System.out.println(sum);
        int i = 0;
        while (i < nums.length) {                  // while traversal
            System.out.print(nums[i] + " ");
            i++;
        }
    }
}
    1. Classic for — you own the index, so you can read a[i], write a[i], traverse backward, or step by two. The condition must be i < a.length, never i <= a.length.
    2. Enhanced for (for-each) — for (int n : nums) visits each element without an index. The variable n is a copy: assigning to it does not write back into the array. The full for-each contract, including collections, is Lecture 8 and Lecture 30.
    3. while — the same index traversal without the header; the update lives in the body, so forgetting i++ is an infinite loop.

    The choice rule: need the position or a write-back, use the index form; need only to read each value, use for-each. For-each can never modify a primitive array in place.

    Interviewer's perspective "Why did doubling n inside for (int n : nums) change nothing?" Because n is a copy of the element, not a reference to the slot. Writing back requires nums[i] *= 2 in an index loop. This is the single most common for-each misunderstanding.

    7. ArrayIndexOutOfBoundsException and NegativeArraySizeException

    An array knows its own length, so every access a[i] is checked at runtime: if i < 0 or i >= a.length, the JVM throws ArrayIndexOutOfBoundsException. The bounds cannot be checked at compile time because the index is usually computed at runtime.

    1. The check happens on both read and write — a[99] = 1; throws just as int x = a[99]; does.
    2. The classic trigger is the off-by-one condition for (int i = 0; i <= a.length; i++), whose last value is a.length.
    3. A negative index also throws — the exception name covers both ends.
    4. The separate NegativeArraySizeException is thrown by new int[-1], at the moment of creation, not access.

    Both are unchecked (runtime) exceptions: the compiler accepts the code, and the JVM rejects the value at the moment the flawed value is used.

    Important Bounds are checked on every array access, which is a small cost Java accepts for memory safety. The reward: a bad index fails loudly and immediately at the exact line, rather than silently corrupting memory as an unchecked access would.

    8. Arrays of Objects and Arrays of Arrays

    An array of a reference type holds references, not objects. Creating the array does not create the elements — only the slots, each initialized to null:

    // Demo3.java — arrays of references and arrays of arrays
public class Demo3 {
    public static void main(String[] args) {
        String[] names = new String[2];     // elements default to null
        names[0] = "Ada";
        names[1] = "Linus";
        int[][] grid = new int[2][3];       // 2 rows x 3 columns, all 0
        int[][] jagged = {{1, 2}, {3, 4, 5}};   // rows of different lengths
        System.out.println(grid[1][2] + " " + jagged[1].length + " " + names[0].length());
    }
}
    1. Array of objects — names holds two String references. new String[2] creates the row, not the strings; each slot must be assigned before use.
    2. Two-dimensional array — int[][] grid = new int[2][3]; is an array whose elements are three-element int arrays. It is a grid of rows and columns, all zero.
    3. Jagged array — new int[3][] defers each row's size; rows may have different lengths. Java has no true multidimensional array: every "2D array" is an array of references to arrays.
    4. grid[1][2] reads row 1, column 2; grid.length is the row count, grid[1].length the length of row 1.

    Important Memory model matters here: int[][] m = new int[3][4]; creates one outer array and three inner arrays — four objects. With new int[3][] only the one outer array exists until each row is created.

    9. The String[] args Entry-Point Pointer

    The main method's parameter is an array of String references: public static void main(String[] args), and inside the method args.length reports how many arguments arrived.

    1. The launcher splits the command line after the class name into arguments: java Demo hello world gives args.length == 2, with args[0] == "hello" and args[1] == "world".
    2. With no arguments, args is an empty array (length == 0), not null under a normal launch — so iterating it is safe.
    3. Because args is an array, it carries the fixed length and zero-based indexing of every array; it cannot collect more arguments than were passed.
    4. The signature and its exact spelling come from Lecture 2; a full command-line-argument treatment with parsing is Lecture 15.

    Interviewer's perspective "Is args ever null?" Under the standard java launcher it is an empty array when no arguments are supplied. Defensive code still checks args.length, but an NPE from a normally launched main is not expected.

    10. Introduction to String

    String is the first class this course touches closely, and one fact must be held from the start:

    1. String is a reference type, not a primitive. There are eight primitives (Lecture 3); String is not one of them. A String variable holds a reference to a String object.
    2. String literals are written in double quotes: String s = "Java";. A literal is automatically a String object — no new is required.
    3. Immutability preview — once created, a String object's contents never change. Every "modifying" method such as toUpperCase() returns a new String; the original is untouched. The full treatment is Lecture 25.
    4. String pool preview — identical literals reuse one shared object in a special pool, which is why two literals with the same text are ==-equal, while a literal and a new String(...) of the same text are not.

    String looks array-like but is not an array: it has no [] indexing, it exposes length() (a method) and charAt(i) (for the i-th character). The length family distinction is captured in Section 12.

    Golden rule String is a class, so String[] args is an array of references to String objects. Treat every string operation as producing a new string, never as editing an existing one.

    11. Common Array Patterns

    Five patterns appear in nearly every written exercise and interview:

    int[] a = {3, 7, 1, 9, 4};
int sum = 0, max = a[0], min = a[0];
for (int x : a) {                 // sum, max, min in one pass
    sum += x;
    if (x > max) max = x;
    if (x < min) min = x;
}
int target = 9, found = -1;
for (int i = 0; i < a.length; i++) {   // linear search
    if (a[i] == target) { found = i; break; }
}
for (int i = 0, j = a.length - 1; i < j; i++, j--) {  // reverse in place
    int t = a[i]; a[i] = a[j]; a[j] = t;
}
    1. Sum / average — one pass with an accumulator; average is (double) sum / a.length.
    2. Maximum and minimum — seed with a[0] (never 0) so an all-negative array still works.
    3. Reverse in place — swap the two ends and walk inward; O(n) time, no extra space. The two-pointer update i++, j-- is the whole trick.
    4. Reverse into a new array — b[i] = a[a.length - 1 - i]; costs an extra array but leaves the original untouched.
    5. Linear search — scan until a match; break on success. An unsuccessful search returns a sentinel such as -1, which is why found is seeded to -1, not 0.

    The reverse comparison is a design question, not a syntax one: in-place saves memory but mutates the caller's data; the copy is safer when the original is needed later.

    12. Pitfalls and the length Family

    Five pitfalls account for most array bugs:

    Pitfall Example What happens Fix
    == instead of contents if (a == b) on two arrays Compares references, so false even for equal contents Compare element by element, or Arrays.equals (Lecture 22)
    Printing an array directly System.out.println(a); Prints [I@1b6d3586 — the type code plus identity hash Arrays.toString(a) for 1D, deepToString for 2D
    Off-by-one for (i = 0; i <= a.length; i++) Reads a[a.length] — ArrayIndexOutOfBoundsException Use i < a.length
    Null versus empty String[] a = null; a.length; NullPointerException A null array is not an empty array — initialize or check
    Literal reassignment a = {1, 2, 3}; after declaration Compile error Write a = new int[]{1, 2, 3};

    The length family is worth a table of its own, because the name collides across three kinds of object:

    Expression Applies to Kind Example
    a.length arrays final field int[] a = new int[5]; int n = a.length;
    s.length() String method int n = "Java".length();
    list.size() collections method int n = new java.util.ArrayList<>().size();

    Important Arrays answer with a field, String and collections answer with a method. length without parentheses and length() with them is a deliberate distinction, not an inconsistency to memorize blindly.

    13. Myth vs Reality

    Myth Reality
    "Arrays grow automatically" An array's length is fixed at creation; adding an element requires a new, larger array and a copy.
    "An array of objects creates the objects" It creates only the reference slots, all null; each object must be constructed and assigned separately.
    "a == b compares the contents" == compares references; two distinct arrays with equal elements are not ==. Content equality needs Arrays.equals (Lecture 22).
    "new int[-1] is a compile error" It compiles and throws NegativeArraySizeException at runtime, because the length is a runtime value.
    "length() works on arrays" Arrays use the field length; only String has the length() method.

    14. Common Trap Questions

    Trap 1 — "int m[], n; — what types are m and n?" m is int[]; n is a plain int. The brackets attach to the declarator only when they trail a single name in a multi-variable statement. int[] m, n; makes both arrays.

    Trap 2 — "a = {1, 2, 3}; after int[] a; — does it compile?" No. The brace literal is legal only in the declaration itself. A later assignment needs the anonymous form: a = new int[]{1, 2, 3};.

    Trap 3 — "Two arrays with the same five elements are ==. True?" False. == compares the references, and two arrays created separately are different objects. Equal contents require element comparison or Arrays.equals.

    Trap 4 — "System.out.println(arr); prints the elements, right?" No. It prints the object's toString, which for an array is its type code and hash, such as [I@1b6d3586. Use Arrays.toString(arr), or Arrays.deepToString for nested arrays.

    Trap 5 — "new int[5] holds five nulls?" No — five zeros. null is the default for reference element types such as String[]; int is a primitive, and its default is 0.

    Trap 6 — "a.length and "Java".length are the same call?" They are different members. a.length is a final field on the array; "Java".length() is a method on String. The parentheses make the difference.

    15. Points to Remember

    1. An array is a fixed-size, homogeneous, zero-indexed, reference-type container whose object lives on the heap.
    2. Both int[] a and int a[] compile; prefer the first, and watch int m[], n;, which declares one array and one int.
    3. A declaration allocates nothing — the reference is null until new or a literal initializer runs.
    4. Three creation styles: literal {...} (declaration only), new int[n] (default-filled), and new int[]{...} (anonymous, usable in expressions).
    5. new fills elements with defaults: 0, 0.0, false, '\u0000', and null for references (Lecture 3).
    6. length is a final field set at creation; new int[0] is a legal empty array, distinct from null.
    7. Traversal: classic for for the index and write-back, for-each for read-only element copies, while when the shape fits.
    8. Index errors throw ArrayIndexOutOfBoundsException at runtime; a negative size throws NegativeArraySizeException at creation.
    9. An array of objects holds references only; a 2D array is an array of arrays, and jagged rows may differ in length.
    10. == compares references, printing an array shows [I@hash, arrays use length, String uses length(), collections use size().

    16. Likely Interview Questions

    Question Crisp Answer
    What is an array in Java? A fixed-size, homogeneous, reference-type container of values reached by zero-based index; the array itself is an object on the heap.
    Difference between int[] a and int a[]? None in type; both declare an int array. The first is idiomatic; the second is C-style and changes meaning in int m[], n;.
    Does declaring an array allocate memory? No — declaration only names the reference. Allocation happens at new or literal initialization; before that the reference is null.
    Difference between new int[3] and {1, 2, 3}? The first creates three default zeros; the second creates three slots containing the given values and is legal only in the declaration.
    What are the default values of an array? 0 / 0.0 / false / '\u0000' for primitives and null for references, applied automatically by new.
    Is a.length a field or a method? A final field on the array object — no parentheses, set at creation, never reassigned.
    Why does a[0] work but a[a.length] throw? Indexing is zero-based, so the last valid index is length - 1; length is out of bounds and throws ArrayIndexOutOfBoundsException.
    Difference between ArrayIndexOutOfBoundsException and NegativeArraySizeException? The first is thrown by an out-of-range access; the second by new with a negative length. Both are runtime, not compile-time.
    Can a 2D array be jagged in Java? Yes — new int[3][] creates three rows sized independently; Java has no true multidimensional array, only arrays of arrays.
    Can for-each modify an array? Not for primitives: the loop variable is a copy. Write-back needs an index loop such as a[i] *= 2.
    Is String a primitive type? No — String is a class, a reference type. Its literals live in the string pool and its objects are immutable (Lecture 25).
    What does String[] args hold? The command-line arguments the launcher passes to main; an empty array when none are supplied, never null under a normal launch.

    17. Final Summary

    declare (int[] a) --> create (new int[3]) --> default-fill (0, 0, 0)
        --> access a[i] (0 .. length-1, checked at runtime)
        --> traverse (for index / for-each / while)
        --> grow? NO: create a bigger array and copy

bad index      -> ArrayIndexOutOfBoundsException
negative size  -> NegativeArraySizeException
print directly -> [I@hash  (use Arrays.toString)
compare        -> a == b tests references, not contents
    • Array → fixed-size, homogeneous, reference-type container; index 0 to length - 1; length is a final field.
    • Declaration → int[] a preferred; int a[] legal; int m[], n; declares one array and one int.
    • Creation → new int[n] defaults every slot; {...} works only in the declaration; new int[]{...} works anywhere.
    • Defaults → 0, 0.0, false, '\u0000', null for references (Lecture 3).
    • Traversal → index for for reads and write-backs, for-each for read-only copies (Lecture 8), while for the same walk without a header.
    • Arrays of references → slots default to null; appending means a new array and a copy.
    • Pitfalls → == versus contents (Lecture 22 equals), [I@hash printing, the length / length() / size() family, and off-by-one.

    Golden rule An array's length is fixed forever and its bounds are checked on every access — so create the right size up front, index from 0 to length - 1, and never mistake a field for a method (length for arrays, length() for String).

    One-line takeaway: an array is a fixed-size reference container of one type and zero-based indices, filled with defaults at new, walked by index or by for-each, guarded at runtime against bad indices — and String[] args is simply the first array every Java program already owns.
