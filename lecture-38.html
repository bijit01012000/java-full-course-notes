    Part 5 · Collections, Lambdas & Streams · Lecture 38

    Lambdas & Functional Interface Deep Dive | Method References & Composition

    20 sections · interview-oriented · both themes

    Scope evidence: "Lambdas & Functional Interface Deep Dive | Method References & Composition" (playlist map, verified). Repo evidence: 6 Demo files.

    Lecture 37 introduced lambdas as anonymous functions and functional interfaces as their target types. This lecture goes one level deeper: the :: operator (method references), target typing when a reference must match a functional interface, and the composition toolkit (andThen, compose, and, or, negate) that turns small functions into pipelines. It also revisits effectively-final capture from Lecture 37 and shows higher-order functions built from a custom @FunctionalInterface. Everything here is the vocabulary that streams (Lecture 39) and collectors (Lecture 40) are built on.

    1. Why Method References Exist

    A lambda expresses behaviour as a body. Very often that body does nothing except call a method that already exists:

    Function<String, Integer> f = s -> s.length();

    The lambda adds no logic; it only forwards its argument to String.length(). The :: operator writes exactly this forwarding shape without repeating the parameter names:

    Function<String, Integer> f = String::length;

    A method reference is therefore not a new kind of value. It is a shorter, more readable lambda whose body is a single existing method. The compiler desugars it back into the equivalent lambda, so anything a lambda can target, a method reference can target too.

    The two forms trade explicitness for brevity:

    Aspect Lambda Method Reference
    Shape parameter list plus body owner plus :: plus name
    Best when body does real work body is one method call
    Names reused rewrites the logic reuses an existing method
    Target type required required (same rule)
    Capture captures used variables captures the receiver for bound refs
    Readability risk verbose but explicit cryptic when overloaded

    Important A method reference does not call the method at the point of writing. It creates an object that implements the functional interface; the referenced method is invoked only when the interface method (for example apply or test) is called.

    2. The :: Operator and the Five Kinds

    Java supports five syntactically distinct method references. They differ only in where the receiver (the object or class the method is called on) comes from.

    1. Static method reference — Class::staticMethod. The receiver is the class itself; the arguments of the functional interface are passed straight through.
    2. Bound instance method reference — obj::method. The receiver is a specific object captured at the moment the reference is created.
    3. Unbound instance method reference — Class::instanceMethod. There is no captured receiver; the first argument of the functional interface becomes the receiver, and the remaining arguments become the method arguments.
    4. Constructor reference — Class::new. Produces a new instance; arguments go to the matching constructor.
    5. Array constructor reference — Type[]::new. Produces a new array sized by the single int argument.

    The words bound and unbound describe the receiver, not the method. bound means "this exact object, fixed now"; unbound means "whatever object is supplied later as the first argument".

    3. Mapping Method References to Lambdas

    This table is the whole :: operator in one place. Read the middle column as "what the receiver does", and the right column as the lambda you could have written.

    Kind Syntax Lambda equivalent Receiver source
    Static Class::staticMethod x -> Class.staticMethod(x) the class
    Bound instance obj::method x -> obj.method(x) a captured object
    Unbound instance Class::instanceMethod (obj, x) -> obj.method(x) first argument
    Constructor Class::new x -> new Class(x) none (creates one)
    Array constructor Type[]::new n -> new Type[n] none (creates one)

    Memory aid Static takes no receiver; bound bakes in a receiver; unbound borrows the first argument as its receiver.

    4. Target Typing for Method References

    A method reference is a bare name, so by itself it has no type. The compiler infers its type from the assignment or parameter it is placed in — the target type, which must be a functional interface with a compatible single abstract method (SAM).

    Function<String, Integer> f = String::length;   // length() returns int, autoboxed to Integer
ToIntFunction<String> g    = String::length;    // primitive int result, no boxing

    Both lines reference the same method, but the target decides the SAM signature and therefore the result type. When a method is overloaded, the compiler uses the target's SAM signature to choose the overload; if no overload fits, you must write an explicit lambda or cast, because a method reference cannot express disambiguation on its own.

    Interviewer's perspective "Why does String::length compile as ToIntFunction<String>?" Because the target type supplies the parameter list and return type. The reference only needs a method whose signature is compatible with the target's SAM — this is target typing, not inference of the reference in isolation.

    5. Bound vs Unbound Receivers (the classic confusion)

    The same method name can produce two very different references.

    String s = "hello";
Supplier<Integer> bound = s::length;        // () -> int, receiver is s
Function<String, Integer> unbound = String::length; // (String) -> int, receiver is the argument
    • s::length is bound: the receiver s is captured now, so the interface method takes no arguments (Supplier).
    • String::length is unbound: the receiver arrives later as the first argument, so the interface method takes one argument (Function).

    The unbound form is why String::length needs a String argument. Reading String::length as "call length on the class" is the single most common misunderstanding of ::.

    6. Function Composition: andThen vs compose

    Function<T, R> provides two default methods that chain two functions.

    Function<Integer, Integer> f = x -> x + 1;
Function<Integer, Integer> g = x -> x * 2;

f.andThen(g).apply(4);   // (4 + 1) * 2 = 10
f.compose(g).apply(4);   // (4 * 2) + 1 = 9
    • f.andThen(g) runs f first, then feeds its result to g. Data flows left to right.
    • f.compose(g) runs g first, then feeds its result to f. Data flows right to left.

    The two are mirror images: f.andThen(g) is the same function as g.compose(f).

    Memory aid andThen follows the reading order (this, then that). compose works backwards, like the word says — the argument is the inner function.

    7. Predicate Composition: and, or, negate, isEqual

    Predicate<T> composes boolean tests with short-circuit logic.

    Method Signature shape Meaning
    and this && other true only when both tests are true
    or this \|\| other true when either test is true
    negate !this logical complement
    isEqual (static) Predicate.isEqual(target) true when the argument equals target, null-safe 
    Predicate<String> nonNull = s -> s != null;
Predicate<String> nonEmpty = s -> !s.isEmpty();
Predicate<String> valid = nonNull.and(nonEmpty);
Predicate<String> blank = valid.negate();
System.out.println(valid.test("ok") + " " + blank.test(""));

    and and or evaluate the left test first and short-circuit, so the right test is never reached when the result is already decided — the same safety && and || give in ordinary code.

    8. Consumer.andThen and the identity Methods

    Consumer<T> returns nothing, but it can still be chained. Consumer.andThen runs the first consumer, then the second on the same input, in order.

    Consumer<String> log   = s -> System.out.println("log: " + s);
Consumer<String> count = s -> System.out.println("len: " + s.length());
Consumer<String> both  = log.andThen(count);
both.accept("java");

    Two identity constants appear constantly in pipelines:

    • Function.identity() returns its argument unchanged — a Function<T, T> used as the key or value mapper in collectors (forward reference: Lecture 40).
    • UnaryOperator.identity() is the same idea for UnaryOperator<T>, which is just Function<T, T> with a clearer name.

    9. Building Pipelines

    The composition methods seen so far, gathered in one place:

    Interface Method Chain semantics
    Function andThen this first, then the argument
    Function compose the argument first, then this
    Predicate and true only if both are true
    Predicate or true if either is true
    Predicate negate logical complement
    Consumer andThen run this, then the argument
    Function / UnaryOperator identity return the input unchanged

    Composition is how small named steps become one named pipeline. Read each statement as "this step, and then that step".

    Function<String, String> trim  = String::trim;
Function<String, String> upper = String::toUpperCase;
Function<String, String> clean = trim.andThen(upper);

Predicate<String> nonNull  = Objects::nonNull;
Predicate<String> nonEmpty = s -> !s.isEmpty();
Predicate<String> valid    = nonNull.and(nonEmpty);

    clean.apply(" java ") is "JAVA"; valid.test(null) is false without a NullPointerException, because and short-circuits before nonEmpty runs. Pipelines are also reusable: clean and valid are values that can be stored, passed, and combined again.

    10. Higher-Order Functions and a Custom Functional Interface

    A higher-order function is a method that accepts a functional interface as a parameter, or returns one, or both. Composition methods are themselves higher-order: andThen accepts a function and returns a function.

    You can define your own functional interface, give it a default composition method, and then use it exactly like the JDK ones.

    @FunctionalInterface
interface IntOp {
    int apply(int x);

    default IntOp andThen(IntOp after) {
        return x -> after.apply(this.apply(x));
    }
}

    Important @FunctionalInterface is a compiler check, not a runtime requirement. It enforces that the interface has exactly one abstract method; default and static methods do not count, which is why andThen above is allowed.

    11. Effectively-Final Capture and Receiver Capture

    Recall from Lecture 37: a lambda may use a local variable from the enclosing scope only if that variable is final or effectively final (assigned exactly once). A method reference obeys the same rule for what it captures.

    • A bound instance reference (obj::method) captures the receiver obj. The reference holds that object for as long as the reference lives.
    • An unbound reference (Class::instanceMethod) captures nothing; the receiver is supplied per call.
    • this::method inside an instance captures the current object, which is why it behaves like a bound reference to this.

    12. Method Reference Gallery

    import java.util.function.*;

public class Demo {
    static int len(String s) { return s.length(); }

    public static void main(String[] args) {
        Function<String, Integer> f1 = Demo::len;        // static
        Function<String, Integer> f2 = String::length;   // unbound instance
        String prefix = "Hi ";
        Function<String, String> f3 = prefix::concat;    // bound instance
        Supplier<StringBuilder> f4 = StringBuilder::new; // constructor
        IntFunction<int[]> f5 = int[]::new;              // array constructor

        System.out.println(f1.apply("abc") + f2.apply("abcd")); // 3 + 4
        System.out.println(f3.apply("Sam"));                    // Hi Sam
        System.out.println(f4.get().append("x"));               // x
        System.out.println(f5.apply(3).length);                 // 3
    }
}

    13. Composing Predicates and Functions

    import java.util.function.*;

public class Demo3 {
    public static void main(String[] args) {
        Function<String, String> trim  = String::trim;
        Function<String, String> upper = String::toUpperCase;
        Function<String, String> clean = trim.andThen(upper);
        Function<String, String> same  = upper.compose(trim);

        System.out.println(clean.apply("  java  ")); // JAVA
        System.out.println(same.apply("  java  "));  // JAVA

        Predicate<String> nonNull  = s -> s != null;
        Predicate<String> nonEmpty = s -> !s.isEmpty();
        Predicate<String> valid    = nonNull.and(nonEmpty);
        System.out.println(valid.test("ok") + " " + valid.test("")); // true false
    }
}

    14. A Custom Functional Interface with andThen

    @FunctionalInterface
interface IntOp {
    int apply(int x);

    default IntOp andThen(IntOp after) {
        return x -> after.apply(this.apply(x));
    }
}

public class Demo6 {
    public static void main(String[] args) {
        IntOp inc = x -> x + 1;
        IntOp dbl = x -> x * 2;
        IntOp pipeline = inc.andThen(dbl);      // dbl(inc(x))
        System.out.println(pipeline.apply(5));  // (5 + 1) * 2 = 12
    }
}

    15. Common Pitfalls and Errors

    Symptom Cause Fix
    String::length "cannot be applied" Treated as bound when it is unbound Give it a String argument via Function<String, Integer>
    Reference is ambiguous Overloaded method, unclear target Use an explicit lambda or cast to the target interface
    this unexpectedly bound this::m captures the enclosing instance Use a lambda, or capture a different receiver explicitly
    Wrong order in a pipeline compose runs backwards Swap to andThen, or reverse the operands
    Unexpected side effects Consumers in an andThen chain all run Keep pipeline steps pure; isolate side effects
    cannot infer type arguments Generic method with no target hint Supply explicit type arguments, e.g. this::<String>m
    Compile error on the interface Target is not a functional interface Use an interface with exactly one abstract method

    16. Myth vs Reality

    Myth | Reality ":: calls the method immediately." | It creates an interface instance; the method runs when the SAM is invoked. "String::length means length on the class." | It is unbound: the first argument supplies the receiver. "Method references and lambdas are different types." | They are two syntaxes for the same functional-interface value; the compiler desugars one to the other. "compose and andThen are the same." | They differ in order: andThen is left-to-right, compose is right-to-left. "Method references always improve readability." | For non-trivial logic an explicit lambda is clearer and safer.

    17. Common Trap Questions

    Trap 1 — "Is System.out::println static or bound?" It is a bound instance reference: the receiver is the System.out object, captured now.

    Trap 2 — "Can a method reference capture a non-final local?" No — the receiver must be effectively final, exactly like a captured lambda variable.

    Trap 3 — "What does f.andThen(g).apply(x) return?" g(f(x)). andThen executes the receiver first.

    Trap 4 — "Does Predicate.and evaluate both predicates?" No — it short-circuits, so the second runs only if the first is true.

    Trap 5 — "Where do variable arguments go in Class::new?" To the constructor whose signature matches the target's SAM; Supplier picks the no-arg constructor.

    Trap 6 — "Is @FunctionalInterface required to use a lambda?" No — it is optional documentation and a compile-time guard; only the SAM shape matters.

    Trap 7 — "Does super::method capture the same object as this::method?" It captures the same instance but dispatches to the superclass method.

    18. Points to Remember

    1. A method reference is a lambda whose body is a single existing method call.
    2. Five kinds exist: static, bound instance, unbound instance, constructor, array constructor.
    3. Bound captures the receiver now; unbound takes the receiver as the first argument later.
    4. A method reference needs a target functional interface; the target's SAM fixes its type.
    5. Overload resolution for :: follows the target's SAM signature, not the name alone.
    6. andThen runs left-to-right; compose runs right-to-left; they are mirror images.
    7. Predicate composes with and, or, negate, and the static isEqual, and short-circuits.
    8. Consumer.andThen chains side effects; Function.identity and UnaryOperator.identity pass values through.
    9. Higher-order functions accept or return a functional interface; composition methods are higher-order.
    10. Captured locals must be effectively final, and a bound reference captures its receiver.

    19. Likely Interview Questions

    Question | Crisp Answer What is a method reference? | A compact syntax (::) for a lambda that forwards to an existing method; the compiler desugars it to the equivalent lambda. Name the kinds of method references. | Static, bound instance, unbound instance, constructor, and array constructor. Difference between bound and unbound? | Bound captures a specific receiver and takes no receiver argument; unbound takes the receiver as the first argument. How is String::length typed? | By its target: Function<String, Integer>, ToIntFunction<String>, etc. The target fixes the SAM signature. What is target typing? | The compiler derives the type of a lambda or method reference from the functional interface it is assigned to. andThen vs compose? | f.andThen(g) is g(f(x)); f.compose(g) is f(g(x)). Order is opposite. How do you combine predicates? | Predicate.and, Predicate.or, Predicate.negate, and static Predicate.isEqual. What is Function.identity() for? | A Function<T, T> that returns its input; used as a mapper in collectors (Lecture 40). What is a higher-order function? | A method that takes and/or returns a functional interface, such as andThen. Why does @FunctionalInterface allow default methods? | Only abstract methods count toward the single-abstract-method rule; default and static methods are ignored. Can a method reference be ambiguous? | Yes, with overloaded methods; resolve it with an explicit lambda or a cast. What does a bound reference capture? | The receiver object, which must be effectively final, held for the reference's lifetime.

    20. Final Summary

    lambda body: s -> s.length()      ==     method reference: String::length
five kinds:  static · bound · unbound · constructor · array-constructor
composition: f.andThen(g) = g(f(x))      f.compose(g) = f(g(x))
             predicate.and / or / negate / isEqual
             consumer.andThen · Function.identity · UnaryOperator.identity
pipelines:   trim.andThen(upper)      nonNull.and(nonEmpty)
    • :: → a short lambda pointing at one existing method, typed by its target interface
    • Bound vs unbound → who supplies the receiver (captured now vs first argument)
    • andThen → left-to-right; compose → right-to-left; predicate and/or/negate short-circuit
    • Higher-order → accepts or returns a functional interface; custom @FunctionalInterface + default andThen
    • Capture → effectively-final locals; a bound reference captures its receiver

    Golden rule Reach for :: when the whole body is one method call; reach for a lambda when the body does anything more.

    One-line takeaway: a method reference is a named forwarding lambda, and composition methods turn those single steps into reusable pipelines.
