    1. Binary Tree and Shape Classifications

    Problem. What is a binary tree, and how do the standard shape classifications (full, complete, perfect, balanced, degenerate) differ from each other?

    Input: n/a - conceptual

    Output: n/a - conceptual

    Approach: Recursive Height Computation

    • A binary tree is a hierarchical structure of nodes where each node has at most two children (left and right); a node with no children is a leaf, and the topmost node is the root.
    • Full binary tree: every node has either 0 or 2 children (never exactly 1).
    • Complete binary tree: every level is fully filled except possibly the last, which fills strictly left-to-right with no gaps - this is exactly the shape a heap's array-index formulas rely on.
    • Perfect binary tree: every internal node has 2 children and every leaf sits at the same depth (a special case of both full and complete).
    • Balanced binary tree: for every node, the heights of its left and right subtrees differ by at most 1 - this keeps height-dependent operations at O(log n) instead of degrading to O(n).
    • Degenerate (or "skewed") tree: every node has only one child, so the tree behaves like a linked list - the worst case for height-dependent operations.

    Time/Space: O(n) time, O(h) space.

    public int height(TreeNode root) {
 if (root == null) return 0;
 return 1 + Math.max(height(root.left), height(root.right));
}

    2. Binary Tree Node Representation

    Problem. How is a binary tree node represented in code, and how do you manually construct a small tree for testing traversal logic?

    Input: Build the tree: 1 as root, 2 as left child, 3 as right child, 4 as left child of 2

    Output: A 4-node tree where root.left.left reaches node 4

    Approach: Explicit Node Struct with Left/Right Pointers

    • A binary tree node is a struct/class holding a value plus two pointers/references to its left and right children (each null/nullptr if that child doesn't exist) - there's no implicit array-index relationship like a heap has; the tree exists purely from these explicit links.
    • The root is just a reference to the topmost TreeNode; the rest of the tree is reachable only by following left/right pointers from it - losing the reference to a subtree loses that subtree entirely (no parent pointer by default).
    • To construct a tree by hand: create each node, then wire up left/right assignments - this manual wiring is exactly what a "construct tree from traversals" algorithm automates later in this section.
    • O(1) to create a single node; O(n) to build an entire n-node tree.

    Time/Space: O(n) time, O(n) space.

    public TreeNode buildSampleTree() {
 TreeNode root = new TreeNode(1);
 root.left = new TreeNode(2);
 root.right = new TreeNode(3);
 root.left.left = new TreeNode(4);
 return root;
}

    3. Inorder Traversal

    Problem. Given a binary tree, return its inorder traversal (left subtree, then root, then right subtree).

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [4,2,1,3]

    Approach: Recursive Inorder (Left-Visit-Right)

    • Recurse into the left subtree first, then visit the current node, then recurse into the right subtree - the visit happens between the two recursive calls.
    • For a binary search tree specifically, inorder traversal visits nodes in ascending sorted order - this is why inorder is the traversal most tied to BST-specific problems later in this course.
    • O(n) time, O(h) space for the recursion stack.

    Time/Space: O(n) time, O(h) space.

    public void inorder(TreeNode root, List<Integer> result) {
 if (root == null) return;
 inorder(root.left, result);
 result.add(root.val);
 inorder(root.right, result);
}

    4. Preorder Traversal

    Problem. Given a binary tree, return its preorder traversal (root, then left subtree, then right subtree).

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [1,2,4,3]

    Approach: Recursive Preorder (Visit-Left-Right)

    • Visit the current node's value first, then recurse into the left subtree, then recurse into the right subtree - the visit happens before either recursive call.
    • Preorder naturally produces a tree's nodes in the order you'd encounter them copying/serializing the tree top-down, since a parent is always listed before its children.
    • The recursion depth equals the tree's height, so the call stack - not any extra data structure - does the bookkeeping.
    • O(n) time (visits every node once), O(h) space for the recursion stack (O(n) worst case for a skewed tree).

    Time/Space: O(n) time, O(h) space.

    public void preorder(TreeNode root, List<Integer> result) {
 if (root == null) return;
 result.add(root.val);
 preorder(root.left, result);
 preorder(root.right, result);
}

    5. Postorder Traversal

    Problem. Given a binary tree, return its postorder traversal (left subtree, then right subtree, then root).

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [4,2,3,1]

    Approach: Recursive Postorder (Left-Right-Visit)

    • Recurse into the left subtree, then the right subtree, then visit the current node last - the visit happens after both recursive calls return.
    • Postorder naturally produces a tree's nodes in the order you'd need to safely process them bottom-up (children before parent) - e.g. deleting a tree, or evaluating an expression tree (operands before operator).
    • O(n) time, O(h) space for the recursion stack.

    Time/Space: O(n) time, O(h) space.

    public void postorder(TreeNode root, List<Integer> result) {
 if (root == null) return;
 postorder(root.left, result);
 postorder(root.right, result);
 result.add(root.val);
}

    6. Level Order Traversal

    Problem. Given a binary tree, return its level order traversal (nodes grouped level by level, top to bottom, left to right within each level).

    Input: tree = [3,9,20,null,null,15,7] (root=3, left=9, right=20, 20.left=15, 20.right=7)

    Output: [[3],[9,20],[15,7]]

    Approach: BFS with Level-Size Snapshot

    • Use a queue-based BFS instead of recursion - push the root, then repeatedly process one full level at a time by recording the queue's current size before dequeuing that many nodes, pushing each dequeued node's children as they're encountered.
    • Recording the level's size upfront (rather than draining the whole queue) is what separates level boundaries - without it, all levels blend into one flat list instead of a list of lists.
    • O(n) time (each node enqueued and dequeued once), O(n) space for the queue (up to the widest level's node count) plus the output.

    Time/Space: O(n) time, O(n) space.

    public List<List<Integer>> levelOrder(TreeNode root) {
 List<List<Integer>> result = new ArrayList<>();
 if (root == null) return result;
 Queue<TreeNode> q = new LinkedList<>();
 q.add(root);
 while (!q.isEmpty()) {
 int levelSize = q.size();
 List<Integer> level = new ArrayList<>();
 for (int i = 0; i < levelSize; i++) {
 TreeNode node = q.poll();
 level.add(node.val);
 if (node.left != null) q.add(node.left);
 if (node.right != null) q.add(node.right);
 }
 result.add(level);
 }
 return result;
}

    7. Preorder, Inorder, and Postorder in One Recursive Pass

    Problem. Compute the preorder, inorder, and postorder traversals of a binary tree in a single recursive walk, instead of three separate traversals.

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: preorder=[1,2,4,3], inorder=[2,4,1,3], postorder=[4,2,3,1]

    Approach: Single Recursive Pass (Three Visit Points)

    • A single recursive function can append to three separate output lists at the three natural "visit points" of one traversal: append to preorder before recursing into either child, append to inorder between the left and right recursive calls, and append to postorder after both recursive calls return.
    • This works because a recursive traversal conceptually passes through each node three times - once before descending, once between the two subtrees, once after ascending - which are exactly the three traversal orders.
    • All three traversals come from one O(n) walk instead of three separate O(n) walks - asymptotically the same total work, but fewer redundant full-tree descents in practice.
    • O(n) time, O(h) additional space for the recursion stack (plus O(n) for the three output lists).

    Time/Space: O(n) time, O(h) space.

    public void allTraversals(TreeNode root, List<Integer> pre, List<Integer> in, List<Integer> post) {
 if (root == null) return;
 pre.add(root.val);
 allTraversals(root.left, pre, in, post);
 in.add(root.val);
 allTraversals(root.right, pre, in, post);
 post.add(root.val);
}

    8. All Traversals in One Iterative Pass

    Problem. Compute the preorder, inorder, and postorder traversals of a binary tree in a single iterative pass using one stack, instead of three separate iterative traversals.

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: preorder=[1,2,4,3], inorder=[4,2,1,3], postorder=[4,2,3,1]

    Approach: Iterative Single Stack with State Flags

    • Push (node, state) pairs onto a single stack; state tracks how many times a node has been "seen" - 1 means not yet processed, 2 means the left subtree is done, 3 means both subtrees are done.
    • On state 1: append to preorder, bump the entry's state to 2, then push the left child (state 1) if it exists - handling preorder's "visit immediately" timing.
    • On state 2: append to inorder, bump the entry's state to 3, then push the right child (state 1) if it exists - handling inorder's "visit between children" timing.
    • On state 3: append to postorder and pop the entry entirely - handling postorder's "visit after both children" timing; all three traversals come from one single-stack walk instead of three separate iterative traversals.
    • O(n) time, O(h) space for the stack.

    Time/Space: O(n) time, O(h) space.

    public void allTraversalsIterative(TreeNode root, List<Integer> pre, List<Integer> in, List<Integer> post) {
 if (root == null) return;
 Deque<Object[]> stack = new ArrayDeque<>();
 stack.push(new Object[]{root, 1});
 while (!stack.isEmpty()) {
 Object[] top = stack.peek();
 TreeNode node = (TreeNode) top[0];
 int state = (int) top[1];
 if (state == 1) {
 pre.add(node.val);
 top[1] = 2;
 if (node.left != null) stack.push(new Object[]{node.left, 1});
 } else if (state == 2) {
 in.add(node.val);
 top[1] = 3;
 if (node.right != null) stack.push(new Object[]{node.right, 1});
 } else {
 post.add(node.val);
 stack.pop();
 }
 }
}

    9. Maximum Depth of a Binary Tree

    Problem. Given a binary tree, find its maximum depth (the number of nodes along the longest path from root to the farthest leaf).

    Input: tree = [3,9,20,null,null,15,7]

    Output: 3

    Approach: Recursive Max Depth (Height Reuse)

    • Recursively compute the depth of the left and right subtrees, and return 1 plus the larger of the two - the base case is a null node, which has depth 0.
    • This is identical to the height computation from the Traversals subsection; "maximum depth" and "height" are the same quantity measured from the root.
    • O(n) time (visits every node once), O(h) space for the recursion stack.

    Time/Space: O(n) time, O(h) space.

    public int maxDepth(TreeNode root) {
 if (root == null) return 0;
 return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}

    10. Check if Two Trees are Identical

    Problem. Given two binary trees, determine whether they are structurally identical and have the same node values at every corresponding position.

    Input: tree1 = [1,2,3], tree2 = [1,2,3]

    Output: true

    Approach: Recursive Structural Comparison

    • Two trees are identical iff both roots are null (base case: equal), or both roots are non-null with equal values and their left subtrees are identical to each other and their right subtrees are identical to each other.
    • Any mismatch - one root null and the other not, or unequal values - means the trees differ, and the recursion should short-circuit to false immediately.
    • O(min(n1, n2)) time in the worst case explored (a mismatch typically returns much earlier), O(h) space for the recursion stack.

    Time/Space: O(min(n1, n2)) time, O(h) space.

    public boolean isSameTree(TreeNode p, TreeNode q) {
 if (p == null && q == null) return true;
 if (p == null || q == null || p.val != q.val) return false;
 return isSameTree(p.left, q.left) && isSameTree(p.right, q.right);
}

    11. Check for a Height-Balanced Binary Tree

    Problem. Given a binary tree, determine whether it is height-balanced (for every node, the heights of its left and right subtrees differ by at most 1).

    Input: tree = [3,9,20,null,null,15,7]

    Output: true

    Approach: Height + Failure Sentinel (Single Postorder Pass)

    • A naive approach recomputes height at every node independently, causing O(n) work per node and O(n^2) overall - instead, compute height and balance simultaneously in one postorder pass.
    • The recursive helper returns a subtree's height, but returns a sentinel (e.g. -1) the moment any subtree beneath it is found unbalanced - this short-circuits the check and propagates "already failed" up without extra recomputation.
    • At each node, if either child's returned height is the sentinel, or the two children's heights differ by more than 1, the node itself is unbalanced and returns the sentinel; otherwise it returns 1 + max(left height, right height) as normal.
    • O(n) time (single postorder pass), O(h) space - versus the naive O(n^2) of recomputing height per node.

    Time/Space: O(n) time, O(h) space.

    private int checkHeight(TreeNode node) {
 if (node == null) return 0;
 int left = checkHeight(node.left);
 if (left == -1) return -1;
 int right = checkHeight(node.right);
 if (right == -1) return -1;
 if (Math.abs(left - right) > 1) return -1;
 return 1 + Math.max(left, right);
}

public boolean isBalanced(TreeNode root) {
 return checkHeight(root) != -1;
}

    12. Diameter of a Binary Tree

    Problem. Given a binary tree, find its diameter - the length (number of edges) of the longest path between any two nodes, which may or may not pass through the root.

    Input: tree = [1,2,3,4,5]

    Output: 3 (longest path: 4 -> 2 -> 1 -> 3)

    Approach: Postorder Height with Side-Channel Best Diameter

    • The longest path through any given node equals the height of its left subtree plus the height of its right subtree (each measured in edges) - but the overall diameter might sit entirely within one subtree instead, so every node must be checked, not just the root.
    • Compute heights bottom-up in a single postorder pass, and at each node update a running "best diameter" using leftHeight + rightHeight as a side effect of computing that node's own height - this avoids a separate O(n) diameter check per node.
    • Returning height normally from the recursive call while updating a shared "best" variable is what fuses two logically separate concerns (compute height, track best diameter) into one O(n) pass.
    • O(n) time (single postorder pass with O(1) extra work per node), O(h) space.

    Time/Space: O(n) time, O(h) space.

    private int diameter = 0;

private int height(TreeNode node) {
 if (node == null) return 0;
 int left = height(node.left);
 int right = height(node.right);
 diameter = Math.max(diameter, left + right);
 return 1 + Math.max(left, right);
}

public int diameterOfBinaryTree(TreeNode root) {
 diameter = 0;
 height(root);
 return diameter;
}

    13. Maximum Path Sum

    Problem. Given a binary tree with possibly negative node values, find the maximum path sum, where a path is any non-empty sequence of nodes connected by edges (it need not pass through the root or end at a leaf).

    Input: tree = [-10,9,20,null,null,15,7]

    Output: 42 (path 15 -> 20 -> 7)

    Approach: Postorder Gain with Side-Channel Best Sum

    • For each node, compute the maximum sum achievable in a path that starts at that node and extends into at most one child (either left or right, never both) - this is the value "passed up" to the node's parent, since a path continuing upward can only use one branch below.
    • While computing that per-node "extendable" value bottom-up, also update a running "best path sum seen so far" using node.val + max(0, leftGain) + max(0, rightGain) - this allows using both children at once, but only for updating the global best, never for the value returned to the parent.
    • Clamp any negative subtree contribution to 0 before adding it in either calculation - a negative-sum branch should simply be excluded rather than dragging the total down.
    • O(n) time (single postorder pass), O(h) space.

    Time/Space: O(n) time, O(h) space.

    private int maxSum;

private int maxGain(TreeNode node) {
 if (node == null) return 0;
 int leftGain = Math.max(maxGain(node.left), 0);
 int rightGain = Math.max(maxGain(node.right), 0);
 maxSum = Math.max(maxSum, node.val + leftGain + rightGain);
 return node.val + Math.max(leftGain, rightGain);
}

public int maxPathSum(TreeNode root) {
 maxSum = Integer.MIN_VALUE;
 maxGain(root);
 return maxSum;
}

    14. Check for a Symmetric Binary Tree

    Problem. Given a binary tree, determine whether it is symmetric around its center (a mirror image of itself).

    Input: tree = [1,2,2,3,4,4,3]

    Output: true

    Approach: Recursive Crossed-Child Comparison

    • A tree is symmetric iff its left and right subtrees are mirror images of each other - define a helper that checks whether two subtrees are mirrors, rather than trying to compare the tree to itself directly.
    • Two subtrees are mirrors iff both are null (base case: mirrors), or both are non-null with equal root values, and the first's left subtree mirrors the second's right subtree, and the first's right subtree mirrors the second's left subtree - note the crossed comparison (left-to-right, right-to-left), not a same-side comparison.
    • This is the same structural-comparison recursion as Check if Two Trees are Identical, but comparing crossed children instead of same-side children.
    • O(n) time (visits every node once), O(h) space for the recursion stack.

    Time/Space: O(n) time, O(h) space.

    private boolean isMirror(TreeNode left, TreeNode right) {
 if (left == null && right == null) return true;
 if (left == null || right == null || left.val != right.val) return false;
 return isMirror(left.left, right.right) && isMirror(left.right, right.left);
}

public boolean isSymmetric(TreeNode root) {
 if (root == null) return true;
 return isMirror(root.left, root.right);
}

    15. Children Sum Property

    Problem. Given a binary tree, check whether it satisfies the children sum property - for every node with at least one child, the node's value must equal the sum of its children's values (treating a missing child as 0).

    Input: tree = [10,8,2,3,5,null,null]

    Output: true (8 = 3+5, 10 = 8+2)

    Approach: Recursive Local Sum Check

    • Recursively check each node: if it's a leaf, the property trivially holds; otherwise compute the sum of the left and right child values (0 for a missing child) and compare it to the node's own value, requiring both subtrees to also satisfy the property.
    • A closely related variant asks you to "fix" a violating tree into a valid one by only incrementing values (never decrementing) - that requires a top-down pass where each node's value is first pushed down to overwrite an undersized child, followed by a final bottom-up pass that recomputes every internal node as the sum of its (now-corrected) children, so the fix propagates consistently root-to-leaves and leaves-to-root.
    • The check-only version is the simpler bottom-up recursion below; the sum comparison and structural recursion don't depend on each other's result, so there's no ordering subtlety here.
    • O(n) time (visits every node once), O(h) space for the recursion stack.

    Time/Space: O(n) time, O(h) space.

    public boolean isChildrenSumProperty(TreeNode node) {
 if (node == null || (node.left == null && node.right == null)) return true;
 int childSum = (node.left != null ? node.left.val : 0) + (node.right != null ? node.right.val : 0);
 return node.val == childSum
 && isChildrenSumProperty(node.left)
 && isChildrenSumProperty(node.right);
}

    16. Zigzag Level Order Traversal

    Problem. Given a binary tree, return its zigzag level order traversal (left-to-right for one level, right-to-left for the next, alternating).

    Input: tree = [3,9,20,null,null,15,7]

    Output: [[3],[20,9],[15,7]]

    Approach: BFS with Level-Size Snapshot + Direction Flip

    • Run the same level-by-level BFS as Level Order Traversal, snapshotting the queue size before draining each level.
    • Track a "left-to-right" boolean that flips after every level; when it's false, write the level's collected values into the output in reverse order.
    • The queue itself always enqueues children in normal left-then-right order regardless of direction - only the order values are read into the output list changes, not the BFS mechanics.
    • O(n) time, O(n) space for the queue and output.

    Time/Space: O(n) time, O(n) space.

    public List<List<Integer>> zigzagLevelOrder(TreeNode root) {
 List<List<Integer>> result = new ArrayList<>();
 if (root == null) return result;
 Queue<TreeNode> q = new LinkedList<>();
 q.add(root);
 boolean leftToRight = true;
 while (!q.isEmpty()) {
 int levelSize = q.size();
 Integer[] level = new Integer[levelSize];
 for (int i = 0; i < levelSize; i++) {
 TreeNode node = q.poll();
 int idx = leftToRight ? i : (levelSize - 1 - i);
 level[idx] = node.val;
 if (node.left != null) q.add(node.left);
 if (node.right != null) q.add(node.right);
 }
 result.add(Arrays.asList(level));
 leftToRight = !leftToRight;
 }
 return result;
}

    17. Boundary Traversal

    Problem. Given a binary tree, return its boundary traversal: the root, followed by the left boundary (excluding leaves), followed by all leaf nodes left-to-right, followed by the right boundary (excluding leaves, bottom-up) - each node appearing only once.

    Input: tree = [1,2,3,4,5,6,7,null,null,8,9] (2.left=4, 2.right=5, 3.left=6, 3.right=7, 5.left=8, 5.right=9)

    Output: [1,2,4,8,9,6,7,3]

    Approach: Three-Piece Boundary Decomposition

    • Split the work into three independent pieces rather than one clever single traversal: (1) the left boundary - walk down from root.left, at each step preferring the left child if it exists else the right child, and skip adding any node that turns out to be a leaf; (2) all leaves - a simple traversal collecting every node with no children; (3) the right boundary - the mirror of the left boundary from root.right (prefer right then left), also skipping leaves, then reversed since it must be added bottom-up.
    • The root itself is added once upfront (if it isn't itself a leaf), and leaves are added only in the dedicated leaf pass - this avoids the left/right boundary walks re-adding nodes that are also leaves.
    • A single-child-only tree edge case matters: if root has no left child, the "left boundary" walk simply terminates immediately with nothing added, and symmetrically for the right.
    • O(n) time (the leaf-collection pass visits every node; boundary walks are O(h) each), O(n) space for the output and recursion.

    Time/Space: O(n) time, O(n) space.

    private boolean isLeaf(TreeNode node) {
 return node.left == null && node.right == null;
}

private void addLeftBoundary(TreeNode node, List<Integer> result) {
 TreeNode cur = node;
 while (cur != null) {
 if (!isLeaf(cur)) result.add(cur.val);
 cur = cur.left != null ? cur.left : cur.right;
 }
}

private void addLeaves(TreeNode node, List<Integer> result) {
 if (node == null) return;
 if (isLeaf(node)) {
 result.add(node.val);
 return;
 }
 addLeaves(node.left, result);
 addLeaves(node.right, result);
}

private void addRightBoundary(TreeNode node, List<Integer> result) {
 TreeNode cur = node;
 List<Integer> temp = new ArrayList<>();
 while (cur != null) {
 if (!isLeaf(cur)) temp.add(cur.val);
 cur = cur.right != null ? cur.right : cur.left;
 }
 for (int i = temp.size() - 1; i >= 0; i--) result.add(temp.get(i));
}

public List<Integer> boundaryTraversal(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 if (root == null) return result;
 if (!isLeaf(root)) result.add(root.val);
 addLeftBoundary(root.left, result);
 addLeaves(root, result);
 addRightBoundary(root.right, result);
 return result;
}

    18. Vertical Order Traversal

    Problem. Given a binary tree, return its vertical order traversal: nodes grouped by horizontal distance from the root, ordered left-to-right by column, then top-to-bottom by depth within a column, with ties at the same position broken by value.

    Input: tree = [3,9,20,null,null,15,7]

    Output: [[9],[3,15],[20],[7]]

    Approach: BFS Column/Row Coordinates + Grouped Sort

    • Assign each node a (column, row) coordinate during a BFS: the root is (0, 0), a left child is (col - 1, row + 1), and a right child is (col + 1, row + 1).
    • Group nodes into a map keyed by column, and within each column's row-keyed sub-structure, collect all values landing at the same (column, row); ties (multiple nodes at the exact same coordinate) must be sorted by value, since traversal order alone doesn't disambiguate them.
    • After grouping, sort columns ascending, and within each column sort by row ascending (with same-row ties broken by value) to produce the final column-by-column output.
    • O(n log n) time (dominated by sorting within columns for tie-breaking), O(n) space for the coordinate map and output.

    Time/Space: O(n log n) time, O(n) space.

    public List<List<Integer>> verticalTraversal(TreeNode root) {
 TreeMap<Integer, TreeMap<Integer, List<Integer>>> columns = new TreeMap<>();
 Queue<Object[]> q = new LinkedList<>();
 q.add(new Object[]{root, 0, 0});
 while (!q.isEmpty()) {
 Object[] cur = q.poll();
 TreeNode node = (TreeNode) cur[0];
 int col = (int) cur[1], row = (int) cur[2];
 columns.computeIfAbsent(col, k -> new TreeMap<>())
 .computeIfAbsent(row, k -> new ArrayList<>())
 .add(node.val);
 if (node.left != null) q.add(new Object[]{node.left, col - 1, row + 1});
 if (node.right != null) q.add(new Object[]{node.right, col + 1, row + 1});
 }
 List<List<Integer>> result = new ArrayList<>();
 for (TreeMap<Integer, List<Integer>> rows : columns.values()) {
 List<Integer> colValues = new ArrayList<>();
 for (List<Integer> values : rows.values()) {
 Collections.sort(values);
 colValues.addAll(values);
 }
 result.add(colValues);
 }
 return result;
}

    19. Top View of a Binary Tree

    Problem. Given a binary tree, return its top view: for each horizontal column (left-to-right), the value of the first (topmost) node encountered in that column.

    Input: tree = [1,2,3,4,5,6,7]

    Output: [4,2,1,3,7]

    Approach: BFS Column Coordinates (Keep First)

    • Reuse the same (column, row) BFS coordinate assignment as Vertical Order Traversal, but process nodes level-by-level (BFS naturally visits shallower rows before deeper ones).
    • For each column, keep only the value of the first node BFS ever reaches - a node deeper in the same column is hidden behind the one already recorded, so once a column has a recorded value, skip recording it again.
    • Because BFS processes nodes level-by-level, the very first node landing in a given column is guaranteed to have the smallest row, which is exactly the "topmost" one for that column.
    • O(n log n) time (a sorted map keyed by column outputs columns left-to-right), O(n) space.

    Time/Space: O(n log n) time, O(n) space.

    public List<Integer> topView(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 if (root == null) return result;
 TreeMap<Integer, Integer> columnToVal = new TreeMap<>();
 Queue<Object[]> q = new LinkedList<>();
 q.add(new Object[]{root, 0});
 while (!q.isEmpty()) {
 Object[] cur = q.poll();
 TreeNode node = (TreeNode) cur[0];
 int col = (int) cur[1];
 columnToVal.putIfAbsent(col, node.val);
 if (node.left != null) q.add(new Object[]{node.left, col - 1});
 if (node.right != null) q.add(new Object[]{node.right, col + 1});
 }
 result.addAll(columnToVal.values());
 return result;
}

    20. Bottom View of a Binary Tree

    Problem. Given a binary tree, return its bottom view: for each horizontal column (left-to-right), the value of the last (bottommost) node encountered in that column.

    Input: tree = [1,2,3,4,5,6,7]

    Output: [4,2,6,3,7]

    Approach: BFS Column Coordinates (Keep Last)

    • Reuse the same (column) BFS coordinate assignment as Top View, but instead of keeping only the first value recorded per column, always overwrite the column's value with the most recently seen node.
    • Because BFS processes level-by-level, later overwrites always come from equal-or-deeper rows, so whatever value survives after the full traversal is the deepest (bottommost) node in that column - ties at the same depth resolve to whichever was enqueued later (rightmost sibling, the standard bottom-view convention).
    • O(n log n) time (sorted map keyed by column for left-to-right output), O(n) space.

    Time/Space: O(n log n) time, O(n) space.

    public List<Integer> bottomView(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 if (root == null) return result;
 TreeMap<Integer, Integer> columnToVal = new TreeMap<>();
 Queue<Object[]> q = new LinkedList<>();
 q.add(new Object[]{root, 0});
 while (!q.isEmpty()) {
 Object[] cur = q.poll();
 TreeNode node = (TreeNode) cur[0];
 int col = (int) cur[1];
 columnToVal.put(col, node.val);
 if (node.left != null) q.add(new Object[]{node.left, col - 1});
 if (node.right != null) q.add(new Object[]{node.right, col + 1});
 }
 result.addAll(columnToVal.values());
 return result;
}

    21. Right and Left Side View of a Binary Tree

    Problem. Given a binary tree, return its right side view (the last node visible at each depth level when looking from the right; left view is the mirror, taking the first node per level from the left).

    Input: tree = [1,2,3,null,5,null,4]

    Output: right view = [1,3,4]

    Approach: DFS Reversed-Child-Order (First Arrival Per Depth)

    • Run a DFS that visits the right child before the left child at each node, passing the current depth down; the first time a given depth is reached, the node encountered is the rightmost visible node at that depth (for left view, visit left before right instead).
    • Track the result using the output list's current size as a "depths seen" counter: only record a node's value the first time its depth is reached, since DFS with right-first visits the truly rightmost node at each depth before any node further left at that same depth.
    • A BFS level-order approach also works (take the last element of each level for right view, the first for left view), but DFS with right-first order avoids materializing full levels.
    • O(n) time (visits every node once), O(h) space for the recursion stack (plus O(h) for the output, one entry per depth).

    Time/Space: O(n) time, O(h) space.

    private void rightViewHelper(TreeNode node, int depth, List<Integer> result) {
 if (node == null) return;
 if (depth == result.size()) result.add(node.val);
 rightViewHelper(node.right, depth + 1, result);
 rightViewHelper(node.left, depth + 1, result);
}

public List<Integer> rightSideView(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 rightViewHelper(root, 0, result);
 return result;
}

    22. Maximum Width of a Binary Tree

    Problem. Given a binary tree, find its maximum width - the maximum number of nodes between the leftmost and rightmost non-null nodes at any level, counting the null positions in between as if the tree were a complete binary tree.

    Input: tree = [1,3,2,5,3,null,9]

    Output: 4 (level 2 has nodes 5,3,null,9 at positions 0,1,2,3 - width 4)

    Approach: BFS with Re-Based Complete-Tree Indices

    • Assign each node an index as if the tree were a complete binary tree: the root gets index 0, and a node at index i has left child at 2i + 1 and right child at 2i + 2 - the width of a level is (last index - first index + 1) among the nodes actually present at that level.
    • These indices overflow 64-bit integers quickly for deep skewed trees, so at the start of each BFS level, re-base indices by subtracting the level's first index from every node's index before assigning children - this keeps indices small while preserving the relative spacing needed for the width calculation.
    • Process the tree level-by-level (BFS), tracking (node, index) pairs; the level's width is the difference between the last and first normalized index processed in that level plus 1, and the answer is the maximum width seen across all levels.
    • O(n) time (BFS visits every node once), O(n) space for the queue in the worst case (a fully filled last level).

    Time/Space: O(n) time, O(n) space.

    public int widthOfBinaryTree(TreeNode root) {
 if (root == null) return 0;
 int maxWidth = 0;
 Queue<Object[]> q = new LinkedList<>();
 q.add(new Object[]{root, 0L});
 while (!q.isEmpty()) {
 int levelSize = q.size();
 long firstIndex = (long) q.peek()[1];
 long lastNormalized = 0;
 for (int i = 0; i < levelSize; i++) {
 Object[] cur = q.poll();
 TreeNode node = (TreeNode) cur[0];
 long index = (long) cur[1];
 long normalized = index - firstIndex;
 lastNormalized = normalized;
 if (node.left != null) q.add(new Object[]{node.left, normalized * 2 + 1});
 if (node.right != null) q.add(new Object[]{node.right, normalized * 2 + 2});
 }
 maxWidth = Math.max(maxWidth, (int)(lastNormalized + 1));
 }
 return maxWidth;
}

    23. Nodes at Distance K

    Problem. Given a binary tree, a target node, and an integer K, return the values of all nodes exactly K edges away from the target - in any direction (up through ancestors, down through descendants, or sideways via a shared ancestor).

    Input: tree = [3,5,1,6,2,0,8,null,null,7,4], target = 5, k = 2

    Output: [7,4,1] (nodes at distance 2 from node 5)

    Approach: Parent Map + BFS (Fixed Distance)

    • A binary tree has no parent pointers, so first do one DFS pass from the root building a child -> parent map for every node - this turns the tree into an undirected graph where "distance" can be measured with a normal BFS.
    • Starting a BFS from the target node, treat its left child, right child, and parent (via the map) all as equally valid neighbors, moving outward one edge at a time and marking nodes visited to avoid re-entering the subtree just came from.
    • After exactly K BFS layers, every node still in the frontier is at distance K - collect that layer's values instead of continuing to expand further.
    • O(n) time (one DFS to build the parent map, one BFS bounded by n nodes), O(n) space for the parent map and visited set.

    Time/Space: O(n) time, O(n) space.

    private void mapParents(TreeNode node, TreeNode parent, Map<TreeNode, TreeNode> parentMap) {
 if (node == null) return;
 parentMap.put(node, parent);
 mapParents(node.left, node, parentMap);
 mapParents(node.right, node, parentMap);
}

public List<Integer> distanceK(TreeNode root, TreeNode target, int k) {
 Map<TreeNode, TreeNode> parentMap = new HashMap<>();
 mapParents(root, null, parentMap);
 Set<TreeNode> visited = new HashSet<>();
 Queue<TreeNode> q = new LinkedList<>();
 q.add(target);
 visited.add(target);
 int depth = 0;
 while (!q.isEmpty() && depth < k) {
 int size = q.size();
 for (int i = 0; i < size; i++) {
 TreeNode node = q.poll();
 for (TreeNode neighbor : new TreeNode[]{node.left, node.right, parentMap.get(node)}) {
 if (neighbor != null && !visited.contains(neighbor)) {
 visited.add(neighbor);
 q.add(neighbor);
 }
 }
 }
 depth++;
 }
 List<Integer> result = new ArrayList<>();
 for (TreeNode node : q) result.add(node.val);
 return result;
}

    24. Time to Burn a Binary Tree

    Problem. Given a binary tree and a target node value, fire spreads from that node to adjacent nodes (parent, left child, right child) one edge per minute; find the total number of minutes needed for the fire to reach every node in the tree.

    Input: tree = [1,5,3,null,4,10,6,9,2], start = 3

    Output: 4

    Approach: Parent Map + BFS (Run to Exhaustion)

    • This reduces to two subproblems already solved elsewhere: build a child -> parent map via one DFS pass (same technique as Nodes at Distance K), then locate the target node itself.
    • Run a BFS from the target node exactly as in Nodes at Distance K, treating left child, right child, and parent as neighbors, but instead of stopping at a fixed K, keep expanding layer by layer until the BFS queue is naturally exhausted.
    • The answer is the number of BFS layers needed to visit every node in the tree, since the starting layer (the target itself) counts as minute 0 and each subsequent layer is one more minute.
    • O(n) time (one DFS for the parent map, one BFS bounded by n nodes), O(n) space for the parent map and visited set.

    Time/Space: O(n) time, O(n) space.

    private void mapParents(TreeNode node, TreeNode parent, Map<TreeNode, TreeNode> parentMap) {
 if (node == null) return;
 parentMap.put(node, parent);
 mapParents(node.left, node, parentMap);
 mapParents(node.right, node, parentMap);
}

private TreeNode findTarget(TreeNode node, int start) {
 if (node == null) return null;
 if (node.val == start) return node;
 TreeNode left = findTarget(node.left, start);
 if (left != null) return left;
 return findTarget(node.right, start);
}

public int amountOfTime(TreeNode root, int start) {
 Map<TreeNode, TreeNode> parentMap = new HashMap<>();
 mapParents(root, null, parentMap);
 TreeNode target = findTarget(root, start);
 Set<TreeNode> visited = new HashSet<>();
 Queue<TreeNode> q = new LinkedList<>();
 q.add(target);
 visited.add(target);
 int minutes = -1;
 while (!q.isEmpty()) {
 int size = q.size();
 for (int i = 0; i < size; i++) {
 TreeNode node = q.poll();
 for (TreeNode neighbor : new TreeNode[]{node.left, node.right, parentMap.get(node)}) {
 if (neighbor != null && !visited.contains(neighbor)) {
 visited.add(neighbor);
 q.add(neighbor);
 }
 }
 }
 minutes++;
 }
 return minutes;
}

    25. Count Total Nodes in a Complete Binary Tree

    Problem. Given a complete binary tree, count its total number of nodes faster than the trivial O(n) linear traversal.

    Input: tree = [1,2,3,4,5,6]

    Output: 6

    Approach: Perfect-Subtree Detection via Height Match

    • Exploit the "complete" guarantee: in a complete binary tree, a subtree rooted at any node is a perfect binary tree (all levels fully filled) whenever the leftmost-path height and rightmost-path height from that node are equal - a perfect tree's size is computable directly as 2^height - 1, with no need to visit its nodes.
    • The algorithm recursively checks this equal-height condition at each node: if the left height equals the right height, return 2^height - 1 immediately; otherwise, recurse into both children and return 1 + leftCount + rightCount, since a mismatch means the tree is complete but not perfect and at least one side must be explored further.
    • Because a complete tree can be at most one node away from perfect, only one of the two recursive calls at each level ever needs to fully recurse into a non-perfect subtree - the other side resolves via the O(height) formula - giving a total cost of O(log^2 n) rather than O(n).
    • O(log^2 n) time (O(log n) recursive levels, each doing an O(log n) height computation), O(log n) space for the recursion stack.

    Time/Space: O(log^2 n) time, O(log n) space.

    private int leftHeight(TreeNode node) {
 int height = 0;
 while (node != null) { height++; node = node.left; }
 return height;
}

private int rightHeight(TreeNode node) {
 int height = 0;
 while (node != null) { height++; node = node.right; }
 return height;
}

public int countNodes(TreeNode root) {
 if (root == null) return 0;
 int lh = leftHeight(root);
 int rh = rightHeight(root);
 if (lh == rh) return (1 << lh) - 1;
 return 1 + countNodes(root.left) + countNodes(root.right);
}

    26. Flatten a Binary Tree to a Linked List

    Problem. Given a binary tree, flatten it in place into a "linked list" that follows the same order as preorder traversal - each node's left pointer becomes null and its right pointer points to the next node in preorder order.

    Input: tree = [1,2,5,3,4,null,6]

    Output: [1,null,2,null,3,null,4,null,5,null,6] (flattened preorder chain via right pointers)

    Approach: Reverse Preorder with Trailing Pointer

    • Process nodes in reverse preorder (right subtree, then left subtree, then the node itself) while tracking a "previously processed" node; at each node, set its right pointer to the previously processed node and its left pointer to null, then update "previously processed" to the current node before returning up - this naturally builds the flattened list from the tail backward.
    • This reverse-preorder-with-a-trailing-pointer pattern requires only O(h) recursion space, but an O(1)-space iterative variant exists using the same Morris-style threading as Morris Traversal: for each node with a left child, find the left subtree's rightmost node (its predecessor in the eventual flattened order), thread that predecessor's right pointer to the current node's original right subtree, then move the entire left subtree up to be the right subtree and clear left - repeating this at the current node (not descending yet) until it has no left child, then advancing to the next node via its right pointer.
    • Both variants produce the identical final structure (a right-only chain in preorder order); the Morris-style version is the one to reach for when true O(1) space is required, otherwise the reverse-preorder recursion is simpler to write correctly.
    • O(n) time either way, O(h) space for the recursive reverse-preorder version vs. O(1) space for the Morris-style iterative version.

    Time/Space: O(n) time, O(h) space.

    private TreeNode prev = null;

public void flatten(TreeNode root) {
 if (root == null) return;
 flatten(root.right);
 flatten(root.left);
 root.right = prev;
 root.left = null;
 prev = root;
}

    27. Sufficiency of Traversal Pairs

    Problem. Given two of the three classic traversal orders (preorder, inorder, postorder) for a binary tree, determine which pairs are sufficient to reconstruct a unique binary tree, and why.

    Input: n/a (conceptual)

    Output: {inorder+preorder}: unique; {inorder+postorder}: unique; {preorder+postorder}: not unique in general

    Approach: Traversal-Pair Sufficiency (Theory)

    • Inorder + preorder uniquely determines the tree: preorder gives the root first, and inorder (which splits into left-subtree-values, root, right-subtree-values around that root) tells you exactly which values belong to the left vs. right subtree - recursing with this split rebuilds the tree unambiguously.
    • Inorder + postorder is equally sufficient by the mirror argument: postorder gives the root last, and the same inorder split around that root separates left from right.
    • Preorder + postorder alone is not sufficient in general - knowing only root-first and root-last orders can't distinguish, for example, "a node with only a left child" from "a node with only a right child," since without inorder there's no split point that tells you which side a given subtree's values belong to.
    • This is a theory/decision question, not an algorithm to run - but it's the reasoning that justifies why the two Construct Binary Tree problems in this section both pair inorder with one other traversal, and why no such problem is posed for preorder+postorder alone.

    Conceptual - no implementation.

    Time/Space: N/A

    28. Construct a Binary Tree from Preorder and Inorder

    Problem. Given the inorder and preorder traversal arrays of a binary tree (with unique values), reconstruct and return the original binary tree.

    Input: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]

    Output: tree = [3,9,20,null,null,15,7]

    Approach: Shared Preorder Pointer + Inorder Index Map

    • Preorder's first remaining element is always the current subtree's root; find that value's position in inorder - everything to its left in inorder is the left subtree's values, everything to its right is the right subtree's.
    • Build a value -> index map over inorder upfront so the root's split point is found in O(1) instead of an O(n) linear scan per call, which is what keeps the whole algorithm at O(n) instead of O(n^2).
    • Maintain a single shared preorder index that only ever advances (never resets or is passed by value across calls) - build the left subtree completely before the right subtree, since preorder visits root, then entirely the left subtree, then entirely the right subtree, so the "next" preorder element is only correct if the left side has fully consumed its share first.
    • O(n) time (one map lookup and O(1) work per node), O(n) space for the index map and recursion stack.

    Time/Space: O(n) time, O(n) space.

    private int preIndex;

public TreeNode buildTree(int[] preorder, int[] inorder) {
 Map<Integer,Integer> inIndex = new HashMap<>();
 for (int i = 0; i < inorder.length; i++) inIndex.put(inorder[i], i);
 preIndex = 0;
 return build(preorder, 0, inorder.length - 1, inIndex);
}

private TreeNode build(int[] preorder, int inStart, int inEnd, Map<Integer,Integer> inIndex) {
 if (inStart > inEnd) return null;
 int rootVal = preorder[preIndex++];
 TreeNode root = new TreeNode(rootVal);
 int mid = inIndex.get(rootVal);
 root.left = build(preorder, inStart, mid - 1, inIndex);
 root.right = build(preorder, mid + 1, inEnd, inIndex);
 return root;
}

    29. Construct a Binary Tree from Inorder and Postorder

    Problem. Given the inorder and postorder traversal arrays of a binary tree (with unique values), reconstruct and return the original binary tree.

    Input: inorder = [9,3,15,20,7], postorder = [9,15,7,20,3]

    Output: tree = [3,9,20,null,null,15,7]

    Approach: Shared Postorder Pointer + Inorder Index Map

    • Postorder's last remaining element is always the current subtree's root (the mirror of preorder's first-element rule); find that value's position in inorder to split left-subtree values from right-subtree values exactly as in the preorder version.
    • Maintain a single shared postorder index that only ever decreases from the end, and - critically - build the right subtree before the left subtree, since postorder visits left, then right, then root, so reading backwards from the end encounters root, then right's nodes, then left's nodes.
    • Build the same value -> index map over inorder upfront for O(1) root-split lookups, keeping the whole algorithm O(n).
    • O(n) time (one map lookup and O(1) work per node), O(n) space for the index map and recursion stack.

    Time/Space: O(n) time, O(n) space.

    private int postIndex;

public TreeNode buildTree(int[] inorder, int[] postorder) {
 Map<Integer,Integer> inIndex = new HashMap<>();
 for (int i = 0; i < inorder.length; i++) inIndex.put(inorder[i], i);
 postIndex = postorder.length - 1;
 return build(postorder, 0, inorder.length - 1, inIndex);
}

private TreeNode build(int[] postorder, int inStart, int inEnd, Map<Integer,Integer> inIndex) {
 if (inStart > inEnd) return null;
 int rootVal = postorder[postIndex--];
 TreeNode root = new TreeNode(rootVal);
 int mid = inIndex.get(rootVal);
 root.right = build(postorder, mid + 1, inEnd, inIndex);
 root.left = build(postorder, inStart, mid - 1, inIndex);
 return root;
}

    30. Serialize and Deserialize a Binary Tree

    Problem. Design an algorithm to serialize a binary tree into a string and deserialize that string back into an identical binary tree structure.

    Input: tree = [1,2,3,null,null,4,5]

    Output: serialized = "1,2,#,#,3,4,#,#,5,#,#" (one valid preorder-with-nulls encoding); deserializing it reproduces the original tree

    Approach: Preorder DFS with Explicit Null Sentinels

    • Use a preorder DFS for serialization, writing each node's value followed by a delimiter, and writing an explicit sentinel token (e.g. "#") for every null child - without these null markers, a plain preorder sequence is ambiguous (it can't tell where one subtree ends and the next begins).
    • Deserialization mirrors this exactly: read tokens one at a time from the front of the stream (in preorder), building the current node from the first token and recursing into left then right - a "#" token immediately returns null for that branch without consuming any further tokens.
    • Any traversal order works as long as null markers are included, but preorder is the conventional choice because it naturally matches "build the root, then recurse into children" without needing to look ahead.
    • O(n) time for both serialize and deserialize (visits every real and null node position once), O(n) space for the output string / token queue and recursion stack.

    Time/Space: O(n) time, O(n) space.

    public String serialize(TreeNode root) {
 if (root == null) return "#,";
 return root.val + "," + serialize(root.left) + serialize(root.right);
}

private TreeNode deserializeHelper(Deque<String> tokens) {
 String token = tokens.poll();
 if (token.equals("#")) return null;
 TreeNode node = new TreeNode(Integer.parseInt(token));
 node.left = deserializeHelper(tokens);
 node.right = deserializeHelper(tokens);
 return node;
}

public TreeNode deserialize(String data) {
 Deque<String> tokens = new ArrayDeque<>(Arrays.asList(data.split(",")));
 return deserializeHelper(tokens);
}

    31. Morris Inorder Traversal

    Problem. Given a binary tree, return its inorder traversal using O(1) extra space (no recursion stack, no explicit stack).

    Input: tree = [1,null,2,3]

    Output: [1,3,2]

    Approach: Morris Threading via Predecessor Linking

    • For a node with a left subtree, find that subtree's inorder predecessor (its rightmost node) and temporarily thread a link from the predecessor back to the current node - this "borrowed" pointer lets the traversal return to the current node later without a stack, since the predecessor's right child would otherwise be null anyway.
    • At each step: if the current node has no left child, visit it and move right; otherwise, walk to the predecessor - if the predecessor's right pointer is null, create the thread (point it at current) and move left (visit is deferred); if the predecessor's right pointer already points back to current, the left subtree has been fully processed, so remove the thread (restore null), visit the current node now, and move right.
    • Removing the thread immediately after using it is essential - leaving it in place would permanently corrupt the tree's structure, since detecting "already threaded" (the second condition) is also how the algorithm knows a subtree has finished and it's safe to visit the current node and advance.
    • O(n) time (each edge is traversed at most twice - once to create the thread, once to detect and remove it), O(1) space - no recursion stack or explicit stack.

    Time/Space: O(n) time, O(1) space.

    public List<Integer> morrisInorder(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 TreeNode current = root;
 while (current != null) {
 if (current.left == null) {
 result.add(current.val);
 current = current.right;
 } else {
 TreeNode predecessor = current.left;
 while (predecessor.right != null && predecessor.right != current) {
 predecessor = predecessor.right;
 }
 if (predecessor.right == null) {
 predecessor.right = current;
 current = current.left;
 } else {
 predecessor.right = null;
 result.add(current.val);
 current = current.right;
 }
 }
 }
 return result;
}

    32. Morris Preorder Traversal

    Problem. Given a binary tree, return its preorder traversal using O(1) extra space (no recursion stack, no explicit stack).

    Input: tree = [1,null,2,3]

    Output: [1,2,3]

    Approach: Morris Threading (Visit on Thread Creation)

    • Reuse the exact same threading mechanism as Morris Inorder Traversal (find the left subtree's rightmost predecessor and thread it back to the current node) - the only change is when the current node's value is recorded.
    • In inorder, the visit happens after the left subtree finishes (on the second encounter, when the thread is detected and removed); in preorder, the visit must happen before descending into the left subtree - so record the value at thread-creation time (the first encounter, right before moving left), not at thread-removal time.
    • Everything else is identical: no left child -> visit and move right; thread already exists (predecessor->right == current) -> remove it and move right without visiting again (already visited on creation).
    • O(n) time (each edge traversed at most twice), O(1) space.

    Time/Space: O(n) time, O(1) space.

    public List<Integer> morrisPreorder(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 TreeNode current = root;
 while (current != null) {
 if (current.left == null) {
 result.add(current.val);
 current = current.right;
 } else {
 TreeNode predecessor = current.left;
 while (predecessor.right != null && predecessor.right != current) {
 predecessor = predecessor.right;
 }
 if (predecessor.right == null) {
 result.add(current.val);
 predecessor.right = current;
 current = current.left;
 } else {
 predecessor.right = null;
 current = current.right;
 }
 }
 }
 return result;
}

    33. Iterative Preorder Traversal

    Problem. Given a binary tree, return its preorder traversal using an explicit stack instead of recursion.

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [1,2,4,3]

    Approach: Iterative Stack (Push Right Before Left)

    • Push the root onto a stack; repeatedly pop a node, visit it, then push its right child before its left child - pushing right first ensures left is popped (and thus visited) next, preserving the root-left-right order.
    • Unlike inorder/postorder, preorder's "visit node immediately" rule means no extra state is needed per stack entry - a plain node stack suffices.
    • O(n) time, O(h) space for the stack (O(n) worst case for a skewed tree) - same asymptotic bounds as the recursive version, but with the implicit call stack made explicit.

    Time/Space: O(n) time, O(h) space.

    public List<Integer> preorderIterative(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 if (root == null) return result;
 Deque<TreeNode> stack = new ArrayDeque<>();
 stack.push(root);
 while (!stack.isEmpty()) {
 TreeNode node = stack.pop();
 result.add(node.val);
 if (node.right != null) stack.push(node.right);
 if (node.left != null) stack.push(node.left);
 }
 return result;
}

    34. Iterative Inorder Traversal

    Problem. Given a binary tree, return its inorder traversal using an explicit stack instead of recursion.

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [4,2,1,3]

    Approach: Iterative Stack (Left-Spine Descent)

    • Maintain a stack and a "current" pointer starting at the root; repeatedly push current and move to its left child until current becomes null - this walks all the way down the leftmost spine.
    • Once current is null, pop a node from the stack, visit it, then set current to that node's right child - this resumes descending down the newly revealed right subtree's leftmost spine.
    • Repeat until both current is null and the stack is empty - this precisely mirrors the recursive "left, visit, right" order without recursion.
    • O(n) time, O(h) space for the stack.

    Time/Space: O(n) time, O(h) space.

    public List<Integer> inorderIterative(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 Deque<TreeNode> stack = new ArrayDeque<>();
 TreeNode current = root;
 while (current != null || !stack.isEmpty()) {
 while (current != null) {
 stack.push(current);
 current = current.left;
 }
 current = stack.pop();
 result.add(current.val);
 current = current.right;
 }
 return result;
}

    35. Iterative Postorder Traversal (Two Stacks)

    Problem. Given a binary tree, return its postorder traversal using two explicit stacks (instead of recursion or extra per-node state).

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [4,2,3,1]

    Approach: Two Stacks (Build Root-Right-Left, Reverse via Second Stack)

    • Push the root onto stack1; repeatedly pop a node from stack1, push it onto stack2, then push its left child followed by its right child onto stack1 - this produces a "root, right, left" order on stack1 by construction.
    • Since stack2 receives nodes in "root, right, left" order and a stack reverses order on pop, draining stack2 entirely at the end yields exactly "left, right, root" - postorder.
    • This avoids tracking any "have I visited this node's children yet" state per node, at the cost of a second stack.
    • O(n) time, O(n) space for the two stacks (both can hold up to O(n) nodes in the worst case, unlike the O(h) bound of the single-stack traversals).

    Time/Space: O(n) time, O(n) space.

    public List<Integer> postorderTwoStacks(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 if (root == null) return result;
 Deque<TreeNode> stack1 = new ArrayDeque<>();
 Deque<TreeNode> stack2 = new ArrayDeque<>();
 stack1.push(root);
 while (!stack1.isEmpty()) {
 TreeNode node = stack1.pop();
 stack2.push(node);
 if (node.left != null) stack1.push(node.left);
 if (node.right != null) stack1.push(node.right);
 }
 while (!stack2.isEmpty()) {
 result.add(stack2.pop().val);
 }
 return result;
}

    36. Iterative Postorder Traversal (One Stack)

    Problem. Given a binary tree, return its postorder traversal using a single explicit stack (no second stack, no recursion).

    Input: tree = [1,2,3,4] (root=1, left=2, right=3, 2.left=4)

    Output: [4,2,3,1]

    Approach: One Stack (Left-Spine Descent + Last-Visited Check)

    • Maintain one stack, a "current" pointer, and a "last visited node" pointer; current first descends all the way down the left spine, pushing each node onto the stack, just like iterative inorder.
    • At each point where current is null, peek (don't pop) the stack's top; if it has an unvisited right child (right child exists and wasn't the last node visited), move current to that right child and repeat the left-spine descent from there.
    • Otherwise, the node's children are both fully processed, so pop it, visit it, and update "last visited" to that node - postorder's core invariant is that a node is only visited after confirming both its children (if any) have already been visited.
    • O(n) time, O(h) space for the stack - matching the recursive version's space bound, unlike the two-stack version's O(n).

    Time/Space: O(n) time, O(h) space.

    public List<Integer> postorderOneStack(TreeNode root) {
 List<Integer> result = new ArrayList<>();
 Deque<TreeNode> stack = new ArrayDeque<>();
 TreeNode current = root;
 TreeNode lastVisited = null;
 while (current != null || !stack.isEmpty()) {
 if (current != null) {
 stack.push(current);
 current = current.left;
 } else {
 TreeNode peekNode = stack.peek();
 if (peekNode.right != null && lastVisited != peekNode.right) {
 current = peekNode.right;
 } else {
 result.add(peekNode.val);
 lastVisited = stack.pop();
 }
 }
 }
 return result;
}
