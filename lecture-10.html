    Part 2 · Arrays & OOP Core · Lecture 10

    How Arrays Work in Java — Heap, Contiguous Storage & Random Access

    17 sections · interview-oriented · both themes

    Scope evidence: "How Arrays work in Java | Heap, Contiguous Storage, Random Access" (playlist map, verified). Repo evidence: notes.pdf only.

    An array is the first data structure every Java programmer meets, and it is also the one whose speed is easiest to explain once you see how it is stored. The Java Language Specification classifies arrays as objects, so an array lives on the heap while the variable that names it is only a reference. Because the elements of a single array sit back-to-back in one contiguous block, the address of any element can be computed arithmetically, which is the reason array access is O(1) and random. This note follows an array from allocation to garbage collection and contrasts its contiguous design with the linked structures covered later in the course.

    1. Arrays Are Objects: Stack Reference, Heap Storage

    An array is a container object that holds a fixed number of values, all of a single type. Two things are created when you write int[] numbers = new int[3];:

    1. An array object on the heap, holding three int slots and an object header.
    2. A reference variable named numbers. When it is a local variable it lives on the stack; its value is the address of the heap array.

    The reference and the object are different things. Copying the reference does not copy the array — both names then point at the same object, which is the root of many aliasing bugs.

    // ArrayHeapDemo.java — the reference is local, the array is on the heap
int[] numbers = new int[3];   // stack: numbers -- reference --> heap: array object
numbers[0] = 10;
numbers[1] = 20;
numbers[2] = 30;
int[] alias = numbers;        // second reference to the SAME array object
alias[1] = 99;
System.out.println(numbers[1]);   // 99 — one array, two names
System.out.println(numbers.length);   // 3

    Important Arrays are objects even when they hold primitives. The full stack/heap model is the subject of Lecture 45; here it is enough to know that the name is on the stack and the contents are on the heap.

    Memory aid: the name is the address, the array is the house.

    2. The Object Header and length — Why It Is O(1)

    Every heap object begins with an object header. For an array, that header includes the array's length, fixed at creation and never changed. This is why array.length costs one field read no matter how large the array is: the JVM does not walk the elements to count them.

    Read the syntax carefully:

    • array.length is a field, so there are no parentheses.
    • string.length() is a method, so it has parentheses.

    array.length() is a compile-time error, not a runtime one.

    Interviewer's perspective "Why is array.length O(1)?" Because the length is stored in the array object's header at allocation time. It is a single load, unlike String.length(), which computes from an internal count. Fixed length is also why arrays never grow: a "resize" creates a new array and copies the elements.

    3. Contiguous Storage and the Random-Access Formula

    The elements of a single array are stored in one contiguous block: element 0, then element 1, and so on with no gaps. Because every element has the same size, the address of element i needs no searching:

    element address = base address + i * element size

    For an int[], the element size is the width of an int; for a reference array, it is the width of a reference. The JVM computes one multiplication and one addition, then loads the value. That is why access by index is O(1) and why we call it random access — any element is reachable in the same constant time.

    Contrast a linked structure, where reaching element i requires following i links from the head, so access is O(n) (forward-ref Lecture 32, LinkedList). The array trades the flexibility of growth for the speed of arithmetic.

    Important Contiguity is what makes the formula legal. Break contiguity and index arithmetic fails; that single fact drives the next two sections.

    4. Homogeneity: Why One Element Type Matters

    An array must be homogeneous — all elements share one type. This is not a stylistic rule but a requirement of the address formula. If element widths varied, base + i * size could not locate element i, because size would be unknown. One uniform element size is what turns lookup into arithmetic instead of a scan.

    Consequences worth noting:

    1. int[] stores only int; String[] stores only String (or its subtypes, via polymorphism).
    2. An Object[] can hold references of many runtime types, but every slot still holds a reference of the same width — homogeneity of storage size is preserved even when runtime types differ.
    3. A primitive array and a reference array have the same geometry, only different element widths.

    Memory aid: same type, same size, one multiplication away.

    5. Bounds Checking: Safety at Runtime

    A valid index for an array of length n is any integer in the range 0 <= index < n. On every element access, the JVM checks the index against the stored length. If the index is negative or at least n, the JVM throws ArrayIndexOutOfBoundsException instead of reading or writing memory that does not belong to the array.

    // BoundsDemo.java — the JVM checks every index at runtime
int[] a = new int[3];              // valid indices: 0, 1, 2
try {
    int bad = a[3];                // one past the end
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("caught: " + e.getMessage());   // prints the index, 3
}

    This is a deliberate safety feature. In C, an out-of-bounds access is undefined behaviour that may silently corrupt memory. Java pays the small cost of a check and converts a memory-safety hazard into a predictable exception.

    Interviewer's perspective "Does Java check array bounds?" Yes, on every access, and that check is the reason you never get a wild pointer from an array. The same check underpins ArrayList, whose get delegates to the backing array.

    6. The Cost of Operations: A Complexity Table

    Because layout is fixed and contiguous, each operation has a characteristic cost. This table is the practical payoff of everything above.

    Operation Typical cost Why
    Access by index a[i] O(1) base address + index × element size
    Update by index a[i] = x O(1) same arithmetic, one store
    Search, unsorted O(n) must scan each element
    Search, sorted O(log n) binary search over the ordered block
    Insert at an index O(n) every later element shifts right
    Delete at an index O(n) every later element shifts left
    Iterate all elements O(n) one visit per element

    The asymmetry is the lesson: the array is fast to reach and slow to restructure. Insertion and deletion are O(n) because the contiguity that gives O(1) access must be maintained by shifting. Collections that wrap arrays (for example ArrayList) hide the shifting behind methods, but the cost does not disappear (forward-ref the collections lectures).

    7. Multi-Dimensional Arrays: Arrays of Arrays

    Java has no true rectangular matrix type. An int[][] is literally an array of arrays: the outer array holds references, and each reference points to a separate inner int[] object. This makes jagged arrays (rows of different lengths) perfectly legal.

    // MatrixDemo.java — int[][] is an array of int[] references
int[][] grid = new int[2][3];                 // outer length 2, each row length 3
int[][] jagged = {{1, 2, 3}, {4, 5}, {6}};    // rows may differ in length
for (int i = 0; i < jagged.length; i++) {
    for (int j = 0; j < jagged[i].length; j++) {
        System.out.print(jagged[i][j] + " ");
    }
    System.out.println();
}

    The memory picture shows why rows are not guaranteed to be contiguous with each other:

    jagged (stack) -- reference --> outer int[][] (heap): [ref0, ref1, ref2]
                                 ref0 --> int[3]  (a separate heap object)
                                 ref1 --> int[2]  (a separate heap object)
                                 ref2 --> int[1]  (a separate heap object)

    Common mistake jagged[0].length and jagged[1].length may differ. Always use jagged[i].length in the inner loop; assuming a common width is the classic 2D bug. Only the new int[rows][cols] form creates equal-length rows.

    8. Default Initialization at Allocation

    new always zero-fills an array before it is handed to you, so no slot ever contains garbage from a previous use. The zero bit pattern is interpreted per element type:

    Element type Default value
    byte, short, int, long 0
    float, double 0.0
    char '\u0000' (the null character)
    boolean false
    Any reference type null

    Memory aid: numbers zero, flags false, characters null, references nothing. A freshly allocated String[] of length 5 holds five null references until you assign them, so touching arr[0].length() before assignment throws NullPointerException.

    9. Working with Arrays: length, Iteration, Printing

    Three everyday skills trip up beginners because the syntax is not symmetric with other types:

    1. Length — a.length, a field, never a.length().
    2. Iteration — the index loop gives you the position; the enhanced for loop gives you each value.
    3. Printing — System.out.println(a) prints the object identity, not the contents; use Arrays.toString or Arrays.deepToString.
    // PrintDemo.java — arrays do not override toString
import java.util.Arrays;
int[] a = {1, 2, 3};
System.out.println(a);                    // [I@... identity, not contents
System.out.println(Arrays.toString(a));   // [1, 2, 3]
int[][] m = {{1, 2}, {3, 4}};
System.out.println(Arrays.deepToString(m));   // [[1, 2], [3, 4]]
    Loop style Best for Limitation
    Index loop for (int i = 0; i < a.length; i++) any position-dependent work more boilerplate, manual bounds care
    Enhanced for (int v : a) reading every element in order no index, cannot remove or reposition

    The enhanced for loop over a primitive array copies each element into v; assigning v does not change the array. Assign back through a[i] when you need to write.

    10. Stack vs Heap: A Preview

    The array is the first place the split between automatic and heap memory becomes visible. Locals and their references live in the frame on the stack; every object and array lives on the heap.

    Region Holds Lifetime Examples
    Stack local variables, primitives, references ends with the method call int i, the variable int[] ref
    Heap all objects and arrays until garbage collected new int[5], new String

    Important An array's reference can be on the stack while its elements are always on the heap. Passing an array to a method copies the reference, not the array, so the method sees the caller's elements. The complete frame and heap model is covered in Lecture 45.

    11. Garbage Collection of Arrays

    An array is reclaimed like any other object: it becomes eligible for garbage collection when no reachable reference points to it. Setting the last reference to null or reassigning it away from the array is enough; the object header and its contiguous block are then freed together by the collector (forward-ref Lecture 46).

    // GcDemo.java — drop the last reference and the array becomes eligible
int[] data = new int[1_000_000];
data = null;               // no reachable reference remains
// the million-int array is now eligible for garbage collection

    Garbage collection never runs because an array is large; size affects when memory pressure triggers a collection, not whether an array is eligible.

    12. Pitfalls and Beginner Errors

    Pitfall Reality
    new int[-1] throws ArrayIndexOutOfBoundsException It throws NegativeArraySizeException at creation.
    new int[0] is illegal A zero-length array is perfectly legal and length is 0.
    a.length() Compile-time error; length is a field.
    a == b compares contents It compares references; use Arrays.equals.
    2D rows are guaranteed contiguous Rows are separate arrays; use Arrays.deepEquals for contents.
    System.out.println(a) prints contents It prints [I@...; use Arrays.toString or Arrays.deepToString.

    13. Myth vs Reality

    Myth Reality
    "An array is a primitive value, not an object." Arrays are objects on the heap; only the local reference sits on the stack.
    "array.length is a method." It is a field stored in the object header; array.length() is a compile error.
    "Arrays can grow like ArrayList." The length is fixed at creation; growth means allocating a new array and copying.
    "Java does not check array bounds, like C." The JVM checks every access and throws ArrayIndexOutOfBoundsException.
    "A 2D array is one contiguous rectangle." It is an array of references to separate row arrays, so rows may be jagged.
    "a == b is true when the arrays hold equal values." == compares references; value equality needs Arrays.equals.
    "An array is garbage collected immediately after = null." It becomes eligible; the collector reclaims it later.

    14. Common Trap Questions

    Trap 1 — "Is array.length a method call, like String.length()?" No. length is a public final field read from the object header; String.length() is a method. Writing array.length() fails to compile.

    Trap 2 — "Why is a[3] on an int[3] a runtime error but writing a.length() is a compile error?" Different checkers catch different problems. The type checker rejects a.length(); the JVM bounds check rejects a[3] at runtime, because index validity cannot be proven in general at compile time.

    Trap 3 — "new int[0] must be illegal because the array is empty." It is legal. A zero-length array occupies only its header and is a valid object; useful as an empty result instead of null.

    Trap 4 — "Comparing two arrays with == tells you whether their contents match." No. == compares the references. Two distinct arrays with identical elements are == false. Use Arrays.equals (or Arrays.deepEquals).

    Trap 5 — "In int[][] m, the rows are laid out one after another in memory, so m[0].length and m[1].length must match." Rows are independently allocated arrays reached through references; only new int[rows][cols] makes them equal in length. Jagged arrays are legal.

    Trap 6 — "Array access is O(n) because the JVM scans for the index." It is O(1): the address is computed as base + index × element size. Only searching for a value in an unsorted array is O(n).

    Trap 7 — "Inserting into the middle of an array is cheap because access is O(1)." It is O(n). Access is cheap, restructuring is not: every element after the insertion point must shift.

    15. Points to Remember

    1. Arrays are objects: the array lives on the heap, and a local array variable is a reference on the stack.
    2. The object header stores the length, so array.length is O(1); it is a field, not a method (array.length() does not compile).
    3. Elements of one array are contiguous, so address = base + index × element size, giving O(1) random access.
    4. Homogeneity — one element type and fixed element size — is what makes the index arithmetic valid.
    5. The JVM bounds-checks every access and throws ArrayIndexOutOfBoundsException; this is the safety C lacks.
    6. Access and update are O(1); unsorted search is O(n); insertion and deletion are O(n) because of shifting.
    7. int[][] is an array of arrays; rows are separate heap objects and may be jagged, so use m[i].length.
    8. new zero-fills: numeric arrays get 0/0.0, boolean[] gets false, char[] gets '\u0000', reference arrays get null.
    9. Print with Arrays.toString (1D) or Arrays.deepToString (nested); compare with Arrays.equals/Arrays.deepEquals, never ==.
    10. An array is eligible for garbage collection when no reachable reference points to it (forward-ref Lecture 46); new int[0] is legal and a negative size throws NegativeArraySizeException.

    16. Likely Interview Questions

    Question Crisp Answer
    Are arrays objects in Java? Yes. The array is a heap object; the variable is a reference (on the stack when local).
    Where does an array live in memory? The array and its contiguous elements live on the heap; the reference lives wherever it is declared.
    Why is array.length O(1)? The length is stored in the array's object header and read as a single field.
    Is length a field or a method? A field. array.length is correct; array.length() is a compile error.
    Why is array access O(1)? Elements are contiguous and equal-sized, so address = base + index × element size.
    Why must arrays be homogeneous? A fixed element size makes index arithmetic possible; mixed sizes would break it.
    What happens on an out-of-bounds access? The JVM throws ArrayIndexOutOfBoundsException; it never reads foreign memory.
    What is the cost of inserting into the middle? O(n), because later elements shift to preserve contiguity.
    Is int[][] a rectangular matrix? No. It is an array of references to separate row arrays; rows may be jagged.
    What are default array element values? Zero for numerics, false for boolean, '\u0000' for char, null for references.
    How do you print and compare arrays? Arrays.toString/deepToString; Arrays.equals/deepEquals — never println or ==.
    When is an array garbage collected? When no reachable reference points to it; then it becomes eligible (Lecture 46).

    17. Final Summary

    int[] a = new int[3]
   -- reference on the stack -->  array object on the heap
   -- object header holds length -->  a.length is a field read, O(1)
   -- contiguous, equal-size elements -->  address = base + index * size --> access O(1)
   -- fixed length -->  insert/delete O(n) shifting, unsorted search O(n)
   -- int[][] is an array of references -->  rows are separate, jagged arrays allowed
   -- no reachable reference -->  eligible for garbage collection (Lecture 46)
    • Objects → arrays live on the heap; the name is a reference, so == compares references
    • Length → stored in the header, a field, O(1), never grows
    • Contiguity → base + index × size → random access O(1), but shifting costs O(n)
    • Homogeneity → one element size is the precondition for the address formula
    • Safety → the JVM bounds-checks and throws, unlike C
    • 2D → an array of arrays, so m[i].length and jagged rows are normal

    Golden rule An array is a fixed-size, homogeneous, contiguous block behind a single reference: contiguity buys O(1) random access and charges O(n) for every change to the block.

    One-line takeaway: an array is one heap object with its length in the header and its equal-sized elements laid end-to-end, so reaching any element is arithmetic while changing the shape is labour.
