    Part 1 · Java Basics · Lecture 03

    Java Variables & Data Types — Identifiers, Literals & Keywords

    15 sections · interview-oriented · both themes

    Scope evidence: lecture title "Java Variables & Data Types Explained | Identifiers, Literals, Keywords" (playlist map, verified). Note: this lecture's repo folder contains one code file, Demo.java.

    Every value a Java program touches travels through a variable, and every variable is declared with a data type — which makes this lecture the vocabulary of the whole language. This lecture covers what a variable is, the identifier rules a name must follow, the three kinds of variables, all eight primitive types with their sizes, ranges and defaults, primitive versus reference types, how Java stores numbers, every kind of literal, the reserved keywords, and the var type inference added in Java 10. Master this lecture and casting, wrappers and objects in later lectures become trivial. These definitions also feed the ready-made demo file Demo.java, which shows variables, defaults and literals running in one program.

    1. What Is a Variable?

    A variable is a named container for a value whose type is fixed at declaration. Exactly three ingredients define one:

    1. Data type — how many bits it occupies and what operations are legal on it.
    2. Name (identifier) — the label the code uses to reach the value.
    3. Value — the current content of that storage.

    Declaration, initialization and reassignment are separate ideas:

    • Declaration — int count; reserves storage of type int under the name count.
    • Initialization — count = 10; stores the first value into it.
    • Assignment later — reusing the same variable with a new value replaces the old one.

    Reading back gives the current value, and every legal operation (+, -, comparison) is defined by the type, not the name. That is why int addition behaves differently from String concatenation even when the code looks similar.

    Important A variable's type is chosen once, at compile time, and never changes at runtime. Java is statically and strongly typed — the greatness of JIT optimization later rests on this promise.

    2. Identifiers and Naming Conventions

    An identifier is simply the name of a class, variable, method or parameter. The compiler enforces five rules:

    1. Allowed characters: letters, digits, _ and $.
    2. Must not begin with a digit (count1 is legal, 1count is not).
    3. No spaces or punctuation — total-price is illegal; totalPrice is not.
    4. Must not be a reserved keyword — int, class, null are out.
    5. Case-sensitive and effectively unlimited in length — count and Count are two different variables.

    Two conventions then make code readable — these are style, not law, but every codebase follows them:

    Naming thing Convention Examples
    Variables, methods, parameters lowerCamelCase studentName, totalMarks, getBalance()
    Classes, interfaces, enums, records UpperCamelCase (PascalCase) Student, BankAccount, OrderService
    Constants (static final) UPPER_SNAKE_CASE MAX_USERS, DEFAULT_TIMEOUT
    Packages all lowercase, dot-separated com.example.app

    Memory aid — "camel for the small things, camel with a fat hump for the big things, shouting SNAKE for the things that never change."

    3. Local, Instance and Static Variables

    Java has exactly three kinds of variables, classified by where they live and how long they live:

    Aspect Local variable Instance variable Static variable
    Declared Inside a method or block Inside a class, outside methods Inside a class with static
    Exists While the method runs As long as the object lives As long as the class is loaded
    Shared By one call only One copy per object One copy for all objects
    Default value None — must be initialized Yes (section 7) Yes (section 7)
    Belongs to The method call The object The class 
    // Demo.java — the three variable kinds in one class
public class Demo {
    static int objectsCreated = 0;      // static — one copy for the class
    int count = 10;                     // instance — every object gets its own

    public static void main(String[] args) {
        Demo d = new Demo();
        int local = 5;                  // local — lives only in this method call
        objectsCreated++;               // shared across all objects
        System.out.println(d.count + local);
    }
}

    static is previewed here only as a variable kind; the full static story is covered in Lecture 15.

    4. The Eight Primitive Data Types

    Java fixes both the type list and the size of every primitive — an int is 32 bits on every machine, which is the architecture neutrality from Lecture 1.

    Type Size Default Range Typical use
    byte 8 bits 0 -128 to 127 Raw binary data, streams
    short 16 bits 0 -32,768 to 32,767 Tight storage, rare
    int 32 bits 0 -2,147,483,648 to 2,147,483,647 The everyday whole number
    long 64 bits 0L about -9.2 x 10^18 to +9.2 x 10^18 Big counts, timestamps
    float 32 bits 0.0f ~7 decimal digits Approximate decimals, saves memory
    double 64 bits 0.0d ~15 decimal digits The everyday decimal
    char 16 bits, unsigned '\u0000' 0 to 65,535 One Unicode character
    boolean 1 bit (logical; JVM-dependent in practice) false true or false Flags and conditions

    Notes that interviews probe:

    1. char is the only unsigned primitive in Java — it stores a Unicode value, not a signed number.
    2. boolean is not a number in C terms — if (1) does not compile, only if (true) does.
    3. long literals need an L suffix and float literals an f suffix — section 8 explains why.
    4. Sizes are exactly as listed because the JVM spec fixes them; the byte-level storage cost of each in an object is covered in Lecture 4.

    Memory aid — the eight primitives in size order: "Boys Shoot, I Love Football, Delighted Champions Bounce" — byte, short, int, long, float, double, char, boolean.

    5. Primitive vs Non-Primitive (Reference) Types

    Every type in Java is either one of the eight primitives or a reference type:

    Aspect Primitive Non-primitive (reference)
    Examples int, char, boolean String, Student, Integer, arrays
    Holds The value itself A reference (address) pointing at an object
    Created with a type No new needed Usually via new or a literal like "hi"
    Default value 0, 0.0, false, '\u0000' null
    Methods None — no int.add(...) Full method set (str.length())
    Stored Value in stack slot or object field Object in the heap, handle in the variable
    Comparison == compares values == compares references, .equals() content

    Three consequences worth saying out loud:

    1. The object wrappers (Integer, Double, ... in Lecture 18) exist so primitives can be handled as objects.
    2. String is a class, not a primitive — its literal behavior and interning are covered in Lecture 25.
    3. Assigning one reference variable to another copies the reference, not the object — a classic interview trap covered properly in Lecture 45.

    6. How Java Stores Numbers in Memory

    "How it works" — three storage mechanisms explain every surprising result in this lecture:

    1. Whole numbers use two's complement. One bit is the sign, the range is exactly [-2^(n-1), 2^(n-1) - 1]. That is why byte stops at -128 but only reaches 127 — the negative side wins one slot because there is no separate +0.
    2. Floating-point numbers follow the IEEE 754 standard (sign, exponent, mantissa). They are approximations, which is why money math uses long or BigDecimal instead of double.
    3. Overflow wraps around silently. Integer.MAX_VALUE + 1 produces Integer.MIN_VALUE (-2,147,483,648) — no error, the bits simply wrap. The bracket math of two's complement and the full bit-level picture are covered in Lecture 4, and what the compiler does about widening and narrowing values in Lecture 5.

    Interviewer's perspective A favorite follow-up is "where do the three variable kinds live?" The layered answer: local variables sit in the method's stack frame, instance variables live inside the object on the heap, static variables live with the class metadata in the method area. The full dump of this layout is Lecture 45.

    7. Default Values — Fields vs Local Variables

    The JVM gives default values to fields but demands values from locals:

    1. Instance and static variables — automatically set: numeric types to 0, boolean to false, char to '\u0000', references to null.
    2. Local variables — no defaults. Using one before assignment is a compile-time error: variable might not have been initialized.
    // Demo.java — the defaults rule in action
public class Demo {
    static long counter;                     // field gets default 0L
    static boolean ready;                    // field gets default false

    public static void main(String[] args) {
        System.out.println(counter + ", " + ready);   // 0, false

        int local;                                    // declared, not set
        local = 5;                                    // must assign before use
        // System.out.println(unused);                // error: might not have been initialized
        System.out.println(local);                    // 5
    }
}

    Important Defaults are a gift of the JVM at object creation; the compiler checks locals at compile time. That is why the same missing value is "fine" for a field and a compile error for a local.

    8. Literals — the Values You Write in Code

    A literal is a fixed value written directly in source. Java has five families:

    1. Integer literals — four bases plus underscores:
    // Demo.java — every integer literal form (all print the same family of values)
public class Demo {
    public static void main(String[] args) {
        int decimal = 42;          // plain digits
        int octal   = 052;         // leading 0  -> base 8, value 42
        int hex     = 0x2A;        // 0x or 0X  -> base 16
        int binary  = 0b101010;    // 0b or 0B  -> base 2 (Java 7+)
        long big    = 9_223_372_036_854_775_807L;  // underscores (Java 7+)
        int limit   = Integer.MAX_VALUE;           // 2,147,483,647 from java.lang
        System.out.println(decimal + octal + hex + binary + limit);
    }
}
    1. Floating-point literals — 3.14, 1.1e2 (scientific a x 10^b), 0.0001. Decimal literals default to double; float requires an f suffix (float f = 3.14f;) because the compiler refuses silent narrowing — an idea extended into explicit casting in Lecture 5. d is optional: 3.14 and 3.14d are identical.
    2. Character literals — one character in single quotes: 'A', '7', '\u0041', and escape sequences '\n', '\t', '\\', '\'', '\"', '\r', '\b', '\f'.
    3. String literals — zero or more characters in double quotes: "Java", "". The compiler interns them; details in Lecture 25.
    4. Boolean literals — exactly two: true and false. No 1/0 shortcut exists in Java.

    Prefix memory aid — "Octopus starts with 0, 0x marks the hex, 0b as in bits." Decimal literals need no prefix at all.

    9. Keywords and Reserved Words

    A keyword is a word reserved by the language — it can never be used as an identifier. Java's complete set, by role:

    Group Keywords
    Class and object class, interface, enum, extends, implements, new, this, super, instanceof, abstract, final
    Access modifiers public, private, protected, default (also a switch case label)
    Types and values boolean, byte, char, short, int, long, float, double, void
    Control flow if, else, switch, case, default, for, while, do, break, continue, return, assert
    Exceptions try, catch, finally, throw, throws
    Modifiers static, synchronized, transient, volatile, native, strictfp
    Package and import package, import
    Unused but reserved const, goto

    Three nuances that lift an answer above average:

    1. true, false and null are reserved literals, not keywords — the JLS keeps them in a separate category, though they are equally illegal as names.
    2. const and goto are reserved but unused — kept so nobody could write code with meanings Java refuses to support.
    3. Since Java 9, the single underscore _ is also reserved; since modern Java, contextual words like record, sealed, permits, yield and var are not keywords — they can still be used as variable names.

    10. The var Keyword — Local Type Inference (Java 10+)

    var lets the compiler infer a local variable's type from its initializer:

    1. var name = "Java"; — the variable is still exactly String; nothing becomes dynamic.
    2. Allowed only for local variables — not fields, not method parameters, not return types.
    3. An initializer is mandatory — var x; does not compile, so the defaults rule of section 7 still protects locals.
    4. var is not truly a keyword but a reserved type name (JLS 3.8) — var remains usable as a class or method name in edge cases.

    Interview angle: "does var make Java dynamically typed?" No — inference is compile-time only; the inferred type is fixed for the variable's whole life and type checking never disappears.

    11. Myth vs Reality

    Myth Reality
    "String is a primitive type" The eight primitives are byte, short, int, long, float, double, char, boolean — String is a class (Lecture 25).
    "Fields and locals both get default values" Only fields and array elements do; uninitialized locals cause a compile-time error.
    "An int can hold any whole number" It is bounded: Integer.MAX_VALUE + 1 wraps to MIN_VALUE; long exists for bigger counts.
    "char is a signed 8-bit type like in C" Java's char is 16-bit unsigned Unicode (0 to 65,535).
    "var removes Java's static typing" Inference happens at compile time; the variable keeps one fixed type forever.
    "true, false, null are keywords" They are reserved literals; keywords are a separate (bigger) category in the JLS.

    12. Common Trap Questions

    Trap 1 — Default value confusion: "Why does an int field print 0 but an int local refuse to compile?" Fields get JVM defaults at object creation; locals are compiler-checked for definite assignment. One prints 0, the other is variable might not have been initialized.

    Trap 2 — The octal surprise: int x = 010; System.out.println(x); prints 8, not 10 — the leading zero switches to base 8.

    Trap 3 — float f = 3.14; does not compile. A decimal literal is a double; silent narrowing is rejected until f suffix or an explicit cast (Lecture 5).

    Trap 4 — char signedness: "char can hold -128?" No. char is 16-bit unsigned (0 to 65,535) and stores Unicode values.

    Trap 5 — Reserved-but-unused: "Is goto a valid identifier?" No — it is a reserved word even though Java never allows a goto statement; const is the same case.

    Trap 6 — Integer.MAX_VALUE + 1 does not throw an exception or produce an error — it silently wraps to -2147483648.

    Trap 7 — var misuse: "var works for fields too?" No — local variables only, and an initializer is mandatory.

    13. Points to Remember

    1. A variable is type + name + value; the type is fixed at declaration and never changes.
    2. Identifiers may use letters, digits, _, $ — but cannot start with a digit or be a reserved word.
    3. Java is case-sensitive: count, Count and COUNT are three different variables.
    4. Conventions: lowerCamelCase for variables and methods, UpperCamelCase for types, UPPER_SNAKE_CASE for constants.
    5. Only eight primitives exist; an int is 32 bits and a char is 16-bit unsigned on every platform.
    6. String, arrays and every class are reference types; their default field value is null.
    7. Fields and array elements get JVM defaults (0, false, '\u0000', null); locals must be initialized before use.
    8. Literals carry prefixes: none for decimal, 0 octal, 0x hex, 0b binary; underscores (Java 7+) work between digits only.
    9. Decimal literals default to double; float needs f, long needs L.
    10. Whole numbers are stored in two's complement, so overflow wraps around instead of erroring (Lecture 4).

    14. Likely Interview Questions

    Question Crisp Answer
    What is a variable? A named storage for a value; declared with a type, initialized once, reassigned later.
    Rules for legal identifiers? Letters, digits, _, $; no leading digit; no spaces; not a reserved keyword; case-sensitive.
    Variable naming conventions? lowerCamelCase for variables/methods, UpperCamelCase for classes, UPPER_SNAKE_CASE for constants.
    Local vs instance vs static? Local lives per method call; instance per object; static one copy per class (Lecture 15).
    How many primitive types and sizes? Eight: byte 8, short 16, int 32, long 64, float 32, double 64, char 16 unsigned, boolean logical.
    Why is char 16 bits? It stores a Unicode code value (0-65535), not a signed machine character.
    Is boolean a number? No — only true/false; if (1) does not compile, unlike C/C++.
    Do local variables get default values? No — compile-time error "variable might not have been initialized"; defaults apply to fields and arrays only.
    What are the default values of fields? 0 numerics, 0.0f/0.0d, false, '\u0000', null for references.
    Literal forms for 42? 42 decimal, 052 octal, 0x2A hex, 0b101010 binary.
    Why does float f = 3.14 fail? Literals with a decimal point are double; add f or cast explicitly.
    Is var a keyword? Not reserved as a keyword — it is a reserved type name; valid only for initialized locals from Java 10.

    15. Final Summary

    literal (0x2A, 052, 0b101010, '_', 42L, 3.14f)
        ↓
declaration: type + identifier   (int x;  keywords reserve the type)
        ↓
initialization  (or JVM default for fields — locals must be assigned)
        ↓
storage: primitives = value in stack slot / object field
         references = object in heap, handle in the variable (Lecture 45)
        ↓
overflow? two's complement wraps (Lecture 4) — conversion? Lecture 5
    • Identifiers → the name rules; camelCase → the conventions
    • 8 primitives → byte, short, int, long, float, double, char, boolean
    • References → default null, methods allowed, compared with .equals()
    • Literals → prefixes choose the base, suffixes choose the type
    • Fields → defaulted by the JVM; locals → checked by the compiler

    Golden rule The type decides the storage; the default fills only what the JVM somehow owns — anything a method owns must be initialized by you.

    One-line takeaway: every variable in Java is a typed, named box — the eight primitives fix the size, the literals fix the value, and the compiler makes sure nothing inside the box was never assigned.
