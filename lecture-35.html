    Part 5 · Collections, Lambdas & Streams · Lecture 35

    Java Queue Interface Deep Dive | PriorityQueue & Heap Explained

    14 sections · interview-oriented · both themes

    Scope evidence: "Java Queue Interface Deep Dive | PriorityQueue & Heap Explained" (playlist map, verified). Repo evidence: 2 Demo files.

    Lecture 34 closed the Set and Map conversation; this lecture opens the third branch of the Collection hierarchy, the Queue. A queue is a Collection with a discipline: elements leave in a defined order rather than in whatever order they were inserted. The lecture builds that idea in three steps — the FIFO Queue interface and its paired method families, the double-ended Deque and its preferred implementation ArrayDeque, and finally the PriorityQueue, which abandons FIFO entirely and serves elements by priority using a binary heap. The heap is the real subject underneath: once its array representation and two repair operations (sift-up and sift-down) are clear, PriorityQueue stops being a mystery and becomes a predictable structure.

    1. The Queue Interface: FIFO and the Paired Methods

    A Queue<E> is a subinterface of Collection<E> that models a first-in-first-out (FIFO) line: elements are inserted at the tail and removed from the head, so the element that waited longest leaves first. It adds insertion, removal and inspection at the head while keeping everything inherited from Collection. The nesting is:

    Iterable  ⊃  Collection  ⊃  Queue  ⊃  Deque  ⊃  (ArrayDeque, LinkedList)
                                   +--  PriorityQueue   (implements Queue, not Deque)

    What makes Queue distinctive is that every basic operation comes in two forms:

    1. One form throws an exception when the operation cannot be carried out (an empty queue, or a capacity-limited queue that is full).
    2. The other form returns a sentinel — null or false — instead of throwing, which makes it convenient in loops and conditionals.

    The full pairing:

    Operation Throwing form Returns sentinel on failure
    Insert at tail add(e) → throws IllegalStateException if no capacity offer(e) → returns false
    Remove head remove() → throws NoSuchElementException if empty poll() → returns null
    Examine head (no removal) element() → throws NoSuchElementException if empty peek() → returns null

    Important The sentinel form is usually the right default. offer, poll and peek never throw for an empty queue, so the classic drain loop is while ((e = q.poll()) != null) { ... }. The throwing forms exist mainly for bounded queues where a full queue is a genuine programming error.

    Memory aid offer = "try to insert", poll = "take or null", peek = "look don't touch". Throwing twins: add, remove, element.

    2. Deque: The Double-Ended Queue, as Queue and as Stack

    A Deque<E> ("deck", double-ended queue) extends Queue and adds operations at both ends. It exposes a full set of first/last methods: addFirst, addLast, offerFirst, offerLast, removeFirst, removeLast, pollFirst, pollLast, getFirst, getLast, peekFirst, peekLast. It also carries the stack vocabulary push (equivalent to addFirst) and pop (equivalent to removeFirst).

    Two implementations ship with the JDK:

    • ArrayDeque — backed by a resizable circular array with head and tail indices. It is not synchronized, is fast, and is the JDK-recommended default for both queue and stack use. ArrayDeque forbids null elements.
    • LinkedList — backed by doubly linked nodes (Lecture 32). It also implements List, so it is a versatile but heavier choice with per-node memory overhead.

    Used as a queue, elements enter at the tail and leave at the head; used as a stack, both entry and exit happen at the head (LIFO). Because ArrayDeque implements both vocabularies without inheriting the List methods that corrupt LIFO (the flaw of legacy Stack), it is the modern replacement for Stack.

    // Demo.java — ArrayDeque as a queue (FIFO) and as a stack (LIFO)
import java.util.*;

public class Demo {
    public static void main(String[] args) {
        Deque<String> queue = new ArrayDeque<>();
        queue.offerLast("first");   // enqueue at tail
        queue.offerLast("second");
        System.out.println(queue.peekFirst()); // first
        System.out.println(queue.pollFirst()); // first (FIFO: head out)

        Deque<String> stack = new ArrayDeque<>();
        stack.push("bottom");       // push to head
        stack.push("top");
        System.out.println(stack.peek()); // top
        System.out.println(stack.pop());  // top (LIFO: head in)
    }
}

    Interviewer's perspective "Why prefer ArrayDeque over Stack and over LinkedList for a queue?" Stack extends Vector, so it leaks indexed List operations and is synchronized method by method; LinkedList pays per-node allocation. ArrayDeque is a plain circular array — O(1) amortized at both ends, no locking, no list leakage.

    3. PriorityQueue: A Min-Heap, Not a FIFO Queue

    A PriorityQueue<E> is a queue whose order is priority rather than arrival. Its head is always the least element according to natural ordering (a min-heap), or according to a supplied Comparator. It is explicitly not FIFO: two elements inserted in order A then B may leave B then A if B has higher priority. Ties are broken arbitrarily by the heap layout.

    Its core costs:

    • peek() — O(1); the minimum sits at index 0.
    • offer(e) / add(e) — O(log n); the new element is placed at the end and sifted up.
    • poll() / remove() — O(log n); the root is taken, the last element is moved to the root and sifted down.
    • contains(o) / remove(o) — O(n); locating an arbitrary element requires a linear scan because the array is only partially ordered.

    It is unbounded — it grows automatically as elements are added (an int capacity argument sets only an initial size). It is not thread-safe; use PriorityBlockingQueue when threads share it. Crucially, its iteration order is not sorted: iterator() walks the backing array in heap order, which is only guaranteed to have the minimum first. Only removing elements through poll() yields priority order.

    // Demo.java — PriorityQueue is a min-heap: smallest first, iteration is not sorted
import java.util.*;

public class Demo {
    public static void main(String[] args) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        minHeap.offer(50);
        minHeap.offer(10);
        minHeap.offer(30);
        minHeap.offer(20);

        System.out.println(minHeap.peek());    // 10 (minimum at the root)
        System.out.println(minHeap);           // heap order, NOT sorted

        while (!minHeap.isEmpty()) {
            System.out.print(minHeap.poll() + " "); // 10 20 30 50 (priority order)
        }
        System.out.println();
    }
}

    Trap System.out.println(pq) and for (int x : pq) show the heap array, which is not sorted. Students routinely print a PriorityQueue and conclude it is broken. Draining with poll() is the only operation that reveals priority order.

    4. Binary Heap Theory: The Array Behind PriorityQueue

    PriorityQueue is built on a binary heap: a complete binary tree stored compactly in an array, with the heap property that every parent is no greater than its children (min-heap). The array indices encode the tree without pointers:

    Relationship Index formula
    Parent of node i (i - 1) / 2
    Left child of node i 2 * i + 1
    Right child of node i 2 * i + 2
    Root 0
    Last element size - 1

    Two repair operations keep the property intact:

    • Sift-up (bubble-up) on insert: put the new element at size and repeatedly swap it with its parent while it is smaller. At most the height of the tree, so O(log n).
    • Sift-down (bubble-down) on extract: move the last element to the root, then repeatedly swap it with its smaller child while it is larger than that child. Also O(log n).
    // Demo.java — heap index arithmetic mirroring PriorityQueue's internal array
public class Demo {
    static int parent(int i) { return (i - 1) / 2; }
    static int left(int i)   { return 2 * i + 1; }
    static int right(int i)  { return 2 * i + 2; }

    public static void main(String[] args) {
        int i = 4;
        System.out.println(parent(i)); // 1
        System.out.println(left(i));   // 9
        System.out.println(right(i));  // 10
    }
}

    Building a heap from n unordered elements costs O(n), not O(n log n): the bottom-up build-heap sifts down only the internal nodes, and the total work telescopes to linear. Heapsort then extracts the minimum n times at O(log n) each, giving O(n log n) with O(1) extra space — the theoretical ancestor of PriorityQueue.

    Memory aid Insert swims up; extract sinks down. The parent of i is its floor-half, and a heap is only partially ordered: parent <= children, siblings and cousins unconstrained.

    5. Custom Priorities: Comparator and Comparable

    The natural ordering of a PriorityQueue is ascending (min-first). To get a max-heap, pass Comparator.reverseOrder(). For user-defined types, PriorityQueue needs a way to compare them, and there are two routes:

    • Make the class implement Comparable and define compareTo — natural ordering (cross-ref Lecture 36, Comparable and the Collections class).
    • Pass a Comparator to the constructor, overriding natural order — including lambdas and method references (cross-ref Lecture 37/38, Comparator and lambdas).
    // Demo.java — a max-heap via Comparator.reverseOrder()
import java.util.*;

public class Demo {
    public static void main(String[] args) {
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());
        maxHeap.offer(50);
        maxHeap.offer(10);
        maxHeap.offer(30);

        System.out.println(maxHeap.peek()); // 50 (largest first)

        // Custom priority: longer strings first, via a lambda Comparator
        PriorityQueue<String> byLength =
            new PriorityQueue<>((a, b) -> b.length() - a.length());
        byLength.offer("hi");
        byLength.offer("hello");
        byLength.offer("hey");
        System.out.println(byLength.poll()); // hello
    }
}

    Important A Comparator must be consistent with the elements it compares; a comparator that contradicts equals is legal but surprising, and one that contradicts itself (e.g., subtracting large ints and overflowing) can leave the heap in an order the JVM never promised. If elements are not Comparable and no Comparator is supplied, offer throws ClassCastException at insertion time.

    6. The Heap as an Engine: Scheduling, Dijkstra, Top-K

    The heap is not an academic artifact; it is the workhorse behind several canonical algorithms:

    • Priority scheduling — an operating system or task runner picks the highest-priority ready job next; a heap gives O(log n) insertion and O(log n) extraction.
    • Dijkstra's shortest path — the frontier of unvisited vertices is a min-priority queue keyed by tentative distance; each relaxation is an offer or a decrease-key, giving O((V + E) log V) with a binary heap.
    • Top-k — to find the k largest items from a stream, keep a min-heap of size k; the root is the smallest of the current best, so any new element larger than the root replaces it in O(log k), and the final heap holds the k largest.
    • Event simulation, Huffman coding, A* search — all select the minimum (or maximum) from a changing set as their inner loop.

    Interviewer's perspective "Why a min-heap for the largest k elements?" Because the root is the weakest member of the current top-k. If the new element beats the root, evict the root and insert the newcomer; if it does not, discard it. A max-heap would force you to scan the whole heap to find the weakest.

    7. ArrayDeque vs LinkedList vs PriorityQueue

    Aspect ArrayDeque LinkedList PriorityQueue
    Backing structure Resizable circular array Doubly linked nodes Binary heap in an array
    Ordering FIFO as queue, LIFO as stack FIFO as queue, LIFO as stack Priority order (min-heap by default)
    Access to middle Not supported O(n) by walk O(n) by scan
    Ends / head Amortized O(1) at both ends O(1) at both ends O(1) peek, O(log n) insert/extract
    null allowed No Yes No
    Synchronized No No No
    Iteration order Insertion order (front to back) Insertion order Heap order, not sorted
    Best used when Default queue/stack Mixed List plus Deque needs Serving elements by priority

    Reading the table: ArrayDeque and LinkedList preserve arrival order and differ only in backing; PriorityQueue is a different contract altogether and should never be described as a queue that "also happens" to reorder.

    8. Heap Operation Complexities

    Operation Cost Why
    peek() / element() O(1) Minimum is the root at index 0
    offer(e) / add(e) O(log n) Append then sift-up along the height
    poll() / remove() O(log n) Replace root with last, sift-down
    contains(o) O(n) Heap is only partially ordered; linear scan
    remove(o) O(n) Find in O(n), then repair the heap
    Build heap from n items O(n) Bottom-up build-heap, linear total
    Heapsort (build + n extracts) O(n log n) n extractions at O(log n) each
    Iterate all elements O(n) Array walk, not sorted

    The asymmetry to remember: the heap optimizes repeatedly taking the extreme, not searching for an arbitrary value. The moment your workload asks "is X in here?" more often than "give me the smallest", a heap is the wrong tool.

    9. Pitfalls and Common Errors

    Pitfall What goes wrong Correct approach
    Expecting sorted iteration The backing array is heap-ordered, not sorted Drain with poll(), or copy and sort
    Adding null PriorityQueue and ArrayDeque forbid null; insertion fails with NullPointerException (NotAllowedException for some queue types) Guard for null before offering
    Assuming thread safety Concurrent access corrupts the heap silently Use PriorityBlockingQueue or external locking (Lectures 51, 56)
    Treating contains/remove(o) as cheap Both are O(n) scans Keep a companion Set when membership queries dominate
    An inconsistent Comparator Elements become unreachable or order is violated Make the comparator total and consistent
    Non-comparable elements offer throws ClassCastException at runtime Implement Comparable or pass a Comparator
    Reaching for Stack or LinkedList by habit Slower, and Stack leaks List methods Prefer ArrayDeque for queue and stack
    Assuming deterministic ties Equal-priority elements may come out in any order Add a tie-breaker field to the comparator

    Golden rule Choose the queue from its ordering contract, not its convenience: use ArrayDeque when arrival order matters, and PriorityQueue only when the next element must be the most important one.

    10. Myth vs Reality

    Myth Reality
    "A PriorityQueue is a FIFO queue." It is not FIFO; it serves the least element (or the Comparator ordering), regardless of arrival.
    "Iterating a PriorityQueue prints elements in priority order." Iteration is heap order, not sorted; only poll() yields priority order.
    "PriorityQueue is thread-safe." It is not; use PriorityBlockingQueue for concurrent use.
    "peek() returns the smallest element in O(log n)." peek() is O(1) — the minimum is always the root.
    "Finding an element in a heap is fast because the heap is ordered." The heap is only partially ordered, so contains and remove(Object) are O(n).

    11. Common Trap Questions

    Trap 1 — Sorted or not: "After inserting 50, 10, 30, 20 into a PriorityQueue, what does printing it show?" The heap array in heap order (for example [10, 20, 30, 50] for this input), which is not a general sorted traversal. Only repeated poll() returns sorted order.

    Trap 2 — Default direction: "By default, is a PriorityQueue a min-heap or a max-heap?" Min-heap: the head is the smallest element under natural ordering. For a max-heap pass Comparator.reverseOrder().

    Trap 3 — Null elements: "Can a PriorityQueue or ArrayDeque hold null?" No. Both reject null (typically NullPointerException); LinkedList as a Deque does allow null.

    Trap 4 — The complex op: "What is the complexity of pq.contains(x)?" O(n). The heap only guarantees parent <= children, so an arbitrary value can be anywhere and must be found by scan.

    Trap 5 — Priority first: "Elements inserted in the order A, B, C with priorities 3, 1, 2 — what is poll()?" B. The smallest priority wins, so arrival order is irrelevant.

    Trap 6 — Ties: "Two elements share the highest priority. Which leaves first?" Either. Ties are broken arbitrarily by the heap layout; add a secondary key to the Comparator for a deterministic order.

    Trap 7 — Deque as stack: "Which Deque methods implement stack push and pop?" push maps to addFirst; pop maps to removeFirst. peek maps to peekFirst.

    12. Points to Remember

    1. Queue adds FIFO insertion at the tail and removal/inspection at the head to Collection.
    2. Each core operation has two forms: add/remove/element throw, while offer/poll/peek return false or null.
    3. Deque extends Queue with operations at both ends and adds push/pop for stack use.
    4. ArrayDeque is a circular-array Deque; it is the preferred queue and stack, and it rejects null.
    5. LinkedList is a node-backed Deque and List; it allows null but carries per-node overhead.
    6. PriorityQueue is a min-heap ordered naturally or by a Comparator; it is not FIFO.
    7. peek is O(1); offer and poll are O(log n); contains and remove(Object) are O(n).
    8. A PriorityQueue is unbounded, not thread-safe, and its iteration order is not sorted.
    9. A binary heap stores a complete tree in an array: parent (i-1)/2, children 2i+1 and 2i+2.
    10. Insert uses sift-up; extract uses sift-down; build-heap is O(n) and heapsort is O(n log n).

    13. Likely Interview Questions

    Question Crisp Answer
    What is the Queue interface? A Collection subinterface with FIFO insertion at the tail and removal/inspection at the head.
    add vs offer, remove vs poll, element vs peek? The first of each pair throws on failure; the second returns false or null.
    What is a Deque? A double-ended queue that supports insertion and removal at both ends.
    Why prefer ArrayDeque over Stack? Stack extends Vector and leaks indexed List methods plus per-method synchronization; ArrayDeque is a faster, lock-free circular array.
    How does PriorityQueue order elements? By priority: natural ordering (min-heap) or a supplied Comparator.
    Is PriorityQueue FIFO? No. It always serves the least element, so a later insertion can leave before an earlier one.
    What is the complexity of PriorityQueue.offer and poll? O(log n) each, because of sift-up and sift-down.
    Why is peek O(1)? The minimum is at index 0, the root of the heap array.
    Why is contains O(n)? A heap is only partially ordered, so an arbitrary element must be located by linear scan.
    Does iterating a PriorityQueue produce sorted output? No — iteration is heap order; only repeated poll() yields priority order.
    How do you build a max-heap with PriorityQueue? Pass Comparator.reverseOrder() (or a custom descending comparator) to the constructor.
    How does a binary heap map to an array? Parent (i-1)/2, left child 2i+1, right child 2i+2, root at 0.
    Is PriorityQueue thread-safe? No; use PriorityBlockingQueue for concurrent access.

    14. Final Summary

    Queue   -> FIFO: add/offer (tail), remove/poll, element/peek (head)
   throws: add remove element        null-safe: offer poll peek
Deque   -> both ends: ArrayDeque (preferred, circular array) · LinkedList (nodes)
           queue: offerLast + pollFirst     stack: push + pop (head)
PriorityQueue -> min-heap by natural order or Comparator; NOT FIFO
           peek O(1) · offer/poll O(log n) · contains/remove(Object) O(n)
           iteration NOT sorted · unbounded · not thread-safe · no null
Binary heap -> array: parent (i-1)/2 · children 2i+1, 2i+2
           insert: sift-up · extract: sift-down · build-heap O(n) · heapsort O(n log n)
max-heap -> Comparator.reverseOrder()      custom types -> Comparable (L36) or Comparator (L37/38)
    • Queue → the FIFO contract; paired throwing and sentinel methods (add/offer, remove/poll, element/peek).
    • Deque → double-ended; ArrayDeque is the preferred queue and stack, LinkedList the node-backed alternative.
    • PriorityQueue → a min-heap, not FIFO; O(1) peek, O(log n) insert/extract, O(n) search, unsorted iteration.
    • Heap → array-encoded complete tree; sift-up on insert, sift-down on extract, O(n) build, O(n log n) heapsort.
    • Priorities → Comparator.reverseOrder() for a max-heap; custom objects need Comparable or a Comparator.
    • Trap → printing or iterating a PriorityQueue shows heap order, never sorted order; only poll() is ordered.

    Golden rule A Queue promises arrival order, a PriorityQueue promises priority order — and only poll() ever reveals it, never println or a for-each loop.

    One-line takeaway: ArrayDeque is the right FIFO/LIFO line and PriorityQueue is a binary heap for serving the most important element next, so trust poll for order and never the iterator.
