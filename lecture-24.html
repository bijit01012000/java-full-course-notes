    Part 3 · OOP Deep Dive · Lecture 24

    Java Interfaces Deep Dive | Default Methods, Functional, Marker Interfaces

    19 sections · interview-oriented · both themes

    Scope evidence: "Java Interfaces Deep Dive | Default Methods, Functional, Marker Interfaces" (playlist map, verified). Repo evidence: 7 Demo files. The cached lecture PDF is image-only and is ignored per project rules.

    Lecture 17 introduced the interface as a pure contract of abstract methods. This lecture goes deep: how an interface is declared and implemented, the implicit modifiers that surprise beginners, multiple inheritance of type, the Java 8 additions (default and static methods) that let interfaces evolve without breaking implementors, the Java 9 private helper methods, the single-abstract-method (SAM) rule behind functional interfaces and lambdas, and marker interfaces together with why annotations have largely replaced them for new code. The diamond-conflict rules and the interface-versus-abstract-class distinction close the loop.

    1. Interfaces Recap: A Contract of Abstract Methods

    An interface is a reference type that declares a contract: a set of method signatures that every implementor promises to provide. From Lecture 17, it is the cleanest expression of abstraction and polymorphism — the interface says what an object can do, never how it does it. A class that commits to the contract uses implements, and the compiler enforces that no abstract method is left unimplemented. The relationship is can-do (capability), as opposed to the is-a relationship of inheritance.

    2. Declaring and Implementing an Interface

    // Demo.java — an interface contract with one default method
interface Greeter {
    String name();                       // abstract method: the contract
    default void greet() {               // default method with a body (Java 8)
        System.out.println("Hello, " + name());
    }
}

class EnglishGreeter implements Greeter {
    public String name() { return "Ada"; }   // override must be public
    // greet() is inherited unchanged
}

public class Demo {
    public static void main(String[] args) {
        new EnglishGreeter().greet();    // Hello, Ada
    }
}

    The implementor picks up the abstract method and the default method in one step. A concrete class must supply every abstract method; an abstract class may leave some unimplemented, deferring them to its own subclasses.

    3. Implicit Modifiers

    Interface members carry modifiers whether you type them or not. This is the first place beginners get surprised, because an interface method with no access keyword is not package-private.

    Declaration Effective modifiers Notes
    method with no body public abstract every override must be public
    default method public not abstract, has a body
    static method public belongs to the interface
    field public static final a constant, must be initialised
    nested type public static implicitly static

    A top-level interface itself may be public or package-private (no keyword), exactly like a class. Only one public top-level type is allowed per file, which is the one-public-class rule of Lecture 18 applied to interfaces.

    Important interface X { int MAX = 10; } declares a constant: public static final int MAX. Writing X.MAX = 20; later is a compile error because the field is final — interfaces have no mutable instance state.

    4. Multiple Inheritance of Type

    A class extends exactly one class, but it may implement many interfaces. Writing class FileLogger implements Closeable, Serializable, Runnable { ... } is legal.

    This is multiple inheritance of type, not of state. Because a pure interface carries no fields and no constructor, combining several of them cannot create the classic state-merging diamond that some languages suffer from. A class may have one superclass and freely implement any number of interfaces, and a reference typed to any one of those interfaces can point at the object. The diamond returns only when interfaces start providing behaviour — the default methods of Section 5.

    5. Default Methods (Java 8): Evolving a Contract Without Breaking It

    Before Java 8, adding a method to a published interface broke every existing implementor. A default method is a method in an interface that carries a body, marked with the default keyword. Implementors inherit it for free and may override it like any other method. This is what allowed the standard library to add methods such as Collection.stream() and List.sort() without rewriting the world. An interface can therefore declare both void move(); and default int wheels() { return 4; } — the second is inherited unless an implementor overrides it.

    Interviewer's perspective The purpose of default methods is backward-compatible interface evolution in a world without multiple class inheritance. An interface with defaults is still not an abstract class: it cannot hold instance fields or constructors, and it cannot access object state directly.

    6. The Diamond Problem and Its Resolution Rules

    Default methods reintroduce the diamond: if two interfaces in a class's hierarchy both supply a default with the same signature, which one does the class inherit? Java resolves it with three deterministic rules, applied in order.

    Rule Situation Winner
    1 A superclass (class) method and an interface default share a signature The class method wins
    2 Two interfaces where one extends the other; the subinterface overrides the default The more specific subinterface wins
    3 Two unrelated interfaces both supply a conflicting default The class must override and choose explicitly 
    // Demo2.java — a diamond resolved with A.super.method()
interface A { default void hello() { System.out.println("A"); } }
interface B extends A { default void hello() { System.out.println("B"); } }
interface C extends A { default void hello() { System.out.println("C"); } }

class D implements B, C {                 // B and C are unrelated branches
    public void hello() {
        B.super.hello();                  // pick the branch explicitly
    }
}
public class Demo2 {
    public static void main(String[] args) {
        new D().hello();                  // B
    }
}

    InterfaceName.super.method() is legal only inside a class that directly implements (or inherits) that interface, and it selects that interface's version unambiguously. Rule 2 means that if only B overrode hello and a class implemented A and B, the compiler would silently choose B with no override needed.

    Memory aid Resolution order is class > more-specific subinterface > your override. Only the last resort forces the class to write Name.super.method().

    7. Static Interface Methods (Java 8)

    An interface may declare static methods. Unlike default methods, they are not inherited by implementors and are not overridable (no dynamic dispatch). They belong to the interface and are called through its name: InterfaceName.method(). If interface Units declares static double kilometersPerMile() { return 1.60934; }, then Units.kilometersPerMile() compiles, while new MyClass().kilometersPerMile() and MyClass.kilometersPerMile() are both compile errors.

    The standard library uses these as utility homes, for example Comparator.comparing(...) and Stream.of(...). The design intent is to keep helper code logically next to the interface without polluting the implementor's namespace.

    8. Private Interface Methods (Java 9)

    Default methods often share logic. Before Java 9 the only way to factor that logic out was a public default method (exposing it to everyone) or a separate utility class. Java 9 added private methods to interfaces: helper methods callable only from other methods of the same interface.

    // Demo5.java — a shared private helper (Java 9)
interface Report {
    default void shortReport() { print("short", 1); }
    default void longReport()  { print("long", 5); }
    private void print(String kind, int pages) {   // not inherited, not exposed
        System.out.println(kind + " report (" + pages + " pages)");
    }
}
public class Demo5 {
    public static void main(String[] args) {
        Report r = new Report() { };   // only defaults: no abstract method to implement
        r.shortReport();
        r.longReport();
    }
}

    A private interface method must have a body, may be static (private static), and is invisible to implementors and to the outside world. It cannot be abstract.

    9. Functional Interfaces: The Single Abstract Method

    A functional interface is an interface with exactly one abstract method (SAM). That single method gives a lambda expression a target: the lambda supplies the body for that one method. The @FunctionalInterface annotation is optional but recommended — it makes the compiler verify the SAM rule at declaration time.

    // Demo3.java — a functional interface implemented by a lambda
@FunctionalInterface
interface Calculator {
    int apply(int a, int b);             // one abstract method = the SAM
}
public class Demo3 {
    public static void main(String[] args) {
        Calculator add = (a, b) -> a + b;        // lambda targets the SAM
        System.out.println(add.apply(3, 4));     // 7
    }
}

    Two subtle rules decide what counts:

    1. Object methods do not count. Redeclaring equals(Object), hashCode() or toString() in an interface does not add to the abstract-method count, because they duplicate public methods of Object.
    2. default and static methods do not count. Only abstract (body-less) methods count toward the single-method rule.

    Lambdas are the subject of Lecture 37; method references, which are shorthand for a lambda, are Lecture 38.

    Important Removing the @FunctionalInterface annotation silently changes an error. With it, a second abstract method is a compile error at the interface. Without it, the interface compiles and only the lambda assignment at the call site fails, with a less obvious message.

    10. Standard Functional Interfaces and Lambdas

    The JDK ships a standard functional interface for most shapes of behaviour. Runnable and Comparator pre-date Java 8; the java.util.function family was added with it.

    Interface Abstract method (SAM) Purpose Typical lambda
    Runnable void run() run a task () -> System.out.println("go")
    Comparator<T> int compare(T a, T b) impose an ordering (a, b) -> a.length() - b.length()
    Function<T,R> R apply(T t) transform a value s -> s.length()
    Predicate<T> boolean test(T t) test or filter a value s -> s.isEmpty()
    Supplier<T> T get() supply a value lazily () -> "hello"
    Consumer<T> void accept(T t) consume a value s -> System.out.println(s)

    Each row is a purpose-built SAM, which is why a lambda alone is never enough — it always needs a target type to resolve the method signature and the return type.

    11. Marker Interfaces: Interfaces With No Methods

    A marker interface (also called a tag interface) declares no methods at all. It carries meaning through type membership alone: an object is a member of the type, or it is not. The classic examples are java.io.Serializable, java.lang.Cloneable, and java.util.RandomAccess.

    // Demo4.java — a marker interface checked with instanceof
interface Deletable { }                  // no methods: a tag

class Draft implements Deletable { }
class FinalReport { }

public class Demo4 {
    public static void main(String[] args) {
        System.out.println(new Draft() instanceof Deletable);        // true
        System.out.println(new FinalReport() instanceof Deletable);  // false
    }
}

    The tag is inspected either by user code with instanceof or by a library that treats membership as a capability signal. Serialization, for example, refuses to write an object that is not Serializable; the marker is the capability grant. Cloneable, notably, is considered a design flaw: it grants Object.clone() permission without declaring a clone() method, so correct cloning still depends on overriding a method the interface never mentions.

    Important A marker interface is a compile-time type, so it can appear in instanceof, as a generic bound (<T extends Serializable>), and as a parameter type. An annotation cannot do any of those.

    12. Marker Interface vs Annotation

    Annotations (Java 5) can also attach metadata to a type, and for most new tagging needs they are the better tool. The comparison clarifies when each is appropriate.

    Aspect Marker Interface Annotation
    Definition Empty interface @interface type
    Example Serializable, Cloneable @Deprecated, @FunctionalInterface
    Carries data No Yes — elements with values
    Type-system role Yes: usable as a type, bound, or instanceof target No: cannot be used as a type
    Processing instanceof or library check Reflection, annotation processors, frameworks
    Retention control Fixed by the type system SOURCE, CLASS or RUNTIME
    Extensibility Fixed once published Can add elements and targets
    New-code guidance Use for genuine type-level capability Prefer for metadata and configuration

    Annotations largely superseded marker interfaces because they are metadata plus tooling: they can carry parameters, be scoped by @Target, be retained or discarded by @Retention, and be consumed by frameworks and annotation processors without altering a class's type hierarchy. A marker interface still wins when the tag must participate in the type system — as a generic bound or a method parameter type.

    13. Interface vs Abstract Class: The Full Recap

    Default methods blurred the line, so the distinction must be stated precisely. The decisive difference is state: an interface can never hold instance fields or a constructor, no matter how many default methods it gains.

    Aspect Interface Abstract Class
    Keyword interface / implements abstract class / extends
    Inheritance Many interfaces One superclass only
    Instance state None — fields are static final constants Any instance fields allowed
    Constructor None Yes, chained via super(...)
    Methods Abstract, default, static, private Abstract and concrete, any access
    Access modifiers on members Effectively public (private since Java 9) Any
    Multiple inheritance Of type only No
    Since Java 8 default and static methods (unchanged)
    Since Java 9 private methods (unchanged)
    Choose it when Unrelated classes share a capability or contract Closely related classes share state and partial implementation

    The default-method nuance: adding default methods gave interfaces behaviour but not memory. An interface method cannot read or write an object's fields, because the interface has no fields. Any algorithm that needs per-object state must still live in an abstract class or be supplied by the implementor.

    Golden rule If the abstraction needs state, use an abstract class; if it needs only a contract and capability, use an interface. Default methods are for evolution, not for smuggling state into interfaces.

    14. Pitfalls and Common Errors

    Pitfall What goes wrong Correct approach
    Overriding a default method without public Compile error: attempting to assign weaker access Interface methods are public; the override must be public
    Two unrelated defaults with the same signature Compile error in the implementing class Override and choose with InterfaceName.super.method()
    Calling a static interface method through an instance or implementor Compile error Call it as InterfaceName.method()
    A "functional" interface with two abstract methods Lambda assignment fails to compile Keep exactly one abstract method, or drop @FunctionalInterface semantics
    Expecting an interface to hold state Constants only; no instance fields are possible Move state to the implementing class or an abstract class
    default method confused with an abstract-class method It cannot touch object state and cannot be private/protected Use it only for state-free behaviour
    Relying on a marker interface for behaviour The marker alone does nothing; some code must test it Ensure a checker (instanceof or library) honours the tag
    Forgetting the lambda needs a target type var f = x -> x + 1; does not compile Assign to a functional interface type

    15. Myth vs Reality

    Myth Reality
    "Interfaces can hold any fields like classes" All interface fields are implicitly public static final constants; interfaces have no instance state.
    "A class can implement only one interface" A class may implement any number of interfaces (multiple inheritance of type); it extends only one class.
    "Default methods make interfaces equal to abstract classes" No: interfaces still lack instance fields and constructors; defaults add behaviour, never state.
    "Static interface methods are inherited by implementors" They are not inherited and not overridable; call them through InterfaceName.method().
    "@FunctionalInterface is required for lambdas" It is an optional compile-time check; any single-abstract-method interface can be a lambda target.
    "Marker interfaces and annotations are interchangeable" Marker interfaces participate in the type system; annotations carry metadata consumed by tools.

    16. Common Trap Questions

    Trap 1 — The Object methods: "An interface declares boolean equals(Object o); plus one other abstract method. Is it still a functional interface?" Yes. A method that matches a public method of Object does not count toward the abstract-method total, so the other method remains the SAM.

    Trap 2 — The weaker access override: "Why does overriding a default method without public fail?" Every interface method is implicitly public; an override may not reduce visibility. The overriding method must be declared public.

    Trap 3 — The static call: "Can I call Comparator.comparing(...) through an instance of a class that implements Comparator?" No. Static interface methods are not inherited; the only legal call is through the interface name, Comparator.comparing(...).

    Trap 4 — The unresolved diamond: "Two unrelated interfaces both provide default void log(). The class implements both without overriding. What happens?" Compile error. With no class method and no more-specific interface, the class must override log() and select a branch with A.super.log() or B.super.log().

    Trap 5 — Two abstract methods: "A @FunctionalInterface-annotated interface gains a second abstract method. When does it fail?" Immediately at the interface declaration: the annotation turns the SAM violation into a compile error at that point, before any lambda is written.

    Trap 6 — The state expectation: "Can a default method keep a counter in an interface field?" No. Interface fields are public static final, so the counter would be a shared constant. Instance state belongs to the implementing class.

    Trap 7 — Classes beat interfaces: "A superclass has a concrete describe() method and an implemented interface has a default describe(). Which runs?" The superclass method wins by rule 1; the interface default is ignored for that class unless the class overrides.

    17. Points to Remember

    1. An interface is a contract of abstract methods; it expresses capability (can-do), not inheritance of state (is-a).
    2. Interface fields are implicitly public static final; interface methods without a body are implicitly public abstract.
    3. A class implements many interfaces but extends only one class — multiple inheritance of type, never of state.
    4. Java 8 default methods add behaviour so an interface can evolve without breaking implementors; conflict order is superclass/class method, then the more specific subinterface, otherwise an explicit InterfaceName.super.method().
    5. Java 8 static interface methods belong to the interface, are called as InterfaceName.method(), and are neither inherited nor overridden.
    6. Java 9 private interface methods are helpers for default and static methods; they are not inherited and not part of the public API.
    7. A functional interface has exactly one abstract method (SAM); @FunctionalInterface enforces the rule, and Object methods plus default/static methods do not count.
    8. Standard functional interfaces include Runnable, Comparator, Function<T,R>, Predicate<T>, Supplier<T> and Consumer<T>; lambdas target them (Lecture 37), method references shorten them (Lecture 38).
    9. A marker interface has no methods; it is a type-level tag (Serializable, Cloneable, RandomAccess) checked with instanceof or by a library, and annotations have largely replaced it for metadata tagging.
    10. Even with default, static and private methods an interface holds no instance state and has no constructor, so an abstract class remains the tool for shared state or partial implementation.

    18. Likely Interview Questions

    Question Crisp Answer
    What is an interface? A reference type declaring a contract of method signatures; implementors supply the behaviour, and the type expresses a capability.
    What are the implicit modifiers of interface members? Methods without a body are public abstract, fields are public static final, methods with default/static are public unless private (Java 9).
    Can a class extend and implement at the same time? Yes: one extends for a class plus any number of implements interfaces.
    Why were default methods added in Java 8? To evolve existing interfaces (notably the collections) without breaking every implementor, and to enable state-free mixin behaviour.
    How is the diamond problem resolved? A class or superclass method wins; otherwise the most specific subinterface wins; otherwise the class must override and call InterfaceName.super.method().
    Are static interface methods inherited? No. They belong to the interface and are called as InterfaceName.method(); they are not overridable.
    What is a private interface method? A Java 9 helper with a body, callable only by other methods of the same interface; used to share code between default methods.
    What is a functional interface? An interface with exactly one abstract method; lambdas and method references use it as their target type.
    Do Object methods count toward the SAM? No. Redeclaring equals, hashCode or toString does not add an abstract method for the functional-interface count.
    What is a marker interface? An interface with no methods used as a type-level tag, checked with instanceof or honoured by a library, e.g. Serializable.
    Marker interface or annotation? Use a marker interface when the tag must be a type (bound, parameter, instanceof); use an annotation for metadata consumed by tools or frameworks.
    Interface vs abstract class in one line? An interface is a stateless contract with multiple inheritance of type; an abstract class may hold state, constructors and partial implementation, but allows only single inheritance.

    19. Final Summary

    interface = contract (what)          class implements many interfaces
   fields   : public static final       methods : public abstract
   Java 8   : default (behaviour) + static (Interface.method())
   Java 9   : private (shared helper)

diamond:  class method  >  specific subinterface  >  Name.super.method()

SAM  --lambda-->  functional interface   (Runnable, Comparator, Function<T,R>, Predicate<T>, ...)
marker (no methods)  --instanceof-->  Serializable, Cloneable, RandomAccess
    • Interface → stateless contract; implicit public abstract methods and public static final constants; capability, not is-a.
    • Default methods → backward-compatible evolution; the class may override; resolution is class > specific subinterface > explicit Name.super.method().
    • Static methods → InterfaceName.method(), not inherited, not overridable; private methods → Java 9 shared helpers, invisible outside the interface.
    • Functional interface → exactly one abstract method; @FunctionalInterface verifies; Object, default and static methods do not count; lambdas (Lecture 37) and method references (Lecture 38) target it.
    • Marker interface → no methods, a type-level tag; annotations replaced it for metadata tagging but cannot act as a type.
    • Interfaces still cannot hold instance state or constructors — an abstract class remains the tool for shared state and partial implementation.

    Golden rule An interface is a promise of behaviour, not a container of state: default, static and private methods extend what an interface can do in Java 8 and 9, but never let it remember anything.

    One-line takeaway: an interface is a stateless contract that a class may implement many times over, and its default, static, private, functional and marker forms let that contract evolve and be expressed without ever holding instance state.
