    Part 3 · OOP Deep Dive · Lecture 19

    Java Nested Classes | Static Nested, Inner, Local & Anonymous Classes

    16 sections · interview-oriented · both themes

    Scope evidence: "Java Nested Classes | Static Nested, Inner, Local & Anonymous Classes" (playlist map, verified). Repo evidence: 4 Demo files.

    Java lets you declare a class inside another class, and it lets you do it in four different ways, each with different access rights, lifetimes and instantiation syntax. The choice matters because it decides whether the nested type carries a hidden reference to an outer object, which in turn decides memory behaviour and serialization safety. This lecture covers why nesting exists, the four kinds (static nested, inner, local and anonymous), how each is instantiated, what the compiler emits on disk, and the traps interviewers use to separate surface knowledge from real understanding. Anonymous classes are also the direct ancestor of lambda expressions, so this is the last stop before that bridge in Lecture 37.

    1. Why Nested Classes Exist

    A nested class is a class declared inside the body of another class, method or block. Java offers it for three reasons:

    1. Logical grouping — a type that only one class needs stays beside its owner instead of polluting the package namespace. Map.Entry lives inside Map because it has no independent meaning.
    2. Encapsulation — a private nested type is invisible outside its owner, giving the owner a private implementation detail that no other class can name. The nested type can also read the outer class's private members, which no top-level helper could.
    3. Helper types and cleaner naming — short names work inside the scope, and the compiler scopes the declaration so it cannot leak.

    A class owns fields and methods; nesting lets it own types as well. Memory aid: a class can own a type.

    Important Nesting is about where a type belongs, not about inheritance. A nested class is not a subclass of its outer class; the only relationship is lexical containment plus (for inner classes) a reference to an outer instance.

    2. The Four Kinds at a Glance

    Java defines exactly four kinds of nested class:

    1. Static nested class — declared static inside a class body; has no outer instance.
    2. Inner class (non-static member class) — declared as a non-static member; holds an implicit reference to an outer instance.
    3. Local class — declared inside a method or block; exists only for that scope.
    4. Anonymous class — declared and instantiated in a single expression; has no name.

    A useful first split: static nested classes behave almost like top-level classes that happen to be namespaced, while the other three are inner in the sense that they are associated with an enclosing instance (except when a local or anonymous class is created in a static context).

    3. Static Nested Classes

    A static nested class is declared with the static modifier directly in the enclosing class body. Because it is static, it belongs to the class, not to any object of the class, so an outer instance is not needed and is not held.

    Consequences:

    1. It can access the outer class's static members directly (fields, methods, nested types).
    2. It cannot access the outer class's instance members directly, because there is no outer instance to read them from.
    3. It is instantiated with Outer.Nested n = new Outer.Nested(); — no new Outer() required.
    // Demo.java — static nested class: no outer instance needed
public class Demo {
    private static int count = 0;   // static -> visible to the nested type

    static class Nested {
        void show() {
            count++;                // outer STATIC member, accessed directly
            System.out.println("static nested, count = " + count);
        }
    }

    public static void main(String[] args) {
        Demo.Nested n = new Demo.Nested();   // no outer object created
        n.show();                            // static nested, count = 1
        n.show();                            // static nested, count = 2
    }
}

    This is the cheapest form to use: no hidden outer reference, no extra object, and it is generally safe to serialize.

    4. Inner (Non-Static Member) Classes

    An inner class is a member of the outer class without static. Every instance of it is bound to an instance of the outer class and carries a hidden field that points back to that outer object. Inside the inner class, the outer instance is available explicitly as Outer.this.

    Consequences:

    1. It can access all outer members — private, instance, static — directly.
    2. It cannot be instantiated without an outer instance: Outer.Inner i = outer.new Inner(); (note the unusual .new syntax).
    3. Because it holds the outer reference, a live inner instance keeps the whole outer object alive — the classic memory-leak risk when an inner object outlives its intended use.
    // Demo2.java — inner class: holds an implicit reference to the outer instance
public class Demo2 {
    private int id = 42;
    private static String tag = "outer";

    class Inner {
        void show() {
            System.out.println(id);            // outer instance field
            System.out.println(tag);           // outer static member
            System.out.println(Demo2.this.id); // explicit outer reference
        }
    }

    public static void main(String[] args) {
        Demo2 outer = new Demo2();
        Demo2.Inner in = outer.new Inner();    // REQUIRES an outer instance
        in.show();
    }
}

    Interviewer's perspective The instantiation syntax outer.new Inner() is the visible symptom of the hidden reference; if you can explain why it is written that way, you understand that the inner object stores a link to the outer object.

    5. Local Classes

    A local class is declared inside a method or a block. Its scope is the block in which it is declared — it cannot be referenced outside it, and it is invisible to the rest of the class. A local class can access the enclosing class's members and, in addition, local variables that are effectively final (assigned once and never changed afterwards).

    // Demo3.java — local class: declared in a method, captures effectively-final locals
public class Demo3 {
    void run() {
        int factor = 3;                      // effectively final (never reassigned)

        class Multiplier {                   // local class: scope ends with the method
            int times(int x) { return x * factor; }
        }

        Multiplier m = new Multiplier();
        System.out.println(m.times(7));      // 21
        // factor = 5;                       // would break capture: not effectively final
    }

    public static void main(String[] args) {
        new Demo3().run();
    }
}

    A local class can have constructors and can be reused within its block, which distinguishes it from an anonymous class. It cannot be declared static, because it is already local.

    6. Anonymous Classes

    An anonymous class is a class with no name, declared and instantiated in one expression: new Interface() { ... } or new AbstractClass() { ... }. It extends the named class or implements the named interface, overrides what it needs, and produces exactly one object.

    1. It is single-use — there is no way to refer to its type again or create a second instance from the same declaration.
    2. It cannot have a constructor — a constructor is named after the class and the class has no name. Initialisation is done in an instance initializer block.
    3. It is the traditional vehicle for listeners, callbacks and Comparators, where a one-off implementation is all that is wanted.
    // Demo4.java — anonymous class: implement an interface in one expression
public class Demo4 {
    interface Greeter { String greet(String name); }

    public static void main(String[] args) {
        Greeter g = new Greeter() {          // no class name, no constructor
            { System.out.println("instance initializer runs once"); }
            @Override public String greet(String name) { return "Hello, " + name; }
        };
        System.out.println(g.greet("Asha"));
    }
}

    7. The Four Kinds Compared

    Kind Where declared static allowed Needs an outer instance Can capture locals Typical use
    Static nested Class body Yes No No Helper types, builders, Map.Entry-style entries
    Inner (member) Class body No Yes No Iterators and callbacks that need the outer object's state
    Local Method/block No Only if in an instance context Yes (effectively-final) One-off helper used by a single method
    Anonymous Expression No Only if in an instance context Yes (effectively-final) Listeners, Comparators, one-shot implementations

    Reading the table: the single biggest axis is static versus non-static, because it decides whether an outer reference is stored. The second axis is lifetime — a local or anonymous class lives only as long as the code that declares it.

    8. Static Nested vs Inner

    Aspect Static nested class Inner (member) class
    Outer instance reference None Implicit reference stored in every instance
    Access to outer instance members No Yes, directly
    Access to outer static members Yes Yes
    Instantiation syntax new Outer.Nested() outer.new Inner()
    Can declare static members Yes (post-Java 16 also allowed in inner classes) Historically no, except static final constants
    Memory footprint Just the nested object Nested object plus the outer object it keeps alive
    Memory-leak risk Low High if it outlives the outer object's intended lifetime
    Preferred when No outer state is needed The type genuinely belongs to one outer instance

    The practical rule: if the nested class does not need an enclosing instance, make it static. Declaring it inner when it does not need the outer object silently adds a back-reference and a leak surface.

    9. Compilation Artifacts and the Dollar Sign

    Nested classes are a compile-time construct; the JVM knows nothing about them. The compiler emits extra class files whose names use the dollar sign:

    Outer.class          // the outer class
Outer$Inner.class    // a static nested or inner member class
Outer$1.class        // an anonymous class (numbered in order of appearance)
Outer$1Local.class   // a local class (numbered prefix, then its name)

    Two consequences worth remembering:

    1. The dollar sign in a class file name is a compiler convention, not a language feature — never write $ in your own type names.
    2. An anonymous class with an instance initializer compiles a synthetic constructor that takes the captured locals and the outer reference as extra parameters, which is exactly how capture works under the hood.

    Important Because the compiler packages the outer reference into a synthetic constructor parameter, an inner class's .class file literally has no way to exist without that link. This is why you cannot create an inner instance in a static context without an explicit outer object.

    10. Anonymous Classes and Lambda Expressions

    Anonymous classes predate lambdas and can do more, but for a single-abstract-method (functional) interface a lambda is shorter and clearer. Lambdas are covered fully in Lecture 37; the comparison now prevents two common confusions.

    Aspect Anonymous class Lambda expression
    What it can implement Any interface or abstract class Only a functional interface
    State (fields) Can declare its own fields No fields; captures from the enclosing scope
    Methods Can override several methods Implements the single abstract method
    Constructor None; instance initializer instead None
    this inside the body Refers to the anonymous class instance Refers to the enclosing instance
    Verbosity Verbose boilerplate Minimal

    The this row is the sharpest difference: inside an anonymous class, this is the new object, so Outer.this is needed for the enclosing instance; inside a lambda, this already means the enclosing instance.

    // Sorting with an anonymous class, then the same with a lambda (Lecture 37)
import java.util.*;

public class SortDemo {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>(List.of("Ravi", "Asha", "Meera"));

        Collections.sort(names, new Comparator<String>() {   // anonymous class
            @Override public int compare(String a, String b) { return a.compareTo(b); }
        });

        Collections.sort(names, (a, b) -> b.compareTo(a));   // lambda: descending
        System.out.println(names);                           // [Ravi, Meera, Asha]
    }
}

    11. Pitfalls, Shadowing and Memory Leaks

    Pitfall What goes wrong Correct approach
    Inner class outlives its outer object The inner instance holds the outer reference, so the whole outer graph cannot be garbage-collected Declare it static if it does not need outer state; null out or scope the reference
    Capturing a non-final local Compile error: the local is not effectively final Keep the captured local un-reassigned, or copy it to a final local
    Anonymous class capturing a loop variable Pre-Java 8 style bugs where every instance saw the last value Use a per-iteration final local, or a lambda in Java 8+ which captures per iteration
    this confusion Inside an anonymous class, this is the new object, not the outer one Use Outer.this to reach the enclosing instance
    Declaring a constructor in an anonymous class Compile error: the class is nameless Use an instance initializer block
    Serializing a non-static nested class The hidden outer reference may not be serializable, and the outer object is serialized too Make the type static, or mark it and its references carefully
    Static nested class reading an outer instance field Compile error: no enclosing instance exists Pass the outer object in, or convert the field access to a parameter
    Shadowing an outer field A same-named inner field hides the outer one Use Outer.this.field explicitly, or rename to avoid the collision

    Important The memory-leak pattern is worth stating plainly: an inner class instance keeps a strong reference to its outer instance for as long as the inner instance is reachable. Long-lived collections of inner objects therefore pin their outer objects in memory.

    12. Myth vs Reality

    Myth Reality
    "An inner class is a subclass of the outer class" Nesting is lexical containment, not inheritance; the two types have no is-a relationship.
    "Static nested classes can access all outer members" They can access only the outer class's static members directly; instance members need an object.
    "Anonymous classes can have constructors" No — a constructor must share the class name, and the class is nameless; use an instance initializer.
    "A local class can be used anywhere in the class" Its scope is the block that declares it; it is invisible elsewhere, even in the same method's later statements.
    "Lambdas and anonymous classes are identical" A lambda implements only a functional interface and rebinds this to the enclosing instance; an anonymous class can implement any type and owns its own this.

    13. Common Trap Questions

    Trap 1 — Static nested access: "Can a static nested class read a private instance field of its outer class?" No. It can read private static members, but without an outer instance there is nothing to read the instance field from. Pass an instance in explicitly if needed.

    Trap 2 — Instantiation syntax: "Why is it outer.new Inner() and not new Outer.Inner()?" An inner instance needs an enclosing instance. The outer.new form makes that required object explicit; new Outer.Inner() is used only when Inner is static.

    Trap 3 — Capture rule: "I reassign a local after creating a local class that uses it. Why the compile error?" Local and anonymous classes capture only effectively-final locals (Java 8+). Reassignment breaks that, so the compiler refuses.

    Trap 4 — Names: "What class file does new Runnable() { ... } produce?" Outer$1.class (or the next number if several anonymous classes appear). The type has no source name; the compiler assigns a numbered one.

    Trap 5 — Constructors: "Can I add a constructor to initialise state in an anonymous class?" No. Constructors need the class name, and the anonymous class has none. Use an instance initializer block { ... }, which runs once per instance before the constructor body of the superclass completes its work.

    Trap 6 — Leaks: "Why is declaring a callback as an inner class risky in a long-lived cache?" The callback holds a reference to its outer instance, so caching callbacks keeps the outer objects alive indefinitely. Prefer a static nested class when no outer state is needed.

    14. Points to Remember

    1. Java has four kinds of nested class: static nested, inner (non-static member), local and anonymous.
    2. Nesting provides logical grouping, encapsulation of helper types, and scoped naming — it is not inheritance.
    3. A static nested class needs no outer instance and can access only the outer class's static members directly.
    4. An inner class holds an implicit reference to its outer instance, accessed explicitly as Outer.this, and is created with outer.new Inner().
    5. Because of that reference, a live inner instance keeps its outer object alive — the main memory-leak risk.
    6. Prefer the static form whenever the nested type does not need the enclosing instance.
    7. A local class is scoped to its block and can capture effectively-final locals; it may have constructors.
    8. An anonymous class implements or extends exactly one type, is single-use, and cannot declare a constructor — instance initializers replace it.
    9. The compiler emits Outer.class, Outer$Inner.class and Outer$1.class-style files; the $ names are compiler-generated.
    10. Lambdas (Lecture 37) are the concise successor to anonymous classes for functional interfaces, with the key difference that this inside a lambda means the enclosing instance.

    15. Likely Interview Questions

    Question Crisp Answer
    What is a nested class? A class declared inside another class, method or block; used for grouping, encapsulation and helper types.
    How many kinds of nested class does Java define? Four: static nested, inner (non-static member), local and anonymous.
    Difference between static nested and inner class? A static nested class has no outer instance reference; an inner class always stores one and can access the outer instance's members.
    Why is an inner class a memory-leak risk? It holds a strong reference to its outer instance, so the outer object cannot be collected while the inner object is reachable.
    How do you create an inner class instance? Outer.Inner i = outer.new Inner(); — an enclosing instance is mandatory.
    How do you create a static nested class instance? Outer.Nested n = new Outer.Nested(); — no outer object needed.
    What is a local class? A class declared in a method or block, usable only within that scope, able to capture effectively-final locals.
    What is an anonymous class? A nameless class declared and instantiated in one expression; single-use, no constructor, often a listener or Comparator.
    Can an anonymous class have a constructor? No. Use an instance initializer block for one-time setup.
    What does the compiler produce for nested classes? Extra class files such as Outer$Inner.class and numbered Outer$1.class for anonymous classes.
    Anonymous class vs lambda? A lambda implements a functional interface concisely and binds this to the enclosing instance; an anonymous class can implement any type and has its own this.
    Why should a nested class be static by default? With no need for outer state, static avoids the hidden reference, the leak risk and the awkward instantiation syntax.

    16. Final Summary

    static nested:  new Outer.Nested()          no outer reference, outer static only
inner member:   outer.new Inner()            hidden Outer.this, all outer members, leak risk
local class:    declared in a method         block-scoped, captures effectively-final locals
anonymous:      new Type() { ... }           single-use, no constructor, instance initializer

compile ->  Outer.class   Outer$Inner.class   Outer$1.class (anonymous)
    • Forms → static nested, inner, local, anonymous; the static/non-static split is the primary axis.
    • Static nested → no outer instance, accesses outer static members, cheap and serialization-safe.
    • Inner → stores Outer.this, accesses all outer members, outer.new Inner(), memory-leak risk.
    • Local → block-scoped, reusable within its block, captures effectively-final locals, may have constructors.
    • Anonymous → one expression, one object, no constructor (use an initializer), the ancestor of lambdas.
    • Artifacts → $-named class files are compiler conventions; capture becomes synthetic constructor parameters.
    • Rule of thumb → make a nested type static unless it truly needs the enclosing instance.

    Golden rule A nested class is about ownership: use the static form when the type stands alone, the inner form only when it genuinely needs an outer instance, and remember that the hidden outer reference is what causes both the convenient access and the memory leak.

    One-line takeaway: group helper types inside their owner, default nested classes to static, and choose inner, local or anonymous only when you need the outer instance, the block scope or the one-off expression respectively.
